# 安全模型

## 凭据

- 长期保存的密码、私钥口令等只进 **保险库**（`crates/term-vault`）。
  保险库用 Argon2 派生密钥并加密，主密码不落盘。
- 会话库（SQLite）只存引用，不存明文密码；测试会检查库文件里不出现明文。
- 会话表单里的密码有三种策略：
  - **不记住**：只在本次连接的生命周期内使用。
  - **本次记住**：只放在进程内存，退出即忘，不需要主密码。
  - **永久记住**：写入保险库，需要主密码解锁。
- 修改主密码时，保险库内容不变，只重新封装；新口令同样通过强度检查。
- 私钥生成器支持 ed25519 / RSA 3072 / ECDSA P-256，可选口令加密；私钥内容
  不回传到界面。

## 主机密钥

- 按 owner 2026-11-27 裁定，与对齐目标（参考版本）一致：主机 key 在客户端
  内部处理，自动接受新的；连接链路只有一个用户名/密码弹窗，没有 UNKNOWN /
  CHANGED 确认窗，也没有任何中间人风险提示。
- 界面不持久化 accepted host key，也不提供「信任 / 换钥 / 忘记」交互；因此
  参考版本里 CHANGED 状态不可达，本版同样不可达。
- **风险警示**：自动接受主机 key 等于不校验服务端身份，连接可能被中间人冒充，
  界面不会给出任何提示。这是与参考版本（原版）一致的有意取舍，**不是安全推荐**；
  需要严格校验的场景请走 `term_ssh` 的 `Strict` / `Tofu` 策略或脚本路径。
- `term_ssh` 库仍保留 `HostKeyPolicy::{Strict,Tofu,Insecure}` 三档与
  `known_hosts_admin` 的 trust / forget / list API，供脚本与自动化规则使用。

## 数据落盘

| 内容 | 位置 | 说明 |
|---|---|---|
| 会话库 | `profile_dir/sessions.db` | SQLite；不含明文密码 |
| 保险库 | `profile_dir/vault.ztv` | Argon2 加密；扩展名是自造的，与普通数据文件区分 |
| 偏好 / 布局 / 快捷栏 | `profile_dir/` 下的配置文件 | 人可读，便于备份与进版本控制 |
| 命令历史 | `profile_dir/command_history.json` | 明文；不含经 `secret` 取的凭据 |
| 会话日志 | 用户指定或默认目录 | 默认关闭；写入前做转义清洗 |

`profile_dir` 由 `term-paths` 决定，可用 `WINDTERM_PROFILE_DIR` 覆盖。目录布局、
原子写规则、启动期搬迁与各文件的完整职责见
[持久化与文件布局](design/15-persistence-and-file-layout.md)。

所有整文件写入都走"同目录临时文件 + 改名"：临时名唯一（进程标识 + 时间戳 +
序号），多进程共享同一份配置目录时不会互相覆盖。配置文件读失败不会被默认值
静默覆盖。

## 网络面

- 程序只主动连接用户配置的主机（SSH / Telnet / SFTP / 隧道目标）。本地控制
  端点不是 TCP 服务，而是 Unix domain socket `~/.zterm/control.sock`
  （Windows 用命名管道），权限 0600 并校验 peercred，只接受同用户连接。
- 没有遥测上报，也没有自动更新外联；网络活动面板把程序自身的连接列出来，
  便于核对。
- CLI / MCP 客户端连不上控制端点时明确报错退出，绝不自己起一个会话池；
  锁屏时拒绝接入与调用。没有 token 文件与 `auth` 握手（ADR-0030）。

## 报告问题

发现安全问题时，请通过仓库的 **Security → Report a vulnerability** 私密通道
提交，不要在公开 issue 里贴可利用细节。
