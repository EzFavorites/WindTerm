# ADR-0027 · 脚本平台目标架构

- 状态：已采纳（取代同主题的早期草案；能力面口径、端口划分、授权信封与打开入口以本文为准）

## 背景

脚本与远程 API 是同一套会话能力面的两个前端：能力面是一张纯数据表，写着动词名、一句话说明、参数与结果的 schema、以及该动词对哪个前端可见；脚本注册与远程自描述都从这张表派生（见 ADR-0023）。

但脚本侧原先只有一个宿主抽象、少数几个方法，能力是会话操作的一个子集：

- 只能执行一次性命令，不能按会话库里的引用打开会话；脚本写一个会话名，会被当成命令执行。
- 没有本地文件、外部进程、剪贴板、向人提问、取选区、读写应用状态。
- 结果面很窄：脚本拿不到配置，也拿不到「界面此刻选中了什么」。

这带来一个说不通的状态：**用户能在界面里做的事，脚本做不了**；同一个意图在两侧走不同的路，差异只在运行到某一步之后才显形。

三个宿主的可用能力本来就不一样——界面、命令行加终端、无头进程。形状必须允许每个面独立降级，并且**降级只能是显式失败**，不能是「返回默认值假装成功」。

分层因此固定为：词汇层（能力面）→ 语义层（引擎、游标、沙箱、门面）→ 端口层（trait 声明）→ 实现层（界面宿主、命令行宿主）→ 横切（授权信封、反应器、取消令牌）。依赖方向不变，变的是端口的数量与形状。

## 决策

### 1. 一张能力面，两个前端，一种语义

- 动词是全局函数，动宾命名，协议无关；线上形状里不出现协议名或对象路径。
- `Exposure` 三档：两个前端都可见、只有远程可见、只有脚本可见。分档依据是「另一侧是否有更省往返的等价表达」，不是对称美学。
- 漂移防线是集合相等断言：脚本侧问引擎自己注册了哪些函数，与能力面中脚本可见的动词对账；只加注册不入表、或只入表不注册，都会让断言变红。

### 2. 七个端口，按接触面切

| 端口 | 职责 |
|---|---|
| 会话 | 列举、按名解析、真名回报、打开、关闭、借出句柄、激活、克隆、序号、当前激活、主机与地址、配置目录、按会话取远端文件访问器 |
| 人机 | 通知、提问（消息 / 确认 / 文本 / 密文 / 选择 / 告警）、选文件 |
| 本地文件 | 读、写、追加、列目录、取属性、建目录、删除，受授权信封约束 |
| 外部进程 | 起子进程，取回标准输出、标准错误、退出码，受授权信封约束 |
| 剪贴板 | 读系统剪贴板（写不需要授权） |
| 窗口 | 取选区、窗口显隐、退出应用 |
| 应用控制 | 应用状态快照、面板可见性、布局动作 |

- **默认实现即降级**：除会话面的核心方法外，端口方法都带默认实现。凡是「没有这个能力就必须让调用方知道」的操作，默认返回显式失败（`Unsupported` / `Denied`）；只有通知这类「本来就可以不送达」的操作允许默认空实现。退化宿主实现会话面的核心方法即可编译运行，其余面自动降级；这比「要求所有宿主实现全部方法」更诚实，也比「静默返回空值」更安全。
- **不做巨型 trait**：一个 trait 装三十多个方法会让「谁必须实现什么」消失，也会逼无界面宿主去实现 `window()`。
- 命名有两条刻意分工：会话端口叫复数（一组会话的登记与启停），单数留给「一条会话」的读写；借句柄叫 `attach`，避免与「会话对象」只差一个字母。`host` 在本仓已指远程主机，不拿来命名端口。
- 远端文件不做独立端口，而是会话端口上的一个访问器：原语绑定「脚本当前会话」，多会话脚本用会话切换即可。独立的句柄对象只多一层生命周期，不增加能力。

### 3. 一个打开入口

`OpenRequest` 只有四个变体：会话库引用、完整配置、一次性命令、本地 shell。唯一映射点在实现层，脚本、远程、命令行不再各写一份。

- 完整配置**只在进程内传递**：远程不接受内联配置，否则凭据会进请求体。
- 「连接」= 按已存配置引用打开新实例，与「打开」共用同一条路径；两者都新建运行实例，不复用运行中的那一条。

### 4. 每次运行一份授权信封

| 能力 | 形态 |
|---|---|
| 文件 | 拒绝，或根目录白名单 + 是否可写 |
| 外部进程 | 允许 / 不允许 |
| 剪贴板读 | 允许 / 不允许 |
| 窗口控制 | 允许 / 不允许 |
| 应用状态 | 拒绝 / 调整 / 配置 |

- **默认全拒**。三个来源：脚本头声明、运行入口参数、用户手选文件——「用户亲手选的那个路径」当场追加进本次运行的文件授权。
- 三条规矩：
  1. **只绑定单次运行**，不写进任何全局配置；否则一次允许等于永久放行。
  2. **路径先规范化再比对**：`..`、符号链接、大小写都走同一条判定；指向白名单外的软链一律拒绝。
  3. **拒绝要说清楚**：带上「要的是什么、给了什么」，脚本才能改走另一条分支，而不是撞一句「权限不足」。

### 5. 反应器：一条通道服务所有「问界面」

提问、选文件、读剪贴板、取选区、读应用快照与改面板，都是同一个形状：**脚本线程阻塞、界面帧循环回答**。

- 请求带回应通道；界面每帧取一个，回「成功 / 已取消 / 不支持」。界面永不阻塞；脚本按 50 毫秒切片等待，与取消令牌同一个节拍。
- 界面侧的写操作只经 `reduce`：端口实现只做「翻译 + 回执」，不直写视图状态。直写会造出第二条写入路径，而「字段有唯一写者」是这一层守住分层的具体方式。
- 剪贴板读取走界面既有的粘贴请求通道，不引入新依赖；不能用「上次自己写出去的那份」冒充系统剪贴板——跨应用复制之后它是旧值。
- 选区不快照、不共享句柄：取的是当前这一帧的事实窗口，过期即失效。

### 6. 稳定性的四条边界

| 边界 | 做法 |
|---|---|
| 取消贯通到每个阻塞点 | 等待是消费型注册，不能靠外部反复调用；因此加默认可取消方法，由 IO 层覆写成切片循环，并且**不撤销、不重登记**，避免丢掉已匹配的内容。睡眠、提问、文件框、剪贴板、选区、远端文件等待全部接同一个令牌 |
| 预算两档，运行期固定 | 交互与批处理各一档，墙钟与操作数上限成对；达到上限是显式失败，不返回半份结果。墙钟同时钳制单次阻塞等待，否则「脚本超时」在一条长等待面前不成立 |
| 同会话互斥，拒绝不排队 | 排队会造出「我点了运行，几分钟后它自己动了」。不同会话不互斥，批量本来就是并行的 |
| 错误分类，不许假装 | 取消与超时分开；授权不足、宿主不支持、会话不存在、IO 失败各自成类。无界面时的确认**绝不返回否定**，文本输入绝不返回默认值 |

错误分类的口径是「调用方要怎么处理」，不是「错误发生在哪一层」。文案直接面向脚本作者，带名字的变体必须点名是哪一个键、哪一条会话。

### 7. 兼容门面只提供形状

对外提供一套对象形状的兼容门面，把外部脚本习惯里的对象路径映射到本仓动词。

- **不缓存、不推断、不补参数**；映射表有测试逐条钉住「这个名字转发到哪个动词」。
- 五条映射纪律，每条都因为「直译会错」：消费式与观察式不能互换；坐标基底不同（门面转换，不在内核里改）；返回值形态不同（门面压回原形状）；目录与模板分开传；取到标签对象时钉住会话，不让后续调用落到「此刻全局绑着的那条」。
- **不做语言层面的兼容**：只支持内嵌脚本语言。门面给形状，不给解释器。

### 8. 应用控制的边界

- 只承诺读快照、改面板可见性与布局动作。**偏好写入不在这个端口**：写设置要求逐键标注「即时生效 / 重启生效」，没有这张表之前，半套实现会让「改了个文件」看起来像成功。
- 应用控制与窗口控制**不合并**：看一眼界面，和改用户配置，风险面不同；合成一档等于把两者同级。
- 应用控制只对脚本可见：当前远程宿主是无窗口子命令，标成两端可见等于在自描述里宣布一组永远「不支持」的方法。出现「界面进程内托管远程」的决策时再整体重估。

## 后果

正面：

- 一个意图只有一条路径：脚本、远程、命令行从同一个打开入口、同一张动词表、同一套错误语义出发。
- 降级是显式的：无头宿主缺什么就报「不支持」，不会返回空值让调用方以为成功。
- 危险动词（写文件、起进程、改应用状态）全部落在授权信封里，可按次审计；默认全拒让「没声明」等于「没权限」。
- 取消、预算、互斥、错误分类四条边界让「停止」是真的能停，超时是真的会失败。
- 反应器把四类阻塞交互收成一套机制，界面不会因为脚本提问而卡帧。

代价：

- 端口从一个大 trait 变成七个，测试替身与装配点变多；`HostEnv` 是必要的收敛，否则构造会退化成十余个 `with_*`。
- 默认实现让「忘了接线」不会编译失败，只会在运行期报不支持；因此每条端口都要有覆盖「支持」与「拒绝」两侧的测试。
- 能力面对两个前端共用，新增一个动词要同时考虑两个前端的语义与可见性；分档判断错了，会在另一侧留下一个永远不可用的名字。
- 兼容门面是长期维护成本：外部形状不变、本仓动词会演进，映射表与测试必须同步，否则「形状一致」会先于「语义正确」腐化。
- 远端文件绑定当前会话，多会话脚本需要在会话之间切换；换来的是没有句柄生命周期与泄漏面。
- 应用控制暂不覆盖偏好写入，用户会看到「脚本能开面板、不能改设置」的能力缺口；这是有意保留，不是遗漏。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 保留一个大而全的宿主 trait | 每个宿主都被迫实现自己用不到的方法；「谁必须实现什么」消失，退化宿主只能写一堆「假装成功」的空实现。 |
| 脚本继续用「只执行命令」的受限打开入口 | 与界面走两条路：按会话名打开会被当命令执行，错误到运行期才显形；能力面共用也就名存实亡。 |
| 引入全局权限配置 | 一次允许等于永久放行；用户无法为「这一个脚本、这一次」授权，也无法在事后确认授过什么。 |
| 在脚本线程引入异步运行时 | 取消、超时与「谁在等谁」会立刻变成需要重新论证的问题；协作式取消加切片等待已经能覆盖全部阻塞点，依赖也更少。 |
| 同会话的第二次运行排队等待 | 用户看到的是「点了运行，几分钟后它自己动了」；拒绝并说明谁在跑，比排队可预期。 |
| 由能力表自动生成脚本注册 | 参数类型适配本来就要手写（整数与浮点双重载、过滤器句柄、返回 Map 的拼装）；生成会把「漏一个重载」推迟到运行期。保留手写、用集合相等断言兜底。 |
| 远程接受内联会话配置 | 凭据会进请求体；配置只在进程内传递，远程按会话库引用打开。 |
| 把窗口控制与应用状态合成一个授权档 | 「看一眼界面」和「改用户配置」风险不同级；合成一档会让最小授权失去意义。 |
| 现在就把应用控制标成两个前端可见 | 唯一的远程宿主没有窗口，那些方法在远程侧永远只能报不支持；自描述里列出一组不可用方法，比不列更误导。 |
| 用独立句柄承载远端文件 | 句柄只增加生命周期与泄漏面；原语绑定当前会话、多会话靠切换，已经覆盖同一批操作。 |
