# ADR-0001 · 实现语言选用 Rust

- 状态：已采纳

## 背景

需要一门语言同时满足四件事：跨平台单二进制分发、无 GC 停顿（终端渲染对延迟敏感）、成熟的多协议 IO 生态（SSH、SFTP、串口、TCP）、能承载加密与凭据管理，并且可以被第三方安全地扩展。

候选为 C++、Go、Rust、Zig、TypeScript（Electron 全栈）。

## 决策

主体实现使用 Rust（edition 2021），异步运行时使用 tokio。

### 理由

- **依赖已经存在**：`russh`、`portable-pty`、`serialport`、`wasmtime` 都是可以直接使用的组件，不必为协议层或插件沙箱自己写胶水。
- **无 GC**：终端在大吞吐输出下，GC 停顿会直接表现为画面卡顿。所有权模型把内存管理变成静态可预测的，而不是运行时偶发的一次停顿。
- **插件宿主同栈**：`wasmtime` 是 Rust 原生项目，插件宿主与主程序共用一套类型和工具链（见 ADR-0006）。
- **单二进制、体积小**：与「轻量原生终端」的定位一致，不需要附带运行时。
- **C++ 路线的代价明确**：终端类 C++ 实现通常要拼 GUI 框架、libssh 与自研的文本组件，构建链随依赖增长而复杂化，编译与调试循环也明显更慢。

## 后果

正面：

- 内存安全边界清晰，凭据与协议代码的漏洞面小于 C++。
- 依赖治理统一，许可证与漏洞检查可以在 CI 里做成门禁。
- GUI 层同为 Rust（ADR-0007），不需要跨语言 FFI。

负面：

- 开发速度低于 TypeScript 或 Go：借用检查与异步生命周期需要经验。
- 编译时间较长，Rust 侧改动只能靠重启验证，热重载无从谈起。
- 协作门槛高于 JS 生态；对单人主导的项目，这一项影响有限。

接受的取舍：用开发速度换长周期的稳定性与安全性。对一个要长期维护、且要处理 SSH 私钥的软件，这个交换成立。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| C++ | 构建链复杂、内存安全负担重、生态碎片化（GUI、SSH、文本组件各自为政） |
| Go | GC 停顿对终端渲染不友好；SSH 生态缺少 agent 转发、连接复用这类能力 |
| Zig | 生态过早期，SSH、SFTP、WASM 都要自己接 C 库 |
| TypeScript 全栈 | 需要 Electron 或 Node 侧原生插件，同时落入「体积重」与「构建链复杂」两个问题 |
