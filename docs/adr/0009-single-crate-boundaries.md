# ADR-0009 · 单 crate 内钉死三层结构与四条所有权边界

- 状态：已被取代（被 ADR-0014 取代）

后续演进：ADR-0014 按副作用与发布需要把代码拆成 workspace 多 crate，本文「不拆 workspace」一条随之失效；分层与所有权边界本身继续有效。

## 背景

早期架构蓝图规划了多个 core crate、异步运行时、插件、会话数据库与加密保险库。实际代码是单 crate、无线程池、无异步运行时，UI 结构体直接持有 PTY 主设备、子进程和 VT 网格。

这个形态在功能少时没问题，功能一多就变成负担：每加一个功能，都要在 UI 层扇出五处——状态字段、绘制分支、菜单表、字符串派发、标签页连接句柄。边际成本线性上升，而且改动散落在一个不断变长的文件里。

## 决策

在单个 crate 内一次性把四条所有权边界钉死：不拆 workspace、不引入异步运行时、不更换 VT 内核。改的是「谁拥有什么」，不是「软件做什么」。

落地后的结构：

```
app/src/
├── core/   网格、主题、VT、通道、监管者   （零 UI 框架依赖）
├── app/    状态、动作、归约              （零 UI 框架依赖）
└── ui/     外壳与终端视图                （只读快照）
```

四条边界由门禁脚本逐条 grep 检查：

| 边界 | 判据 |
|---|---|
| 核心不依赖 UI | `core/` 内 `egui` / `eframe` 零命中 |
| UI 不持有 OS 资源 | `ui/` 内 PTY 主设备、通道接收端、子进程类型零命中 |
| UI 只读快照 | UI 只接受网格快照引用，一切写入经动作 |
| 动作强类型 | 无字符串派发残留，归约函数是纯函数 |

线程模型保持标准库通道加每会话一个监管线程：字节摄入与 VT 解析不在 `draw()` 里发生，空闲时不请求重绘。

### 主动推迟的部分

| 推迟项 | 理由 | 何时升级 |
|---|---|---|
| 拆 workspace 多 crate | 边界还没在单体里验证过，拆早了只是把耦合搬进 `Cargo.toml` | 出现第二个可执行目标，或 `core` 需要独立发布 |
| 引入 tokio | 当前规模下通道加每会话线程足够，异步反而增加调试面 | 并发会话数明显上升，或需要异步 SFTP 流 |
| 迁移 `alacritty_terminal` | 手写解析已有单测与金样本可依赖；没有金样本就同时改解析和渲染，回归无法定位 | 金样本回归全绿之后，独立排期 |
| `russh` 与原生 SSH | 要与 SFTP 共享连接，应当一起做 | 作为新的通道实现接入，UI 侧零改动 |
| 会话数据库与加密保险库 | 会话 JSON 已够用 | 需要跨设备同步或合规审计 |
| WASM 插件与 tmux 控制模式 | 依赖稳定的 ABI 与稳定的连接层 | 核心边界稳定且动作枚举冻结后 |

## 后果

正面：

- 新增功能从「扇出五处、全在一个大文件里」变成「新增实现加注册动作」，扇出收敛到一两处，且落在独立文件里。
- VT 语义由单测与金样本锁住，重构时可以判断是否引入回归。
- 四条边界可以逐块落地，每块都能单独回退，不必一次改到底。

负面：

- 边界靠门禁脚本与代码审查维持，不是编译器强制。只有拆成独立 crate、把依赖方向写进 `Cargo.toml`，才会变成编译错误。
- 通道目前用非阻塞读取而非阻塞读，两种实现共享同一套会话对象；将来接 SSH 时需要再抽一层。
- 长时帧时间与空闲 CPU 的基准未在真实设备上实测，是否要升级到逐行字形缓存，需要先有实测数据再决定。
- 推迟项以触发条件为界，不是无限期搁置；触发条件出现而不处理，等于默认放弃这条决策。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 直接按蓝图拆多 crate | 边界未经单体验证，拆出来的多半是错误边界，`Cargo.toml` 会变成耦合的新藏身处 |
| 一次性引入异步运行时 | 当前并发规模不需要；异步会改变每个通道实现的形态，与「先钉定边界」的目标冲突 |
| 保持现状、只做局部修补 | 边际成本已经可见，局部修补无法阻止下一处扇出 |
