# ADR-0026 · 每窗格一组标签，分屏复制配置开新会话

- 状态：已采纳（细化 ADR-0025 的窗格层；取代「一个窗格只挂一条会话」以及「同一会话进入两个窗格、共享滚动」的早期假设）

## 背景

二分切分布局完成后，窗口模型仍是「一个全局标签条 + 一棵树决定谁在哪个窗格」：

- 布局叶子只挂**一个**会话，因此每个窗格只能显示一条标签。
- 窗口持有一份扁平的会话身份列表与一个全局唯一焦点。
- 标签条只有全窗一条，无法表达「这一格当前显示哪一条」。

目标结构是：**每个窗格是独立的一组，组里可以有多条标签；点组内标签只换该窗格显示的会话；分屏 = 新建一个窗格组，组里装一条新会话。**

这里有两件容易混淆的事，必须在模型里分开：

- **组内切换**：改「这一格显示哪条会话」，布局树不动。
- **分屏**：新建窗格，并新起一条会话；不是把已有会话搬到另一个窗格。

## 决策

### 1. 数据模型

| 结构 | 职责 |
|---|---|
| `PaneId(u64)` | 窗格（组）的恒在身份；运行期原子计数器铸造，单调递增、不回收、不落盘 |
| `Layout::Leaf(PaneId)` | 几何树的叶子标识一个窗格，不再直接标识会话 |
| `PaneGroup { order, active }` | 该窗格拥有的会话序列与组内活动会话 |
| `pane_groups: HashMap<PaneId, PaneGroup>` | 空间分区的唯一真源 |

- `PaneId` 是独立 newtype，与 `SessionId` 刻意不混用。把窗格身份当会话身份传进绘制入口，必须在编译期被挡下；两者都退化成裸 `u64` 时，这类错只能靠人眼。
- 窗口仍持有 `tabs: Vec<Tab>`（会话真身、PTY、快照、视图态）与 `active: Option<SessionId>`（窗口焦点）。
- `open_order` 保持「由 `tabs` 派生的只读顺序」，不引入第二套由分组派生的算法。

### 2. 三份真源的分工

- **`tabs`**：会话的生命周期真源。新建会话即入列；彻底结束才移除并关闭。
- **`pane_groups`**：空间分区真源。只引用会话身份，不持有标签对象。
- **`open_order`**：派生视图，恒等于 `tabs` 的身份序列，也恒等于各分组 `order` 的并集。

### 3. 不变式

1. **会话只在一处**：一个 `SessionId` 在全部 `order` 的并集里至多出现一次——同组内不重复，跨组也不重复。
2. **并集一致**：`pane_groups` 引用的会话集合必须等于 `tabs` 的集合；不允许分组引用已不存在的会话，也不允许会话不在任何分组里（收起窗格后的瞬时态除外，且必须能手切回）。
3. **活动窗格不单独存字段**：由 `active` 反查所属窗格。因为每条会话只在一处，反查结果唯一，不需要一个会与 `active` 不一致的缓存。
4. **单窗格收敛**：树只有一片叶子时，该窗格的分组压成「只有当前会话」。否则从单窗格分屏时会锚到错误的会话——分屏锚点是「当前会话所在的窗格」。
5. **叶子身份唯一**：剪叶只剪一片；重复身份会让后续分屏与关闭只认第一个匹配。

### 4. 独立滚动是默认事实

因为会话只在一处，同一会话不可能同时出现在两个窗格，所以「每个窗格各自滚动」不需要共享视口机制，也不存在「同一会话两份选区谁权威」的问题。每个会话一份投影、一份视口，滚动互不影响。

### 5. 动作语义

| 动作 | 语义 |
|---|---|
| 组内新增标签 | 新起一条会话，追加进当前分组的 `order` 并设为该组活动；布局树一个字节不动 |
| 分屏 | 新建 `PaneId` 与只含一条**新会话**的分组，落在对应方向；原窗格与源分组不变 |
| 关闭当前标签 | 从所属分组移除；组仍非空则换显示到被关那条的左邻居（左边没有取第一条） |
| 关闭后组为空 | 剪掉该窗格叶子，兄弟顶上来；复用既有剪叶语义 |
| 关闭最后一格 | 不剪叶；唯一窗格的分组改指窗口里第一条活会话，窗口始终留一块终端 |
| 真正结束会话 | 仅当某会话已不被任何分组引用，才从 `tabs` 移除并关闭；仍可被「重新打开已关闭」拉回 |
| 拖动标签 | 拖一条标签落到另一格 = **两片窗格交换位置**，整组随窗格走；树形与身份集合都不变 |
| 移动窗格 | 把当前窗格连同整组会话并进相邻窗格，自己收起 |
| 调整比例 | 分隔条只改千分比，两侧都不允许被拖到消失 |

- **分屏一律新建会话**：一种入口起本地 shell，另一种复制当前会话的**配置**再开一条（新身份、新 PTY、新快照、空回滚）。没有「同一条会话进两个窗格」的分支。
- **窗格本身不是拖动对象**：没有「抓住窗格拖动排序」的手势；位置由树决定，比例由分隔条决定。拖标签的目标是「把哪条会话换到哪一格」，交换的结果是两片窗格互换位置，而不是把会话塞进对方的组。
- 「重新打开已关闭」是独立视图：它新建一个窗格、清掉旧分组，只留这一片窗格；关闭历史按会话名排队，不保存原窗格归属。

### 6. 每窗格一套界面，单窗格保持原路径

- 只有一片叶子时，全窗的标签条、工具行、系统监视条照旧由窗口壳声明，终端绘制走原来的单终端路径。
- 真的分屏后，每片叶子自上而下自己画：标签条、地址栏、终端内容、系统监视条；全窗那三条不再画，否则会出现「全窗一条 + 每格一条」的重复。
- 窗口级单例的绘制必须先参数化：控件标识带窗格区分量，浮动位置与拖拽状态不读窗口级那份。否则分屏下不是标识冲突，就是三格互相抢位置。
- `≡` 只列当前窗格所属分组的会话，不是全窗清单。

### 7. 组名由身份派生

组名是组的一等标识，用于在界面与菜单里指认「哪一组」。实现上不存 `name` 字段，而是由 `PaneId` 纯函数派生：`1 → A`、`26 → Z`、`27 → AA`（进位式列名）。

- 名字跟着身份走，不随屏幕位置重排：`A` 挪到右上也还是 `A`。
- 名字不回收：关掉 `C` 再分屏，新组拿 `D`。
- 名字不落盘：重启后窗格身份按树形重建顺序重新铸造，名字随之重建，可能与上次不同。

### 8. 焦点只由活动标签表达

焦点只体现在「当前窗格标签条上的活动标签」那一条指示线上；窗格本身没有边框高亮、标题底色或角标。光标在哪个窗格，哪个窗格标签条的指示线就是焦点。不引入窗格级焦点装饰。

### 9. 持久化边界

布局文件仍只记「每片叶子一条会话下标」，格式版本不变：

- 窗格身份不落盘，恢复时按树形重建；第一片叶子复用构造期的窗格，组名因此从 `A` 起。
- 组内多标签与组内活动态**不跨重启恢复**：重启后每格只摆回一条会话。
- 要恢复分组，必须把落盘形状改成「一片叶子存会话下标列表 + 组内活动下标」，并按旧版本显式迁移。这是兼容性事件，等真正需要跨重启恢复多标签时再做，不在本决策里顺手改掉。

## 后果

正面：

- 窗口结构补齐「分组」这一层，能表达「每格一条标签条、组内切换、分屏建组」。
- 模型比「同一会话多窗格 + 共享滚动」的版本更简单：会话只在一处，拖拽残留、共享视口互踩、选区归属等边界问题自然消失。
- 复用既有剪叶、比例、即时落盘与交换逻辑，改动是「加一层分组」而不是推倒重来。
- 不碰控制面，也不把视口下沉；分层与 ADR-0025 的视图态键控结论不变。

代价：

- 所有叶子操作从「按会话身份」改为「按窗格身份 + 分组查表」，是改动的主要面积。
- 每窗格界面要求把原本窗口级的单例逐项参数化；漏一处就是标识冲突或共享状态互抢。
- 单窗格与分屏是两条绘制路径，必须各自保持正确；单窗格路径不许因为分组层而变形。
- 分组结构暂不落盘，用户重启后看到的是「每格一条」，需要重新在组内开标签。
- 组名重启后可能变化：它由运行期身份派生，不是持久名字。要固定名字，得把名字一起写盘，或让窗格身份可持久化。
- `PaneId` 与 `SessionId` 的类型隔离是编译期防线；一旦有人把两者塞进同一个裸整数通道，防线失效且没有运行期兜底。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 同一会话进入两个窗格、共享滚动 | 需要把视口下沉到窗格，或为每个（窗格, 会话）维护一份视口；随后选区、查找、折叠都要回答「哪份才是权威」。而两个窗格显示同一条会话，本身也不是「每格是独立终端」的直觉。 |
| 保留全窗一条标签条，用组名前缀区分 | 一条横条无法表达「这一格显示哪一条」；分屏后用户必须靠位置猜归属。每格自己的标签条是分组模型最直接的呈现。 |
| 把活动窗格存成独立字段 | 它会与 `active` 形成两个可分别写入的状态，任何一处漏同步就是「焦点在 A 格、活动会话在 B 格」。反查唯一，不存第二份。 |
| 拖动整个窗格重排 | 位置由树决定、比例由分隔条决定，两件事分开；再加一套拖拽重排等于给同一件事两个写者。 |
| 分屏时复用源会话（移动引用） | 会让两个窗格共享一条 PTY，滚动与输入互相干扰；「分屏看两台机器 / 两个目录」才是这个动作的常见用途，复用会话不满足它。 |
| 新增「空白新会话」与「复制配置」两个分屏命令 | 两类动作已经由「分屏」与「拖标签」区分；再按配置来源分叉，会把同一件事拆成两条需要各自维护的路径。 |
| 现在就升级落盘格式以保存分组 | 落盘形状变更是兼容性事件，需要旧版本显式迁移与读回测试；在没有「跨重启恢复组内多标签」的真实需求前，先保持「每格一条」，把代价写在明处。 |
| 给分组存一个 `name` 字段 | 名字是身份的派生值，存一份就有两个写者；重命名还会引出「名字与身份谁优先」。派生纯函数没有这个问题。 |
