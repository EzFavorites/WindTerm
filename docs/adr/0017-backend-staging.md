# ADR-0017 · 后端按「同步先行、异步关进连接层」分期落地

- 状态：已采纳

## 背景

此前后端整体处于延后状态：SSH 拉起系统 `ssh`，会话存明文 JSON，没有凭据保险库、没有 SFTP、没有端口转发。延后的理由是「这些是上层建筑，要等连接层 ABI 稳定」。

这条理由不再成立。后端这几块能力可以按「是否需要异步运行时」分成两类，而两类都不必等某个 ABI：

| 类别 | 内容 | 运行时 |
|---|---|---|
| 同步 | 凭据保险库、会话库、会话导入 | 不需要 |
| 异步 | SSH 客户端、端口转发、SFTP | 需要一个异步运行时 |

同步那几件是纯本地数据问题，与 GUI、与网络都无关；异步那件只有一个来源——连接层要同时读写多个方向，且要保持长连接。所以本 ADR 真正要拍板的不是「写不写」，而是「愿不愿意为一个异步运行时不破坏现有分层」。

现有分层已经把这件事的成本压得很低：`term-core` 是纯语义，`term-app` 只有动作与效果值，`term-runtime` 每会话一条线程加一槽邮箱，会话线程与上层之间只走 `mpsc`。异步只要落在会话线程内部，上层一行都不用改。

## 决策

### 1) 分期落地，每片独立可上线、可回退

| 片 | 内容 | 新依赖 | 运行时 |
|---|---|---|---|
| 一 | 凭据保险库：Argon2id 派生 + XChaCha20-Poly1305 | argon2 / chacha20poly1305 / rand / zeroize / base64 | 无 |
| 二 | 会话库：SQLite 替换明文 JSON | rusqlite（bundled） | 无 |
| 三 | 会话导入（第三方终端产品的会话导出格式） | encoding_rs | 无 |
| 四 | SSH 客户端：认证、`known_hosts`、TOFU、PTY 通道 | tokio + russh | 局部 |
| 五 | 端口转发：本地 / 远程 / SOCKS5 | 复用第四片 | 局部 |
| 六 | SFTP：先只做列目录与浏览，传输留到有调用方时 | russh-sftp | 局部 |

顺序理由：前三片是同步的，任何一片都能独立上线并单独回退，不牵动线程模型；第四片引入异步，必须最后做，且做完才有第五片的意义——转发骑在已认证的连接上。第三片排在第二片之后，因为它需要会话模型先定下来。

### 2) tokio 的笼子（本 ADR 的核心约束）

引入 tokio 不是「全仓库异步」，而是给它划一个笼子：

```
apps/* ─┬→ term-app → term-core              全同步，依赖表里永远不许有 tokio
        └→ term-runtime                      同步 + 每会话一条线程
                 ↑
       term-ssh / term-tunnel / term-sftp    唯一允许 tokio 的地方
                 └→ term-core                纯语义，仍同步
```

- tokio 只允许出现在连接层三个 crate 的依赖表里；`term-core` / `term-app` / `term-runtime` / `apps/*` 一旦出现 tokio，依赖表检查即失败。
- 判定不止一条：还要查笼子外的 `russh`、`term-app` 与 `apps/*` 源码里的 `.await`、以及连接层是否真的提供了 `TermChannel` 的实现——「能力接上了」和「依赖没越界」是两件事，必须同时成立。
- 连接层里有三处而不是一处，不是破例：SFTP 与端口转发同形——都只认得「已认证、未开会话」的连接，都在自己那条线程里跑 `new_current_thread` 运行时，对外都给同步句柄。真正要守的始终是「应用层与可执行目标源码里零 `.await`」和「核心语义层不认识网络」。
- 线程模型不变：仍然是每会话一条监管者线程加一槽邮箱，tokio 只活在会话线程内部的连接任务里，不引多线程调度器。桌面端不变成 async，帧循环里不许 `.await`。
- 会话线程与 tokio 之间只走既有的 `mpsc`：`TermChannel` 新增一个 SSH 实现，监管者一行不改。当初把监管者拆成独立编译单元，就是为了这一步。

### 3) 保险库与会话库的职责切分

两个文件，各管一件事：

- `sessions.db` 存会话树与分组，会话行里只有一个 `vault_entry_id` 做引用，**不含密码**。会话配置从来不含凭据，密码只在连接时现填或从保险库取。
- `vault.ztv` 存凭据：magic + 版本 + header（JSON）+ 密文，header 作为 AAD 参与认证——否则攻击者可以把 KDF 参数改小再离线爆破。默认 KDF 参数 64 MiB / t=3 / p=4。
- 解锁一次，本次运行可用：保险库实例挂在窗口对象上，纯内存，不进视图状态。锁定等于丢弃内存中的主密钥，之后连接只会退回「手填密码」。

为什么会话库值得一个 SQLite：不是为了查询性能，而是明文 JSON 给不了的三件事——整文件重写在写一半时全丢（SQLite 有事务）、密码字段无处安放引用（多一列即可）、按字段筛会话树必须先全读进内存。

### 4) 明文 JSON 直接退场，不做迁移

拍板是不搬：旧的明文会话文件不读、不搬、不改名，会话只存在 `sessions.db`。

- 代价明确：升级后会话树回到出厂默认值（一条本地 shell）。密码从来没进过那份 JSON，所以不丢凭据；主机信息重填一次即可。
- 换来的是：不引入「半途中断怎么办」的原语（先写库后改名、原样保留、存档副本、字段白名单），存储层只剩「读库 / 写库」两条路，没有任何一条代码路径同时认识两种格式。
- 迁移代码是长期负债：它一旦存在，就必须为「库与旧文件同时出现」的所有排列写测试，而这样的状态在产品里不会再有第二次。
- 判据随之从「迁移做对了」变成「迁移不存在」：库能往返、引用能跨列表存活、库文件与 `-wal` 的原始字节里明文密码零命中，且持久化模块里没有任何一次 JSON 序列化。

一条边界：`persist::load` 先看库文件在不在，不在就返回「没有库」，不顺手建一个空库。`Store::open` 会建库，所以这道判断必须在它之前——只读路径不该产生副作用，否则第一次「看列表」就会在同一台机器上留下一份默认库。

### 5) 两条 SSH 路径并存，而且是故意的

会话配置里的 `builtin_ssh` 决定一条会话走进程内客户端还是系统 `ssh`。新建会话默认走进程内客户端，想换回系统 `ssh` 在属性页取消勾选。

保留系统 `ssh` 是逃生门：真遇到老服务器算法协商不了，用户还有一条路能用。这不是过渡期的遗留，是有意的冗余。

## 后果

1. 构建时间上升：`rusqlite` bundled 要编 C，`russh` + `ring` 也是 C/汇编。目标目录可接受，但持续集成的缓存要跟上。
2. 异步代码进了仓库，就得有人守「异步只在一处」。这靠依赖表检查，不靠自觉。
3. 攻击面变大：多了一个加密库、一个 SQLite、一个 SSH 实现。缓解是依赖审计进持续集成，且保险库格式公开可审计——用户真丢密码时能用脚本抢救数据。
4. 升级即空树：这是「不做迁移」的账单，写进 ADR 而不是写进已知问题，因为它是取舍不是缺陷。
5. 复查触发：连接层的 tokio 用量超出「会话线程内一个 current_thread 运行时」（例如要跨会话共享调度器或用阻塞线程池）→ 线程模型该重估，先写新 ADR；`apps/desktop` 出现 `.await` 或 `tokio::spawn` → 立刻回滚，桌面端一旦异步化，帧语义会被毁掉；bundled 构建在目标平台拿不到 C 工具链 → 改用纯 Rust 的 SQLite 绑定，或退回 JSON 加保险库并牺牲可查询性；某类服务器协商失败 → 先补算法映射表，仍不行则以系统 `ssh` 为主路径、进程内客户端为可选项；出现「忘记主密码」的支持请求 → 不做恢复后门，只提供「导出未加密条目一次」的显式降级并写明风险。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 继续延后整个后端 | 理由已不成立：同步那几件与 GUI、与网络都无关，延后只让脚本与自动化继续没有入口 |
| 把 tokio 引进 `term-app` 或 `term-runtime` | 等于交出「副作用只能以效果值返回」和「每会话一条线程」两条约束，分层退化成口头约定 |
| 只保留系统 `ssh`，不写进程内客户端 | 拉起子进程拿不到协议层可见性：SFTP、端口转发、`known_hosts` 判定都做不了，只能靠解析终端输出猜 |
| 保险库与会话库合到一个加密文件 | 两者生命周期不同：会话树要频繁小改，保险库要整块重加密；合并后每次改一个分组都要重写全部凭据 |
| 会话库存 JSON、只把密码挪进保险库 | 保住了凭据，但留下整文件重写的丢数据窗口，且无法按字段筛会话树 |
| 迁移旧明文会话一次 | 见决策 4：为一个不会再出现的状态永久维护兼容分支。真有人要旧树，做法是一次性外部脚本直写库，不往产品里加分支 |
| 先做会话导入 | 它依赖会话模型，模型没定就写导入，等于把别人的字段结构变成自己的内部结构 |
