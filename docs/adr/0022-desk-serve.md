# ADR-0022 · `desk serve` 只绑回环，用 token 与锁屏门守住远程执行入口

- 状态：已采纳；全文被 [ADR-0030](0030-foreground-control-plane.md) 取代。
- 关系：落地 ADR-0020 中「桥接服务」的缺口；依赖 ADR-0019（desk 是会话唯一所有者）与 ADR-0017（tokio 笼子）；不改动任何既有决策

## 背景

1. 会话所有者定为 desk，桥接、脚本、Agent 都是客户端。客户端要连得上，就得有个地方**等待连接**——而桥接层只提供了 stdio 形态（一条标准输入输出管道），没有网络层。
2. **stdio 的对端天然可信**：能往你标准输入写字的人，本来就能直接另起一个进程。TCP 不是——同机上任何进程、任何用户（如果监听面放大）都能连进来。
3. **这个能力面的杀伤力等于一个 shell**：开标签能起任意命令，写入能往终端里打字。所以它不是「一个本地 API」，而是「一个远程执行入口」，安全决策必须按后者做。
4. 错误分类里早就为这种情况留了位置：「被策略拒绝」这个类别（锁屏态或无授权时不许新建会话）先占住码位，加门时只改判定、不改线上形状。本 ADR 就是来兑现它。

## 决策

### 1) 它是 desk 的另一个形态，不是第二个可执行目标

`serve` 是 `cli/` 下的一条**无窗口子命令**，在窗口框架起来之前返回（与环境体检、能力面清单同一机制）。可执行目标已经收敛成一个，这里不开第二条口子。

一个连接一条线程，全部**同步**：会话池零 `.await`，stdio 形态也是阻塞式，所以 `serve` 在 tokio 笼子里一个字都不用破。

### 2) 只绑回环，不提供 `--host`

绑定 `(Ipv4Addr::LOCALHOST, port)`。默认端口 47653，`--port 0` 让内核分配，真实端口打印到标准输出供脚本捕获。

**刻意不提供 `--host`**：远程访问的正确形态是 SSH 隧道——那是有认证、有审计、有现成配置的通道。让本服务直接监听 `0.0.0.0`，等于把终端能力面挂到局域网上，「临时开一下」的便利会在第一次忘记关掉时变成事故。

这条不是口头约定：整个 desk 里只允许出现一处监听绑定，且必须绑在回环地址上，由检查脚本守着。

### 3) token 文件：`~/.zterm/bridge.token`，0600，不覆盖、不代改权限

- 首次运行以「文件必须不存在」的方式创建，权限位 0600，内容为 32 字节随机值的十六进制表示，取自系统随机源。不为一次 32 字节读取引一棵依赖树，直接用 `/dev/urandom`。
- 文件已存在就**沿用**：服务重启不该让已配置好的客户端全部失效。
- 权限宽于 0600 → **拒绝启动**，并告诉使用者去执行 `chmod 600`，而不是替他改。擅自改权限会掩盖使用者自己设的访问控制意图，下次还会被改回去。
- 比对用恒定时间（逐字节异或累加，不提前返回）。长度不是秘密，定长十六进制也不泄露内容。

### 4) 鉴权是传输外壳的准入，不进能力面

一条连接的第一条请求必须是 `auth`，带上 token；应答成功后才开始正常协议。

`auth` **不在**能力面的方法表里，也不出现在 `describe` 的结果中。理由：方法表里那些是**会话能力**，`auth` 是**这条连接凭什么被允许说话**。把它混进能力面，会让 stdio 客户端也看到一个自己用不着、且语义上属于传输层的方法。

失败一律回「被策略拒绝」并**关闭连接**，只给一次机会：256 位 token 不值得为它维护限流状态机，而「一次机会」迫使暴力尝试必须重新建连。

### 5) 锁屏门：纵深防御，不是主闸门

- **接入时**：锁屏则直接关闭连接，一个字节都不回——回错误等于确认「这里有个桥接」。
- **每次调用前**：再问一次。中途锁屏的会话立刻开始返回「已锁定」，但**不主动断连接**——客户端可能只是在等使用者回来解锁，断掉只会让它更难排障。
- **探测结果缓存 2 秒**：探测是 `fork` 加 `exec`（macOS 上读 `CGSSessionScreenIsLocked`），不是函数调用。不缓存的话，一段连续写入的脚本会被逐条拖慢十几毫秒——安全检查变成性能税，而性能税最后会被人用「关掉它」来还。2 秒窗口是安全的：锁屏是人的动作，没人能在 2 秒内锁屏再连上来。
- **探不出来就放行**：本服务的主要用途是本机脚本与自动化，探测失败就整体不可用属于本末倒置；token 仍然是硬闸门。

探测做成一个 trait，因为「真锁一次屏」没法自动化——把「怎么问系统」与「问了之后怎么办」拆开，后者可以用假探针在单测与端到端里钉死。

### 6) 后端适配留在 desk，桥接层不多一行依赖

桥接层的能力接口在 desk 里有一个生产实现，把会话池翻译成线上形状。**不放进桥接 crate**：那会让会话层（终端、线程、监管者）变成任何想用桥接的编译单元的依赖。

也不为此新建 crate：这份翻译的宿主是会话所有者，现在只有一个使用者。第二个宿主出现时再抽——那时才有第二个证据；现在抽等于凭想象设计接口。

测试夹具里另有一份同形的实现（夹具不能依赖二进制 crate）。防漂移靠三点：方法名与 schema 的单一真相是核心的方法表、参数解析只走桥接层的统一入口、两边各有断言线上形状的用例。

### 7) 显式承认的限制：`serve` 与窗口不共享标签页

它们是**两个进程，各自持有自己的会话池**：通过 `serve` 开的标签不会出现在正在运行的窗口里，列标签也只列本进程的。

跨进程共享需要一个中介（谁持有会话、窗口掉线怎么办、token 怎么分层），那是另一张 ADR。现在把它写清楚，而不是让使用者自己发现。

## 后果

- **正面**：脚本与自动化第一次有了稳定的连入方式，且路径是「连得上就一定是本机加有 token」；不新增可执行目标、不新增 crate、不破 tokio 笼子；失败分类沿用既有的错误类别，客户端不必为新能力学一套新语义。
- **负面**：生产路径上存在两份同形实现（另一份是测试夹具），靠单一真相的方法表与形状用例守；锁屏探测的「已锁」分支在本机无法自动化验证（锁一次屏要人工），解析按系统接口的文档形态实现并留了合成样例，真机验证属于发布前的手工步骤。
- **不改变的**：桥接层的依赖表、协议的线上形状、会话层的接口。
- **判据**：全仓库只有一处监听绑定且绑回环；`auth` 不出现在 `describe` 结果里；未认证或错 token 返回「已锁定」且连接被关；token 文件为 0600，宽权限拒绝启动且不改权限；锁屏时连接一个字节都不回；`apps/desktop` 源码零 `.await`、零 `tokio::`；真 TCP 端到端能开标签、等输出、取屏、关标签。
- **复查触发**：窗口与 `serve` 需要共享标签页 → 必须引入中介，决策 1 与 7 重写；出现第二个能力接口宿主 → 把那份适配抽成 crate，两份变一份；需要跨机器访问 → 先写清楚认证与审计，再谈绑定地址，不许直接放开 `--host`。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 提供 `--host`，允许绑定任意地址 | 等于把终端能力面挂到局域网；「临时开一下」的便利会在第一次忘记关掉时变成事故。远程访问应走 SSH 隧道 |
| 上 TLS | 回环加 256 位 token 已经覆盖这个威胁模型；上 TLS 就要管证书分发，而证书分发比 token 更容易做错 |
| 多用户 / 多租户 | 一个 token 一个使用者；要区分权限就再开一个服务实例，不为想象中的需求引入身份系统 |
| 把 `auth` 放进能力面方法表 | 会让 stdio 客户端看到一个用不着、且语义上属于传输层的方法；能力面应只描述会话能力 |
| 为错 token 维护限流状态机或多 token | 256 位 token 的猜测空间不需要限流兜底；一次机会已经迫使攻击者重建连接 |
| 把适配实现放进桥接 crate | 会让会话层（终端、线程、监管者）成为任何桥接使用者的依赖，桥接就从协议层退化成实现层 |
| 现在就为适配新建 crate | 只有一个宿主，抽象没有第二个证据；等第二个宿主出现再抽，成本一样而判断更准 |
| 省略锁屏门，只靠 token | token 是静态凭据，同机进程若读到它就再无阻拦；锁屏探测成本只有一次 `fork` 加 `exec`（且缓存 2 秒），换来的是无人值守时不再接受命令 |
| 锁屏时主动断开已建立的连接 | 客户端可能只是在等使用者回来解锁，断连只会让排障更难；返回「已锁定」已经足够 |
| 加一个「先非回环、以后再收紧」的开关 | 开关会被打开；安全默认值必须是不能被配置绕过的 |
