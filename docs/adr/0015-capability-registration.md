# ADR-0015 · 能力注册：动作按能力分区，未接线命令显式置灰

- 状态：已采纳

## 背景

动作派发已从字符串匹配改为类型化动作加纯 reducer，投影层不再解释字符串。但随后暴露出三个问题：

| 问题 | 事实 |
|---|---|
| 动作是平铺的全局枚举 | 窗口开关、对话框、查找等若干类动作混在一个枚举里；每加一个能力都要往同一个枚举加变体、往同一个 reducer 加分支 |
| 占位项与坏功能无法区分 | 菜单命令约两百条，其中已接线的只有十几条；其余落到「未处理」分支，点了没反应却看起来可点 |
| 投影层是第二个写入者 | 查找栏在绘制时把匹配总数与当前匹配写回视图状态，「状态只有一个写入者」只成立一半 |

## 决策

把「一个能力」作为最小演进单元，并把「是否已接线」做成类型层面的事实。

1. **动作按能力分区。** 顶层动作降为路由枚举：`Shell(ShellAction) | Find(FindAction)`。每个能力自持子枚举、自持字符串入口 `parse(&str) -> Option<_>`、自持 reducer。
2. **取消「未处理」变体。** 顶层 `parse` 返回 `Option<Action>`：能解析即已实现，解析不了即占位。不用空动作冒充成功。
3. **占位项显式置灰。** 菜单绘制时按 `capability::is_implemented(id)` 决定是否可点，悬停给出「未接线」的说明。
4. **菜单树降级为纯数据。** 命令清单从 UI 模块迁到数据层，UI 不再硬编码任何命令标识。
5. **匹配计数回到 reducer。** 匹配集由查询词加当前事实窗口确定性推出，投影层只读。总数不再缓存在状态里：输入换成事实窗口后，滚动会换窗口而不产生动作，缓存必然过期，因此改为每帧计算。
6. **粘贴走统一编码入口。** 投影层不得把原文直接写进 PTY，编码函数必须被调用、直写路径必须不存在。

可自动检查的判据：

- 命令标识只出现在数据层与各能力的 `parse`；
- 不存在「未处理」变体；
- 投影层不出现匹配计数的写入；
- 粘贴必须经过编码函数（调用存在、直写不存在）；
- 能力面三态清单由测试固定，条数变化必须同改测试。

## 后果

- 新增能力等于新模块（动作、解析、reducer、状态）加路由枚举一个变体、菜单数据一项，不改其它能力的 reducer。
- 置灰是一次可见的诚实降级：使用者能区分「还没做」与「坏了」。每接一条命令都要同时改清单数字——数字是确认，不是统计。
- 查找栏从两百余行降到约一百行，删掉的都是「投影层写状态」的实现。
- 不做动态能力：没有 `dyn` 派发、没有动态加载，能力表在编译期确定，插件式扩展不在本决策范围内。
- 查找的「下一个 / 上一个」语义随之改变：从光标位置重新搜索改为在匹配集合上循环，与「第 N / 共 M」的计数天然一致。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 保留平铺枚举与「未处理」分支 | 占位与坏功能仍然同形；能力增长继续堆在同一个 reducer 上 |
| 用动态插件与 ABI 派发实现能力注册 | 需要稳定 ABI 与加载器；能力表在编译期确定已足够满足「新增能力不改核心」 |
| 让投影层继续写匹配计数 | 违反「单一权威、投影只读」；同一份数据两个写入者，界面状态无法推理 |
| 让未接线命令可点但无动作 | 用户无法区分未实现与故障，问题被推迟到用户报告 |
