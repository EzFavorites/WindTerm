# ADR-0029 · 副作用会话按职责收敛：IO、档案、路径各自成层

- 状态：已采纳（细化 ADR-0014 的编译单元划分；「按副作用划分、依赖表即判据」的原则延续，`term-runtime` 不再是副作用落点）

## 背景

ADR-0014 把仓库拆成 core / runtime / app 三个编译单元后，「副作用会话」全部落在一个 `term-runtime` 里。它随后长成了一个杂货箱：会话线程、伪终端、串口、会话日志、会话库读写、界面偏好、窗口布局、主题文件、外部会话导入、本地目录枚举同处一个 crate。后果有三个，都是编译器可见的结构问题而不是风格问题：

| 压力 | 具体表现 |
|---|---|
| 档案层与会话线程同 crate | 改一行偏好的读写路径，要等带 PTY 与线程的那部分重新编译 |
| 依赖树被无关重物污染 | 任何想读偏好的地方，连带把 `portable-pty` 与 `nix` 拖进自己的依赖树 |
| 传输层被绑在本地设备上 | `TermChannel` trait 与 `SpawnError` 的类型本体在 `term-runtime`，SSH 库为了实现一个 trait 就得拖进整个 PTY 栈——而它明明只需要这两个类型 |

当时的应对是把「A 不许依赖 B」写成脚本判据。判据可以挡住反向边，挡不住「正着依赖但依赖错了东西」：正确的修复不是加更多黑名单词，而是让被依赖的东西待在正确的层。

## 决策

拆分依据不是「文件现在长什么样」，而是**内部的 `crate::` 依赖图**：把杂货箱里的模块按「谁只引用谁」分组，组内互相引用、组间零边的，就是天然的一层。实测下来边界干净得超出预期——会话 IO 那一组与档案那一组之间一条边都没有。

### 1) 四个新层与一个下沉

| crate | 收什么 | 依赖边界 |
|---|---|---|
| `term-io` | 会话 IO 与线程：pty / serial / serial_channel / telnet_channel / channel / supervisor / log / local_dir / host / preview | 语义层、路径层、PTY 库、串口库；无 SQLite、无 serde、无 tokio、无 UI |
| `term-profile` | 用户档案：persist / layout_state / prefs / quickbar / search | 纯语义层、路径层、SQLite 会话库、序列化；无 PTY、无串口、无异步运行时、无 UI |
| `term-paths` | profile 目录的唯一解析与启动期整理 | 只依赖取平台配置目录的库 |
| `term-import` | 外部配置导入：解析纯函数与主题文件读取 | 语义层、序列化、平台目录库；无会话运行时、无配置写入、无 UI |

通道 trait `TermChannel` 与错误类型 `SpawnError` 的类型本体**下沉到语义层的 `channel` 模块**：传输层为了实现它们不必再依赖带 PTY 与线程的 crate。实现留在 `term-io`，调用路径不变。

### 2) `term-runtime` 退化为兼容门面

界面侧仍有大量旧导入路径（`term_runtime::supervisor::…` 等），一次全改会制造一堆无意义的 import 冲突。因此门面保留同名模块的**纯再导出**，让旧路径继续解析；它不再有任何实现，依赖表里只剩四个实现 crate，连 `portable-pty` 都不再需要。

两条纪律随门面一起生效：

- **新代码不得依赖门面**，直接依赖对应实现 crate。可执行目标确实需要新类型（如文件预览的数据底座）时，直接依赖 `term-io`，不为省一个 import 给门面续命。
- **门面只许减**：旧路径迁完后，对应的再导出条目跟着删，不让门面长回杂货箱。

### 3) 判据落在依赖表上

验收脚本对**每个** crate 的依赖表逐个检查：语义层不得出现 UI / PTY / 文件系统 / 异步运行时库；应用层的内部依赖收成精确白名单（只许语义层一个，其余任何内部依赖一律判红——黑名单漏一个词就全体失守，曾经有crate 顺着词表空隙把带文件系统的依赖溜了进去）；SSH / 隧道 / SFTP 三个异步笼子不得反向依赖应用层，也不得碰门面。文件系统的 grep 判据与依赖表判据共用同一份词表，两处不许各写各的。

## 后果

正面：

- 档案层与会话线程互相隔离：改偏好不再等 Supervisor 编译，改监管循环不再重编序列化。
- 「想读偏好就拖进 PTY」这类连带污染从结构上消失——档案层的依赖表里根本没有 PTY。
- SSH 库只依赖语义层拿到 trait 与错误类型，「本机能开伪终端」不再是网络层的隐含前提。
- 本地文件 IO（目录枚举、文件头预览、宿主环境事实）有了明确的层：持有 OS 句柄，但不属于任何界面。

需要接受的代价：

- 门面是一笔暂时的债：它存在的每一天都在提醒旧导入路径还没清。全部迁完后它应退化成更薄的壳乃至删除。
- crate 数量从三个涨到十几个，workspace 成员表、发布脚本与文档里的代码地图同步变长。
- 「新增落盘文件要同步哪些清单」从一处知识变成两处（路径层的搬迁名单、临时文件前缀），漏同步的后果由启动期整理的测试兜住。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 立即改掉界面侧全部旧导入 | 制造一大批与本次收敛语义无关的 import 冲突，把结构性改动和机械改名搅在同一个变更里 |
| 保留杂货箱，加 lint 限制模块间引用 | 与 ADR-0014 否决 grep 判据的同一理由：例外只能登记不能隔离，lint 挡不住新文件 |
| 档案层并入路径层 | 路径层只有一条规则，档案层带 SQLite 与序列化；合并后改路径规则又要等序列化重编，恰好复刻要修的问题 |
| 把会话日志留在杂货箱原处 | 日志写入端必须在监管线程里（字节只有那一处拿得到），而监管线程在 IO 层；拆开等于每轮输出跨 crate 传字节 |
| 门面直接删除、一次性换名 | 与「立即改全部导入」同险；门面是迁移缓冲，不是永久层 |
