# ADR-0025 · 会话为单元，标签是会话的投影

- 状态：已采纳（与 ADR-0024 的「按会话名寻址」互补；取代「窗口持有一份标签列表、控制面另持一份会话登记表」的双真相模型；布局叶子一项后由 ADR-0026 细化为窗格身份）

## 背景

窗口里「有哪些会话、当前看哪一条」曾经有两套平行真相：

- 窗口持有一份 `Vec<Tab>`，用**下标**记活动标签（`active_tab: usize`）。
- 控制面持有一份会话登记表，按名字与运行实例身份寻址。
- 两份清单靠构造与增删站点的胶水同步，`Tab` 里又存了一份会话配置，名字因此有两个来源。

由此产生三类具体问题：

1. **下标寻址把「不在主区的标签」变成危险物。** 停靠面板需要自己的标签条时，只能另起一份平行列表；否则活动下标会指到另一个列表的同一格，表现为「点 A 跳到 B」。那份平行列表是寻址方式的并发症，不是功能需求。
2. **标签条遍历窗口的标签列表，而不是会话池。** 脚本开出来的会话进了池子却没进列表，用户看不见它；当时的应对是给界面脚本加一道「不许开会话」的闸门——把症状当成了策略。
3. **名字有两个写者。** 标签里的配置名与池里的名字各自可写，漂移无从发现。

判断标准可以收成一句：软件的基础单位是会话，标签是会话的呈现。会话是唯一真相，标签是按会话身份每帧现算的投影，活动标签用身份而不是下标。

## 决策

### 1. 两层身份，各司其职

- **逻辑会话**：用户在会话库里认的那一条，按名字唯一。
- **运行实例**：一次打开，`SessionId`（`u64`，进程内自增）。

窗内一切身份键用运行实例；持久化与跨进程引用用会话名。理由：同一份配置可以开多次，每次要有独立 PTY 与独立滚动，名字无法承担这个区分；反过来，名字是用户可见、可改的寻址键，适合跨进程。

不引入第三层「逻辑会话 UUID」：名字已经是会话库主键与线上寻址键，重启后按名字打开，在语义上就是同一条会话。代价是改名即断引用，这条代价被明确接受。

### 2. 窗口态迁到身份世界

- 窗口持有 `tabs: Vec<Tab>`（会话真身与生命周期）、`open_order: Vec<SessionId>`（有序身份）、`active: Option<SessionId>`（唯一焦点）。
- 窗口的 `active_tab: usize` 删除；仍按槽位寻址的局部结构与函数参数由派生访问器翻译：身份取槽位、槽位登记身份；越界与空窗口一律落 `None`，不再保留陈旧下标。
- 布局树叶子改为引用会话身份，删除「删除标签后重排下标」的逻辑——身份不随删除漂移（分组决策之后叶子改挂窗格身份，见 ADR-0026）。
- `open_order` 由 `tabs` 派生，两者等长同序；标签增删只有一个收口入口，不允许多处直接追加。

### 3. `Tab` 是投影，但保留一份打开时的配置快照

`Tab.identity: SessionId` 是恒在身份，铸造与存活态解耦：断连、重连、重排都不改值。名字、协议、连接参数在存活态一律从会话池按身份取。

例外是 `Tab.config`：它被重新定义为**打开时的配置快照**，不是与池子重复的权威字段。两个理由：

- 控制面没有「按标识取配置」的读取面，清单只给「标识、名字、状态」；
- 断连标签不在池子里，名字没有第二个来源，而「保留名字让用户能认出来、能手关、能重连」正是要的行为。

### 4. 视图态按会话键控，留在投影层

滚动位置、派生视图窗口、选区、输入行是每 `(窗口, SessionId)` 一份的投影，不写进控制面，也不写进持久字段。键到会话而非槽位：标签重排、跨窗格移动时视图态跟着会话走，不随槽位序号漂移。

### 5. 运行实例与窗口严格一对一，不引入引用计数

- 每个运行实例只属于创建它的窗口，不跨窗口共享；池子不记引用数。
- 关窗口 = 结束它拥有的全部实例；关单条 = 移出 `open_order`，若是唯一所有者再结束实例。
- 标签跨窗口移动 = 关旧实例 + 用同一份配置在新窗口开新实例（新 `SessionId`）。代价是丢失该实例的滚动与 PTY 状态；换来的是没有引用计数、生命周期只有一条规则。
- 同一配置在两个窗口各开一次 = 两个独立终端，符合「我想再连一台」的直觉。

### 6. 脚本与 API 共用同一条会话通路

- 打开只有一种结果：**新建运行实例**。两种入口只差入参形态：给完整配置或会话库引用是「打开」，只给已存会话的引用是「连接」。
- 「连接」是按已存配置引用打开，永远新建实例，不复用运行中的那一条；不存在「有就复用、没有就新建」的隐式语义，也不承担「聚焦已开实例」的职责（那是界面关注点）。
- 界面脚本因此不再需要「不许开会话」的闸门。脚本线程把新会话的身份与配置推进交接队列，窗口每帧取走、逐条绑定**同一身份**建标签（不抢焦点、同会话去重）。
- 无池的退化宿主仍然显式拒绝开会话——那是「没有会话池」的事实，不是界面策略。

### 7. 存活态以池子为准，每帧对账

`Tab::poll` 每帧取一次会话状态，三种返回分开处理：不在册 → 把标签转成断开态并请求重绘；无新事实 → 原样；有新事实 → 取快照。

转成断开而不是删标签：标签连同名字留在原处，用户能看见、能手关、能手按快照重连。一条标签在眼前凭空消失，比「断开」更难理解。被外部关闭的会话因此不再表现为「画面冻住、敲键盘全落空」的僵尸标签。

### 不变式

1. 一个 `SessionId` 在窗口里至多一条标签；`open_order` 与 `tabs` 等长同序。
2. `active` 为 `None`，或必须存在于 `open_order` 中。
3. 布局叶子引用的身份必须存在于 `tabs`。
4. 存活态以池子为准，断连态以打开时的快照显示；两者并存是分层，不是冗余。
5. 视图态不进控制面，不落盘。

## 后果

正面：

- 单一真相：会话在池子一处定义，标签是其投影；名字不再有两个来源。
- 「下标越界」「删标签后下标指空」「点 A 跳到 B」这一整类问题从设计上消失——身份不存在就取不到。
- 脚本开出来的会话自动成为标签，闸门没有存在理由；脚本与进程级路径同权。
- 断连标签保留名字与配置，重连不需要额外的名字来源。

代价：

- 改动面大：字段访问、布局遍历、标签构造与恢复都要改到身份；过渡期存在「派生列表 + 残留字段」的共存状态。
- 每帧投影多一次按身份取标签的查表；可用 `HashMap<SessionId, Tab>` 缓存、按池子变更失效，代价与按名查池同量级。
- `open_order` 当前由 `tabs` 派生，因此「遍历 `open_order`」与「遍历 `tabs`」行为等价；把它变成真源，要等 `tabs` 本身改成按身份索引的结构。
- 标签跨窗口移动丢失进程与滚动状态。
- 改名即断引用：布局恢复按名字查表，旧名字找不到就跳过。要消掉这条代价，需要给逻辑会话一个不可变持久标识，并同步改会话库主键与布局键——本决策不做。
- 停靠面板仍有一份独立的标签列表；它不再是「绕开下标」的隐患，合并只剩整洁收益，不构成行为变化。
- 断连标签的名字来自快照，因此快照必须覆盖显示所需的字段；把它当成「与池子重复」删掉，断连标签会全部失去名字。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 保留下标寻址，加强同步 | 同步点只会继续增加；「哪个下标属于哪个列表」靠约定，一次漏改就是跨列表跳转。结构问题不用纪律解决。 |
| 把窗口身份放进控制面 | 窗口是界面概念；控制面一旦认识窗口，分层就破了，池子也无法被无界面宿主复用。 |
| 运行实例跨窗口共享 + 引用计数 | 引用计数把「谁负责结束进程」变成分布式记账；跨窗口移动还要保证状态不丢。而「移动标签」并非高频需求，用关旧开新换取最简生命周期更划算。 |
| 用逻辑会话标识作为窗内键 | 同一逻辑会话可开多次，多个实例会撞同一个键，「这是第几次打开」的区分消失。 |
| 用会话名作为窗内键 | 名字可变、可重名（重名会被唯一化），改名即断引用；它适合寻址，不适合身份。 |
| 删掉配置快照，一切从池子取 | 控制面没有配置读取面，且断连标签不在池子里；删掉等于断连标签全部丢名字。需要同时补读取面与断连快照两件事，只做一半是倒退。 |
| 每帧从池子重算全量标签 | 会把别的窗口的会话拉进本窗口（串台）。「派生」的准确含义是窗口显式登记 + 每帧回收被外部关掉的会话。 |
| 让脚本保留一个受限的「只执行命令」打开入口 | 同一个意图在界面与脚本里走两条路：按名字打开会被当成命令执行，错误到运行期才显形。共用一个入口，差异只在入参。 |
