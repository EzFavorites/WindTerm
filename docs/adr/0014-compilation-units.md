# ADR-0014 · 按副作用把仓库拆成三个编译单元

- 状态：已采纳；取代 ADR-0009 的「不拆 workspace」条款（ADR-0009 其余决策继续有效）

## 背景

ADR-0009 当时判断：边界还没在单体内部验证过，提前拆分只是把耦合从源码搬进 `Cargo.toml`。此后前提发生变化：

| 变化 | 依据 |
|---|---|
| 依赖方向已在单体内部成立 | 门禁脚本长期检查语义层不得反向依赖 UI |
| 数据面已改为按范围请求 | 屏幕快照是值类型，取窗口是纯函数，成本只与窗口大小相关，与历史总量无关 |
| 回归资产齐备 | 金样本用例、单元测试与截图基线可在拆分后继续复用 |
| 语义平面已剥离墙钟 | 终端语义不再读时钟 |

同一次核查也暴露出 ADR-0009 未覆盖的结构缺陷：语义 crate 不是封闭的编译单元——线程与超时、PTY 句柄、读磁盘的主题加载，与纯语义文件同处一个 crate。这类副作用只能靠「限定文件 + 登记例外」约束，而 grep 判据挡不住整类副作用，编译器依赖图可以。

## 决策

建立 workspace，拆成三个编译单元，严格单向依赖：

```
crates/term-core     纯语义：零 UI、零 IO、零线程、零 OS 句柄
                     grid / vt / width / find / theme / session
crates/term-runtime  副作用会话：依赖 term-core
                     supervisor / channel / pty / persist / theme_load
app（可执行目标）     投影：依赖 term-core 与 term-runtime
                     main / ui / 状态与动作 / 字体 / 剪贴板 / 主题适配 / 金样本
```

- `term-core` 的依赖表只允许 `vte` / `serde` / `serde_json`，不得出现 `egui` / `eframe` / `portable-pty` / `dirs`。
- 全部线程、PTY 句柄、文件 IO、墙钟超时归 `term-runtime`；可执行目标只持有只读事实与 UI 框架。
- 主题加载拆成两半：配色方案到调色板的纯解析留在 `term-core`，找路径与读文件放进 `term-runtime`，语义层内不再出现 `std::fs`。
- 保持 `std::mpsc` 加每会话一个线程；不引入 tokio；不引入共享写锁，跨线程只传值。
- 判据由依赖表本身承担：语义 crate 新增一条 UI、PTY 或文件系统依赖会直接编译失败，不再依赖人工检查清单。

## 后果

正面：

- 语义层与副作用层的边界从脚本检查升级为编译器强制——语义 crate 的依赖表里根本没有 UI、PTY、文件系统 crate。
- 原先靠登记维持的架构例外不再需要。
- 不同人以不同功能并行改动时，编译单元互相隔离。

需要接受的代价：

- 所有模块路径改写；门禁脚本的 grep 路径、清单路径、金样本与截图路径必须同步更新，否则验收会假绿。
- `cargo test` 必须带 `--workspace`，否则只测可执行目标、漏掉两个新 crate 的测试。
- 增量编译缓存失效一次，多 crate 编译时间上升。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 维持单 crate 加 grep 判据 | 例外只能登记不能隔离；新增一次文件 IO 需要有人记得补一条判据 |
| 一次拆成按功能域的十余个 crate | 按功能域切开的正是变化最快、互相引用最多的一层 |
| 只拆出 `term-core`，运行时留在主 crate | 例外清不零，边界仍靠 grep，等于半途而废 |
| 用共享镜像加读写锁替代值传递 | 传输成本已证明与历史总量无关；共享可变状态会破坏「单一权威、投影只读」 |
| 顺带引入 tokio、更换 VT 内核或接入 SSH 库 | 与「只改编译单元」正交，属另一项决策 |
