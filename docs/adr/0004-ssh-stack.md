# ADR-0004 · SSH 栈选用 russh

- 状态：已采纳

## 背景

SSH 是产品的核心协议，栈的选择会长期影响跨平台构建、算法兼容性、异步模型与许可合规。

候选：

- A. `russh`：纯 Rust 实现，Apache-2.0。
- B. `ssh2`：libssh2 绑定，需要 OpenSSL 与 pkg-config。
- C. 调用系统 `ssh` 二进制。
- D. `libssh` 经 FFI 接入。

## 决策

采用 `russh`；SFTP 使用 `russh-sftp`，与主连接共享同一条认证会话。

### 理由

- **消除构建地狱**：不依赖 libssh2、OpenSSL、pkg-config。跨平台编译从「每个平台各调一遍 C 依赖」变成 `cargo build`。
- **异步原生**：与 tokio 同栈，通道读写、keepalive、端口转发都能用 `async` 表达。`ssh2` 是阻塞式 C 库，要线程池桥接，在多会话加大流量时会成为瓶颈。
- **许可干净**：Apache-2.0，与自有代码一致。
- **可审计**：纯 Rust 意味着协议实现可读、可打补丁。对一个要处理私钥的产品，这是实质优势。

## 后果

正面：

- 三平台构建一致，CI 简单。
- 可以对协议层打补丁，例如为老服务器补回弱算法。
- 无 C 依赖，静态链接没有摩擦。

负面：

| 负面 | 严重度 | 处理 |
|---|---|---|
| 老服务器算法兼容性 | 高 | 见下节 |
| 生态成熟度低于 OpenSSH | 中 | 用真实 sshd 夹具做回归；维护「已知不兼容服务器」清单 |
| 0.x 版本 API 迭代快 | 中 | 锁定精确版本，升级走独立 PR 加全量回归 |

### 老服务器兼容性

`russh` 默认算法集偏现代，只支持 `diffie-hellman-group14-sha1`、`ssh-rsa`（SHA-1）或 `3des-cbc` 的设备会连接失败。这是实际会遇到的问题，不是理论担忧：默认算法集与兼容算法枚举之间需要手写映射，缺了映射就会在握手阶段失败。

处理方式：

- 兼容模式按会话可选开启弱算法组，UI 显式标红风险；
- 弱算法默认关闭，不为兼容而全局降低安全基线；
- 提供连接失败诊断，明确告知「服务器只支持 SHA-1 算法，是否临时允许」，把选择权交给用户而不是静默降级。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| `ssh2`（libssh2） | 阻塞式 C 库加 OpenSSL 依赖，跨平台构建成本高 |
| 调系统 `ssh` | 无法精细控制通道、转发与认证流程；Windows 侧不保证存在；tmux 控制模式这类场景拿不到所需控制粒度 |
| `libssh` 经 FFI | LGPL 合规负担；FFI 层脆弱；构建复杂度会随平台增加 |
