# 能力面与菜单

## 这一层负责什么，不负责什么

**负责**：把「用户能做的每一件事」收敛成一份可枚举、可查询、可置灰的能力清单；让菜单、命令面板、脚本、JSON-RPC 与无头 CLI 共用同一套命令标识与接线状态。

**不负责**：具体怎么执行（在 `term-app` 的动作与 reducer）、怎么绘制（在 `apps/desktop` 的投影层）、以及某个命令属于哪个版本（范围见 `14-scope-and-requirements.md`）。

## 1. 三态模型

每个命令标识在能力面上有一个状态：

| 状态 | 含义 | 界面表现 |
|---|---|---|
| 已接线 | 有真实动作，调用会改变状态 | 正常可点 |
| 置灰 | 结构保留、语义已定义，但动作未接 | 可见但不可执行，悬停给出理由 |
| 规划 | 只在清单里，界面不出现 | 不出现在菜单 |

置灰是刻意保留的第三态：删掉菜单项会让结构与交互模型缺一块，而把没接线的项做得「看起来能用」比置灰更糟。置灰项必须能说出「为什么置灰」，否则就是噪音。

## 2. 命令标识的归属

- 命令标识（如 `Session.New`、`View.ZoomIn`）只在数据层定义一次，菜单树、命令面板、脚本能力面、无头 CLI 都引用同一份标识。
- 投影层不得硬编码命令字符串：界面只按标识查表拿「标签 / 快捷键 / 状态 / 是否可执行」。这条由构建门禁检查（`term-app` 之外出现命令字面量即红）。
- 同一标识在四种前端上的行为必须一致：菜单点一下、命令面板回车、脚本调用、CLI 子命令，落到同一个动作。

## 3. 菜单树：结构与接线分离

菜单树描述的是**结构**（一级菜单、子菜单、分隔符、顺序），接线状态挂在命令标识上。两者分离带来三个直接结果：

- 调整接线不影响结构：接一条命令只改能力面与动作表，菜单树一行不动。
- 调整结构不影响接线：补回一组子菜单不会让已有命令失效。
- 置灰项在结构里始终占位，用户能看见「这里有一类能力」，而不是面对一棵被删瘦的树。

菜单树本身是纯数据，不含 `egui` 类型；绘制层的职责只是遍历这棵树并按状态渲染。

## 4. 置灰理由要可读

置灰项悬停时必须说出**此刻为什么点不了**。理由不存进能力面数据，而是由绘制侧用同一个判态函数现算：`apps/desktop/src/ui/shell/menu_items.rs` 的 `action_state` 同时看 `capability::is_implemented(id)`（能力台账接没接）与当前日志写入端状态。因此实际只有两种口径：

- **`Not wired (placeholder)`**：命令未接线，在能力台账里是占位。
- **`Not available in the current log state`**：命令已接线，但当前会话日志状态让它不可用。

菜单栏、终端右键菜单与命令面板都走这一个函数，不各维护一张理由表——同一条命令不该在两处一亮一灰。新增置灰项无须登记文案，但必须保证判态经过 `action_state`；绕过它自己算 enabled，理由就会和状态脱节。

## 5. 命令面板的两种检索模式

命令面板把「动作」与「菜单项」拉到同一个搜索框里，分两种模式：

- **Command**：只列已接线的命令，选中即执行。
- **Anything**：列出全部菜单项，未接线的也展示并标注不可执行。

两种模式共用同一份能力面数据，差别只在过滤条件。这样用户既能快速执行，也能一屏看清「有什么、还差什么」，不需要逐级翻菜单。

检索按标签与标识做子串匹配，结果按「已接线优先、同级保持菜单顺序」排序；空查询时给出最近使用与常用分组。

## 6. 计数口径

能力面提供两个计数：命令总数与已接线数。派生口径固定为：

```
置灰数 = 命令总数 − 已接线数
```

菜单侧另有一个独立口径：菜单项总数（含分隔符之外的可见项）。两个口径不等价——菜单项可能映射到同一个命令（例如同一动作出现在两个菜单下），也可能有命令不占菜单项（只由快捷键或脚本触发）。对外展示时明确标注用的是哪个口径，不混用。

计数由 `inventory()` 现算，不在文档里写死数字；界面与 CLI 读同一份结果。

## 7. i18n 的边界

进入词表的：菜单标签、页面标题、按钮、提示、状态栏文字、关于对话框。

不进词表的：会话名、分组名、主机名、终端输出、要写进 PTY 的命令行、文件路径。这些是**数据**，翻译它们会破坏语义。

词表以「英文原文 → 目标语言」的映射实现，缺词回落到英文原文而不是空串；缺词不阻断构建，但会在设置页的「语言」分组里标注覆盖率。

## 8. 设计约束

- 命令标识唯一且集中在数据层；投影层零命令字面量。
- 每个置灰项必须有理由；理由与状态同源。
- 菜单树是纯数据，不依赖 UI 框架。
- 计数现算，不写死；文档不承诺具体条数。
- 能力面与脚本注册面共用一套标识，不允许两套并行命名。
