# 脚本与自动化

本文说明 WindTerm 的脚本能力是怎样搭起来的：Rhai 引擎跑在什么线程上、宿主暴露哪几组动词、一次执行被哪些预算与开关约束、错了以后脚本能从哪里读到原因，以及同一套能力面如何同时服务脚本与 JSON-RPC 桥。

**负责**：引擎与线程模型、宿主 API 的分组与命名口径、执行预算与取消传播、错误分类与 `last_error` 的语义、能力面与脚本注册面的对账关系、从成熟终端工具借鉴的设计点、JSON-RPC over stdio 的协议形状、`script run` 与 `serve` 两个入口及其准入、安全边界。

**不负责**：触发器规则的数据模型与匹配内核（属自动化内核，不在本文）；SFTP 与协议传输的实现（见《文件传输》）；会话控制面本身的动词语义（见 `docs/architecture.md`）；界面里脚本编辑器的排版与交互。

## 1. 引擎与线程模型

引擎是内嵌的 Rhai：纯 Rust、无 C 依赖、沙箱旋钮（操作数、嵌套深度、墙钟）可直接配置，且与 Rust 类型的互转足够顺滑，不必为每个原语写一层 FFI 胶水。这几条正好对上「脚本要能跑、但不能跑飞」的定位。

一次执行跑在**自己的线程**上，不在 UI 线程，也不在会话线程。这条边界决定了三件事：

- **脚本绝不直写 UI 状态**。要弹框、要改面板，都得把请求交给 UI 线程并等回执（`AskQueue` 的形状：一问一答、回信通道容量 1）。
- **会话操作走会话控制面的动词**，而不是摸 PTY 或 socket。脚本看到的是抽象会话，不是某类连接。
- **取消只能靠脚本自己看见令牌**。Rust 没有安全的线程终止，所以每个可能长阻塞的原语都必须在切片边界检查令牌；漏一个，那个原语就成了「按停止没反应」的黑洞。

运行时依赖只有会话抽象层与 `regex`，零 tokio、零 `.await`。这不只是洁癖：脚本线程一旦引入异步运行时，取消、超时与「谁在等谁」都会变成需要重新论证的问题。

## 2. 宿主 API 的分组

动词按用途分组注册，全部是**全局函数**，不挂在某个对象上。这样脚本读起来是线性的命令流，而不是一串对象链——脚本的常见形状本来就是「发一条、等一段、再发一条」。

| 分组 | 代表动词 | 用途 |
|---|---|---|
| 会话 | `session_open` `session_use` `session_close` `session_list` `session_current` `session_connect` `session_clone` `session_activate` `session_info` `session_at` `state` `facets` | 开会话、改绑、查询 |
| 收发 | `write` `keys` `send_keys` `wait` `wait_any` `wait_idle` `read` `read_until` `set_synchronous` | 写字节或按键、等输出 |
| 屏幕 | `screen` `region` `region_lines` `cursor_pos` `terminal_size` `selection` | 读当前屏幕、区域与选区 |
| 过滤 | `grep` `grep_v` | 构造行过滤句柄 |
| 文件 | `fs_read` `fs_write` `fs_append` `fs_list` `fs_stat` `fs_mkdir` `fs_remove` `sftp_list` `sftp_get` `sftp_put` `sftp_stat` `sftp_mkdir` `sftp_rename` `sftp_remove` | 本地与远端文件 |
| 进程 | `proc_run` | 跑外部命令并取输出 |
| 剪贴板 | `clipboard_get` `clipboard_set` | 读写系统剪贴板 |
| 日志 | `log_start` `log_stop` `log_status` | 会话日志 |
| 偏好 | `profile_list` `profile_get` `profile_set` | 读写具名配置 |
| 交互 | `ask` `confirm` `message` `text_input` `choose` `notify` `secret` `pick_file` | 向人提问、提示、选文件 |
| 应用 | `app_state` `app_panel_set` `app_layout` `app_quit` `window` | 面板、布局、窗口、退出 |

命名上有两条刻意的分工：

- **`write` 与 `keys` 不合并**。`write` 送原始字节，脚本拼什么就发什么；`keys` 送**键名**，由与界面同一张键表翻译成字节序列。合并成一个「聪明」的 `send` 就得在运行期猜「这串字符是文本还是键名」，猜错是静默发错字节——程序收到不认识的序列然后不动，脚本作者看到的是「卡住了」，不是「参数错了」。这类错在自动化里最贵。
- **`session_*` 按名字寻址**，不用进程内自增 id。名字跨进程稳定，脚本存下来明天还能跑；重名在插入时唯一化（`cat` 变 `cat-2`），返回的是真名。关掉当前绑定会被拒绝：关掉之后剩下的原语没有作用对象，自动改绑到别的会话属于静默换目标。

空模式一律拒绝。空串会立刻匹配任何东西，那是脚本 bug，不是「匹配全部」的简写。

## 3. 执行预算

预算分两档，因为两种用户的期待相反：界面上的用户在等结果，批处理里的用户要的是「别在中途放弃」。

| 档 | 墙钟 | 操作数上限 | 典型场景 |
|---|---|---|---|
| 交互 | 30 秒 | 100 万 | 界面「运行」按钮、编辑器试跑 |
| 批处理 | 600 秒 | 5000 万 | CI、`script run --batch` |

另有两条结构性上限：表达式嵌套深度 32，全局语法嵌套深度 64。三个旋钮各管一类失控——死循环归操作数、递归表达式爆栈归深度、慢脚本归墙钟。达到上限是**显式失败**，不是「返回已算出的部分」：半份结果比报错更难查。

墙钟同时钳制单次阻塞等待的上限。一个 `wait` 要 3600 秒也不能击穿脚本的总预算——否则「脚本 30 秒超时」这句话在一条 `wait` 面前就不成立了。

**输出没有单独的字节配额**，这一点必须说清，免得读者以为存在一个「最多能读多少」的旋钮。输出侧的边界由两件事构成：一是每次取数只返回「自上次消费点以来」的文本，二是捕获窗口固定 64 KiB，超出时按保尾裁剪丢弃最旧的部分。所以脚本拿到的是**有界窗口**里的数据；要处理更长的输出，正确做法是循环取数并当场消费（写文件、做判断），而不是指望一次 `read` 把几 MB 全端上来。被裁掉的旧数据不会报错，也不会补发。

## 4. 取消

取消旗子是一个跨线程共享的原子布尔。置位幂等——用户连点几下「取消」不该有任何额外后果；克隆共享同一个标志，否则取消只能在下一帧生效。

传播路径是「一次运行一份」：`HostEnv` 持有令牌，每个会话原语在构造时拿一份克隆，阻塞循环按 50 ms 切片检查。工作区自己的辅助方法（`sleep`、`ask`、`pick_file`、剪贴板读取、选区读取）在调用前与返回后各看一眼。

界面按「停止」置位后，必须能把**已经阻塞**的调用唤醒。人机端口用 100 ms 的 `recv_timeout` 轮询令牌，醒来就返回 `Cancelled`；面板请求与布局请求同样有超时上限，不让一次卡帧把所有调用拖成永久等待。

取消与超时是两个错误：`Timeout` 是「等的东西没来」，`Cancelled` 是「人不让它等了」。合并成一个会让脚本无法区分「重试一次」与「立刻收摊」。宿主不提供「忽略取消继续跑」的开关——有那个开关，取消就只是建议。

## 5. 错误分类与 `last_error`

失败一律显式，禁止静默空成功。错误类型的划分按**调用方要怎么处理**来定，而不是按发生在哪一层：

| 类型 | 含义 | 脚本该怎么反应 |
|---|---|---|
| `Timeout` | 等的东西没出现 | 换条件重试，或判定环境不对 |
| `Closed` | 会话已结束 | 停手，别再往死会话写 |
| `NoSuchSession` / `NoBinding` | 名字不存在 / 没有当前绑定 | 改名字或先 `session_use` |
| `BadArgument` / `EmptyPattern` | 参数不合法 | 改脚本，不要重试 |
| `UnknownKey` / `UnknownName` | 键名或（停靠面板 / 偏好等）名字不在表里 | 改脚本；文案会点名是哪一个 |
| `Denied` | 授权不足 | 改授权声明或换入口，不要循环重试 |
| `Unsupported` | 宿主没有该能力 | 换宿主（界面 / 无窗口）或降级 |
| `Cancelled` | 用户按了停止 | 收尾退出 |

文案直接面向脚本作者：带名字的变体（`UnknownKey`、`UnknownName`、`NoSuchSession`、`CloseCurrentSession`）就是为了让「是哪一个」不用逐个试。

`last_error()` 是一个**字符串槽**，不是一个异常日志：

- 初值是空串，空串表示「还没有错误」；不是 `null`、不是 `false`。
- 写入是**覆盖**，只保留最近一次；不存在自动清空，也不存在「成功后清空」。
- 它不替代错误传播。原语失败仍然抛 Rhai 错误，脚本该用 `try/catch` 就用；`last_error` 是给宿主与脚本自省读的旁路，不是「错误被吞掉了」的证据。
- 它也不做脱敏改写：写入什么就是什么，所以调用方必须自己保证不往里塞口令。

## 6. 一套注册面，两个前端

能力面是一张纯数据表：方法名、一句话说明、参数与结果的 schema、以及「哪个前端可见」。脚本注册与远程 `describe` 都从这张表派生，因此不存在「脚本能调、桥接不认识」的第二套语义。

`Exposure` 只有三档：两个前端都可见、只有远程可见、只有脚本可见（「只有远程可见」一档当前为空：`describe` 也对脚本可见）。分档不是随意的——远程侧有等价的更省往返的表达时，就不单列一个方法；脚本侧需要拿两个数时，也不必为了对称让远程多一次往返。

漂移防线是一条**集合相等断言**，而不是文档约定：

- 取名字的方式是问引擎自己（`gen_fn_signatures`），不是读一份常量表——常量表会和注册代码一起漂移，那就等于没有防线。
- 注册集合必须等于「能力面里脚本可见的动词」并上「语言辅助函数」。辅助函数只有 `grep` / `grep_v` 两个：它们是过滤器构造函数，不碰会话、没有远程等价物，所以不进能力面表，但必须能被点名。
- 任何新增的、既不在表里也不在辅助函数名单里的注册都会让这条断言变红。想消红只有两条路：进表，或者承认它是辅助函数并写进名单。

为什么不从表里自动生成注册：Rhai 的闭包是手写的类型适配（`f64` / `i64` 双重载、过滤器句柄参数、返回 Map 的字段拼装），生成器会把「漏写一个重载」推迟到运行期才发现。保留手写、用断言兜底，是这里唯一能同时拿到「不漏」与「报错早」的做法。

## 7. 借鉴 CRT 的设计思想，不提供对象门面

我们参照成熟终端工具的自动化经验，但**不实现它的对象形状**，也不解释它的脚本语言。
借鉴的是这些设计点，落到本仓就是原生动词：

- **录人敲的字节 + 屏幕静默点**，生成「发一段 → 等提示符 → 再发一段」的脚本；
  生成物用 `write` / `read_until`，人看得懂也改得动。
- **消费式与观察式分开**。`read_until` / `wait_any` 推进捕获游标并取走文本；
  `wait` 只观察、不推进游标。两者语义不同，不能互相代用。
- **坐标统一为 1 起、含端点**的屏幕矩形（`region`），会话按**名字**寻址，
  多会话脚本用 `session_use` 切换并钉住目标。
- **多入口**：菜单、映射键、按钮栏、会话登录钩子、命令行都能启动同一份脚本。
- **按运行授权**：危险能力默认全拒，脚本头 `// @cap`、命令行 `--allow` 与界面手勾
  三源合并，只作用于本次运行。

刻意不照搬的部分：只支持 Rhai 一种内嵌语言（另有外部 Python 子进程通道）；
不解析两行语言头；等待超时是显式错误，不返回「假装成功」的哨兵；不做对象门面，
所以照别家手册抄来的对象链在这里要改成动词，按 `docs/scripting.md` 的对照表改写即可。

对象名从来不进能力面表：能力面描述「会话能做什么」，schema 不出现协议名或对象名。
脚本注册集合等于能力面脚本可见动词并上 `grep` / `grep_v`，由集合相等断言守住。

## 8. JSON-RPC over stdio

桥接让外部进程用同一套动作操作会话，而不必链接本仓任何 Rust 代码。协议是 JSON-RPC 2.0，**一行一个 JSON**，读到 EOF 正常收场。

形状上的取舍：

- **参数只按名传**。收到数组形式的位置参数直接报 `invalid_params`：位置参数会让「第 2 个参数是什么」随 schema 演进而静默错位。
- **`id` 逐位回传**。数字用原始 JSON 数字携带，不把 `1` 与 `1.0` 揉成同一个值，否则客户端认不出自己的响应。
- **通知真实执行、不回包**；批量请求按序回包，全是通知时一个字节都不回。
- **错误是三元组**：`code`、`message`、`kind`。分类远比一句 `internal` 有用——「再等等」和「桥接坏了」不该是同一件事。
- **未知方法报 `method_not_found`**，不返回空成功。空成功会让客户端以为「这个方法什么都不用做」，而不是「我调错了名字」。
- **不推送、不订阅**。一条 stdio 管道就是一条串行的事实流；加订阅要引入连接级状态、重连语义与背压，收益不抵成本。要「等某件事」用等待动词，要「持续观察」就循环等。
- **非法行不中断管道**。回一个 `id: null` 的解析错误继续读，写失败才收摊——stdio 上写坏一行不该把整条管道打死。

`describe` 的答案由同一张表生成，桥接不持有第二份清单。任何手工维护的副本都会漂移，而漂移的表现是「客户端按 `describe` 调用，桥接说不认识」。

## 9. 两个入口

**`term-desk script run`** 是脚本引擎的第一个产品消费者，跑在独立进程里：

```
term-desk script run <file> [--exec CMD | --session NAME] [--cols N] [--rows N]
                            [--timeout SECS] [--batch] [--quiet]
```

- 默认开一个本地 shell 会话；`--exec` 改开一次性命令（给 CI 与排障现场），`--session` 改开会话库里那条（含内建 SSH），两者互斥。
- 退出码：0 脚本跑完，1 会话起不来或脚本报错，2 用法或读文件失败。**不把失败折成 0**——自动化里「跑挂了但退出码是 0」比跑挂本身更贵。
- 它不共享窗口的会话池，自己开自己关。这是进程模型的限制，不是偶发缺陷；跨进程共享要等一个 broker，现在不假装支持。
- 密码与 keyboard-interactive 认证的会话在这里打不开：密码在保险库里，而无窗口进程从不解锁保险库。遇到就明说「去解锁」或「改用 Agent / 私钥」，退出码 1——不偷偷换成系统 `ssh`，那就是行为分叉。
- 脚本来自 stdin（`-`）时 `ask()` 不可用：输入源已经被脚本本身占住了。stdin 不是终端时同样显式失败，不返回空串冒充「用户按了回车」。

**`term-desk serve`** 把同一套能力暴露到本机 TCP：

```
term-desk serve [--port N] [--token-file PATH]
```

- **只绑回环**，没有 `--host` 这个参数，并且有用例钉住它不存在——免得将来有人顺手把能力面挂到局域网上。远程访问走 SSH 隧道。
- 默认端口 47653；`--port 0` 让内核分配并把真实端口打到 stdout。
- token 默认在 `~/.zterm/bridge.token`，首次以 0600 生成；权限宽于 0600 时**拒绝启动**，提示用户 `chmod 600`，而不是擅自改权限盖掉用户自己的 ACL 意图。不覆盖已有 token：并发起两个 `serve` 时，后一个不该换掉前一个已经交给客户端的凭证。
- 每条连接的**第一条请求必须是 `auth` 握手**；不是 `auth` 或 token 不对，回一个 `locked` 错误并关连接，**只有一次机会**。
- 握手不在能力面表里：表里描述的是会话能力，`auth` 是传输外壳的准入，写进表会污染 `describe`。
- 之后每次调用前再查一次锁屏（纵深防御）：中途锁屏的会话立刻开始拒绝，但**不主动断连接**——断不断由客户端决定，服务端只拒绝执行。
- `serve` 与窗口是两个进程，各自持有自己的会话池。通过 `serve` 开的会话不会出现在正在运行的窗口里。

## 10. 安全边界

**授权是信封，不是全局开关**。一次运行一份 `Capabilities`，缺省全拒；放行来自脚本头声明或命令行 `--allow`，两者共用同一个解析器，所以语法天然一致。

- `fs=read:<路径>` / `fs=write:<路径>`：根目录先规范化再比前缀；`..` 与相对路径在比较之前就拒——先比再规范会让 `logs/../../etc` 通过。写是独立一档：给了读根不代表能写它。
- `process` / `clipboard` / `ui`：各自一档。
- `app` 与 `app=configure`：应用级状态单独一档。`app` 是最窄的可用档（读快照加改面板可见性，**不落盘**）；`app=configure` 才允许写偏好。把偏好写进 `ui` 会把「看一眼界面」与「持久改动用户配置」混成同一档风险。
- 档名写错一律报错，不静默降档。`app=tune` 不被接受，只认 `app=configure`；「想写偏好却只拿到只读」如果静默发生，脚本侧看不出差别。

**`secret` 不制造「看似隐藏其实没隐藏」**。界面里它是掩码输入框；进程级运行时它直接报 `Unsupported`——不关回显等于把口令打进终端历史与肩窥范围，做半套比明说不支持更糟。`Ask` 的一句话描述只写标题，不写提示正文，所以日志与错误信息里不会出现口令原文。日志、错误、`last_error` 都不做「自动脱敏」，这条责任在写入方：不要往这些地方塞口令。

**脚本不绕过能力面**。

- 会话面动作必须是能力面表里的动词；触发器动作、桥接方法、脚本原语引用的是同一张表，因此不存在「脚本有、远程没有」的第二条实现路径。
- 应用面写操作不直写界面状态，而是派发既有的 `Action`，由唯一的 reducer 落地。直写字段会造出第二条写路径，让「改没改」无法用同一份回读判断。
- 本地文件与外部进程都过授权信封；无头宿主的对应端口是显式降级（`Unsupported`），不是「静默用默认值」。
- Rhai 默认没有文件与网络访问，本设计不放开。脚本要碰这些，只能走上面那些受控动词。

## 11. 设计约束

- **引擎不碰 UI、不碰 PTY**；所有跨线程交互只有两种形状：一问一答的队列，或一次性的通知。
- **一个动词只有一种名字**。改名要走破坏性变更流程；在两端未定稿的窗口里可以改，定稿之后不许留两套拼写。
- **错误必须分类**。新增失败场景先问「调用方要据此做什么」，答不上来说明它应该并入现有类别，而不是加一个变体。
- **预算用名字而不是数字**。两档预算的意图由档名表达；中间那两百个可调秒数只是让人多做一次决定。
- **注册集合 = 能力面 ∪ 已列名的辅助函数**，这条断言不许放宽；新增辅助函数必须显式登记，不能靠「它反正不在表里」。
- **兼容层不进能力面**，不提供语言解释器，不为缺失成员造空成功。
- **桥接不加推送、不加连接级状态**；需要持续观察就由客户端循环等待。
- **服务端只绑回环**；token 权限判定在启动时做，失败即拒绝启动。
- **授权绑定单次运行**，不写进任何全局配置；一次「允许」不等于永久放行。
- **口令类输入只有两条路**：会被掩码的界面输入，或明确的「不支持」；没有第三条。
