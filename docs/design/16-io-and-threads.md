# 会话 IO 与线程层

本文说明会话的字节和线程真正落在哪里：伪终端、原生通道、每会话一条监管线程、
快照邮箱、日志写入端，以及为什么本地文件读取也归这一层。它是所有会话的地基——
[02](02-terminal-core.md) 把终端语义定为纯计算，本文讲那台计算器的输入输出两端
接的是什么。

**负责**：真实 OS 句柄（PTY、串口、socket、文件）的持有；每会话一条监管线程的
循环模型；字节到屏幕、日志、等待匹配、传输旁路的分配；宿主环境事实的读取。

**不负责**：VT 解析与屏幕模型（[02](02-terminal-core.md)）；会话的创建 / 寻址 /
控制面（[01](01-sessions-and-connection.md)）；日志内容的清洗规则与文件名模板
（[02](02-terminal-core.md) / [06](06-security-credentials.md)）；配置文件的落盘
路径与原子写（[15](15-persistence-and-file-layout.md)）；崩溃后的提示与恢复
（[10](10-crash-hardening.md)）。

## 分层位置与依赖边界

| 有 | 没有 |
|---|---|
| 终端语义层、路径层、伪终端库、系统信号库、串口库、标准网络库 | SQLite、序列化库、异步运行时、SSH 库、任何界面框架 |

这条表里"没有"的一列就是判据：日志虽然写文件，但它写的是"按这份配置落盘"，
配置对象由语义层构造、由调用方带进来，本层不认识偏好文件，也不去读它。
会话库与偏好属于档案层（[15](15-persistence-and-file-layout.md)），两侧互不依赖——
改一行偏好不该让监管线程重新编译，反过来也一样。

**同步**。异步只活在 SSH / 隧道 / SFTP 三个连接层 crate 里（见
[架构决策 0017](../adr/0017-backend-staging.md)）：本层的对外契约是"阻塞调用 +
一个队列"，界面只发命令、收快照，永不直接持有 OS 句柄。语义层的通道 trait 放在
更下面一层，让连接层为了实现它不必把整套伪终端栈拖进依赖树。

## 每会话一条监管线程

一条会话对应一条监管线程，线程体里跑一个循环，做四件事：

1. **排命令**：把界面发来的写、改尺寸、清屏、请求窗口、起停日志、登记等待、
   挂接旁路等命令一次性取空并按序处理；
2. **抽字节**：从通道拿这一轮的输出，每帧有上限，避免一次全量搬移卡住循环；
3. **加工**：字节先落日志、再喂终端语义，取回要写回设备的应答，同时喂给等待
   匹配器与输出读取器；
4. **发布**：屏幕有变化就放一份新快照，再按请求切出只读窗口，最后按退出状态
   决定继续还是收尾。

界面侧只有一个句柄：它发命令、取快照、合并少量事件。它看不到伪终端主端、
子进程或接收端，也不在绘制帧里做字节摄入与终端解析。

> 帧预算是有意的上限。一次 `find /` 吐出的字节远多于一帧能画的，若让它无限
> 增长，这一轮循环就再也回不到命令队列，键盘输入会被卡住。超出预算的字节留在
> 通道里，下一轮继续抽。

## 一槽邮箱与唤醒

快照不是每轮都发。早期做法每轮 `send` 一份，有两个具体毛病：生产者比消费者快
得多，绝大多数快照发出去就被下一帧丢弃，等于高频做整张网格的分配再扔掉；更要
紧的是队列本身不唤醒界面，"输出到达 → 不重绘 → 不取快照 → 看不到输出"，直到
用户动一下鼠标才刷新。

现在改成**一槽邮箱 + 唤醒回调**：槽里只留最新一份，消费者没取走就不再生成新的；
放入后调一次界面注入的唤醒回调，界面立刻醒来取。空闲时既没有快照分配，也没有
唤醒。装上回调的那一刻若槽已经是满的（启动竞态），会补一次唤醒，免得界面停在
空屏等用户碰鼠标。

一个槽就够——屏幕只有一份最新事实，中间版本没有保留价值。退出前是例外：已报告
退出后不再合并，强制覆盖槽，保证邮箱里是到本轮为止的最终屏。否则线程可能就在
这一轮末尾结束，被推迟的那份永远留在待发布状态，而退出事件已经发出、消费者
已经停止，拿到的就是旧空屏。

## 两档等待

循环按"这一轮有没有活动"分两档等待：

- **有活动**（收到命令或输出）：短等，因为输出往往成串，马上还有下一批；
- **完全空闲**：阻塞在下一条命令上，直到超时或命令到达。

不能用固定 `sleep(空闲档)` 代替后者：那样按键要等到下一个休眠周期才被处理，
输入延迟会明显变大。阻塞在命令接收上则会被按键立刻唤醒，同时把空闲时每会话的
系统调用频率降下来。这是一条同时满足"空闲省 CPU"和"输入不迟钝"的取舍。

## 一份字节的四个去处

同一批输出按状态分流，先后顺序是正确性的一部分：

| 去处 | 语义 | 与终端语义的关系 |
|---|---|---|
| 日志 | 写原始或清洗后的字节，由调用方配置决定 | 先记再解析，崩溃排查时顺序更保险 |
| 旁路副本 | 非破坏性复制给上层字节视图 | 复制，终端照常吃；取不到原始字节时无法从网格反推控制序列 |
| 终端语义 | 喂进状态机，取回应答写回设备 | 主路径，驱动快照与版本号 |
| 等待匹配 / 输出读取 | 吃清洗后的纯文本，不做正则 | 转义序列不该挡住 `Password:` 这类提示 |

等待登记与输出读取都遵循**先入队、后确认**：命令循环在抽输出之前处理登记，
确认信号放进匹配队列之后才发回。因此调用方拿到登记成功时，登记点之后到达的
输出一定会被匹配到。反过来做就会漏掉"刚登记、还没入队"那一小段窗口——这是
无头脚本里最容易被误判成竞态的失败模式。

**原始旁路**是另一种语义：字节整块改道给传输协议，终端不吃、屏幕冻结、版本号
不涨、也不进日志。传输进度由界面自己画，屏幕本来就不该动；旁路期间协议回包
由传输层自己写回。它和上面的"旁路副本"恰好相反——一个是改道，一个是复制，
两条独立的槽位，不能混用。

## 会话日志的写入端

日志写在这条监管线程里，不在界面线程：字节只有这一处拿得到，界面卡一帧不该
丢一屏输出。四个决定决定了这个模块的形状：

- 默认写**清洗后的可打印文本**，不是原始字节——日志的用途是事后翻一遍，不是
  放录像；选"记录全部输出"时才改走原始字节。
- **暂停 = 不写，但字节照样过屏幕**。恢复时在文件里插一行标记，说明停了多久、
  期间丢了多少字节；否则日志看起来像那段时间什么都没发生，那是更坏的误导。
- 文件名、每行格式、覆盖追加、大小上限都是用户可配的，本层只按给定配置落盘，
  不发明规则。同名默认不覆盖，而是加序号——覆盖等于把上一段日志悄悄删掉。
- 写失败就地停手并记住原因；磁盘满了还每轮重试只是烧 CPU。退出前一定收尾，
  否则最后几 KB 停在写缓冲里，用户拿到的是结尾被截断的日志。

日志状态只在变化时上报，字节数不在这里维护——文件大小是磁盘上的事实，界面
直接查文件，本层维护一份计数迟早与文件不一致。

## 原生通道

通道层把"一条会话怎么连到字节流"收在同一个 trait 后面，几种实现共用一条监管
线程：

- **伪终端**：本地 shell 与外部进程都跑在真 PTY 里，一个读线程抽主端，写端留
  给键盘输入。环境变量、启动目录、终端尺寸在这里落地；远端连接的超时也在这里
  判定。
- **串口**：本进程直接开设备，不拉外部客户端——只有进程内才拿得到收发计数、
  热插拔与流控信号。非阻塞读无数据是常态不是错误；重连不清零计数，否则状态栏
  会跳回零。写可能因流控只写出一部分，余下的留在自己的缓冲里下一帧补写；缓冲
  溢出丢最新的，不折断已经排队的字节；改尺寸一个字节都不写到线上。
- **Telnet**：用标准网络库直连，把协商语义接在字节流上。协商字节绝不进数据流，
  在语义层就被剥掉；读等待在后台线程，取窗口的调用不碰网络。窗口尺寸按协议在
  对端同意后才发，既不发非法协商，也不漏掉初始尺寸。
- **一次性命令**：无头入口直接起一条通道跑完，再排空最后一帧屏幕与退出码。
  它复用同一套监管循环，保证"屏幕上留下什么"与交互会话一致。

串口与 Telnet 打开失败都**明确报错，不回退**外部客户端。回退会让人以为在用
原生实现，实际还在拉另一个进程——这种假成功比失败更糟。

## 本地文件 IO 为什么也在这里

本地目录枚举、文件头预览、宿主环境事实都在本层，理由是同一条：它们持有或读取
本机事实，而终端语义层必须保持"同样的输入输出同样结果"，不能自己读环境变量或
文件系统。

- **目录枚举**：只返回已经变成值的行，界面不接触目录条目对象。隐藏项过滤放在
  数据层而不是绘制层——放绘制层的话，条目计数、排序、滚动上限都会先按未过滤的
  列表算，状态行的数量就与实际行数不符。改时间换算成显示字符串是纯算术，不引
  入日期库。
- **文件头预览**：只读开头一段，不把大文件整个读进内存；只看字节不看扩展名，
  因为扩展名会写错而魔数不会；图片只读头拿尺寸画占位框，不在这里解码。判定
  顺序是有意的——带签名的文本天生含零字节、图片头里也有零字节，所以签名与图片
  魔数都必须排在"含零字节即二进制"之前。
- **宿主事实**：当前登录名与壳名从环境读，注入给语义层构造默认会话。值只作
  展示用途，不拿来做鉴权或拼路径。

视觉基线不能钉在真实家目录上，所以演示夹具用固定条目，本层的目录枚举在夹具
下不被调用。

## 崩溃隔离与退出收尾

监管线程体整体包了一层 panic 捕获：某条会话的内部错误被吞在本线程，转成一条
人读得懂的说明写进退出注记，其余会话不受影响。payload 文本化只有两种标准形态，
兜底分支绝不能再 panic，否则一次可恢复的崩溃会变成整个进程退出。

退出有几条不能省的顺序：先落最终屏再报退出事件；先收日志再关通道；真实通道的
退出状态会重复返回，只报第一次；句柄被丢掉时也要收尾。这些顺序保护的是同一件
事——消费者收到"结束"时，屏幕和日志都已经是可信的最终状态。

## 兼容门面

底层收敛后，会话 IO、用户档案、路径规则与外部导入的实现分别落在各自的 crate
里；界面侧仍有大量旧导入路径。**兼容门面** crate 只保留这些旧路径的再导出，
让界面一行不改地继续解析，本身没有任何实现。新代码直接依赖对应的实现 crate，
不要依赖门面；门面存在的唯一理由是给尚未重新校对的那层留时间，校对完成后它就
可以退化成纯粹的再导出、直至删除。构建脚本会检查依赖方向，反向边一条都不允许。

## 设计约束

- OS 句柄只在本层；语义层与界面层都不持有伪终端、设备、socket 或文件句柄。
- 对外同步：阻塞调用加队列，不把异步运行时带进这条主路径。
- 一槽邮箱加唤醒；空闲不分配快照、不定时戳界面，退出前强制发布最终屏。
- 帧有预算；一次输出洪流不能饿死命令队列。
- 登记先入队后确认；旁路改道与旁路复制是两套独立语义。
- 原生通道失败不回退外部客户端；日志写失败就地停手并在退出前收尾。
- 新代码不依赖兼容门面；依赖方向由构建门禁守住。
