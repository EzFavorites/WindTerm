# 窗口壳与界面组件

## 负责什么 / 不负责什么

本文描述主窗口的**固定框架**：菜单栏、标签条、窗格工具条、终端区、快捷命令栏、状态栏
如何相邻与叠放，状态栏有哪些字段、为什么只留这些，快捷命令栏与标记图形怎么组织，每窗格
工具条与面包屑的边界，通知条的位置与画法，居中浮层（含锚定窗口）的定位规则，界面文案的
双语覆盖范围，以及命令面板的两种检索模式。

不负责：可停靠 / 可浮动面板的内部布局（另属停靠系统）；终端网格绘制、选区与查找；分屏树
的语义（见标签与分屏一篇）；对话框的业务内容。

## 窗口壳的相邻关系与叠放顺序

顶层面板的**声明顺序决定相邻关系**：先声明的占据外圈，后声明的只得到剩下的中间区域。
因此壳层顺序被固定为：

| 顺序 | 构件 | 高度 |
|---|---|---|
| 1 | 菜单栏 | 32 |
| 2 | 状态栏 | 27.5 |
| 3 | 快捷命令栏 | 27.5 |
| 4 | 查找栏（仅查找时） | 43 |
| 5 | 底带（横跨整窗） | 由停靠系统决定 |
| 6 | 左带 / 右带（整高） | 由停靠系统决定 |
| 7 | 标签条 | 30 |
| 8 | 窗格工具条 | 26 |
| 9 | Sysmon 细带（终端区下沿） | 25 |
| 10 | 中央区（终端） | 余量 |

- **贴底顺序**：状态栏先声明，所以它贴窗口最底边；快捷命令栏在它**上方**，两条等高且紧邻。
  反过来写会让两条互换位置。
- **两条竖带必须在标签条之前声明**：竖带才是整高的，标签条只横跨终端区。否则标签条会一路
  铺到右带上方，窗格工具条那几件也就对不上位置。
- **底带必须在竖带之前声明**：写在之后它只切走中间一条，左右带会一路顶到状态栏。
- **定高 + 垂直居中**：顶部三条与底部两条都给固定高度，并把内容放进垂直居中布局；不给定高
  时高度由内容撑开，24 点的图标按钮与 14 点的文字会各贴上沿，墨迹中线差 2–2.75 点。
- **纵向零内边距**：面板框默认会在上下各加 3 点，于是「设了高度」并不等于「画出来是这个
  高度」。顶部三条与状态栏都改用零纵向内边距；横向留 11 点，工具行例外只留 8 点——它的
  拖动抓手离窗格左缘就只有 8 点，用 11 会让整串窗格 chrome 右移。
- **分隔线按需关闭**：标签条与工具条上下同色相接，不加分隔线；菜单栏保留。
- **专注模式**压掉除菜单栏以外的一切——菜单栏必须留着，否则进去之后没有退出的路。
- **分屏时不画全窗的那三条**（标签条 / 工具条 / Sysmon 细带），改由每片窗格自画一套；否则
  同一屏上会出现两套 chrome。

## 状态栏：字段与取舍

左区在无事件时只有一个词 `Ready`；有事件时换成那一条事实，优先级依次是：连接中、隧道状态、
日志状态、只读查看模式（`Local mode`）、一次性提示文本。

右区按**从右往左**摆放（布局方向是右到左，先画的在最右）：

| 位置 | 字段 | 说明 |
|---|---|---|
| 最右 | `🔒 Lock Screen` | 可点击，直接锁屏 |
| 次右 | `🐛 WindTerm Issues` | 蓝色带下划线，打开项目主页 |
| | `YYYY/MM/DD HH:MM` | UTC 墙钟，分钟精度 |
| | `os` | 本机编译目标，不写死某个平台名 |
| | `Ln 行 Ch 列` | 光标位置，取自快照，行列各加一 |
| | `Window 列×行` | 网格尺寸，说的是「这屏能装多少格」 |
| 最左 | `Local Mode` / `Remote Mode` | 由活动会话的协议决定 |

- **没有竖线分隔符，也没有分区色块与状态点**：字段之间只有 20 点等宽空隙。分区染色与状态
  点会让一条只读的信息条看起来像仪表盘，且每加一个字段就要再定一次配色。
- **查找命中时整条换底色**：底色在面板框这一层换（内容层再铺一块会漏掉左右内边距），左区
  换成 `N of M Found`，右区字段一个不动，链接文字改白以免蓝底上再画蓝字。
- **取舍：删掉重复控件**。早先这条栏里塞过连接态、网格尺寸、接收字节数、配色下拉、日志与
  同步开关；主题切换在工作台里有真实入口，锁屏在菜单里也有——把同一个动作画两次，
  只会让「哪一处才是真的」变成问题。留下的是**没有别处可去**的信息（光标位置、网格尺寸、
  模式）与两个只在这条栏里成立的入口。
- **确定性**：`os` 取编译目标而不是照抄某个平台的字符串；墙钟是这条栏唯一的非确定量，截图
  运行把它钉成固定串，其余字段都来自只读快照与编译期常量，同一份代码两次出图逐字节一致。
  时钟按固定间隔请求重绘，空闲时不会因为要更新秒数而空转。
- **演示运行与正常运行画同一套字段**：早先的实现会在演示运行里短路掉新增字段，于是「演示里
  看着还行、真跑起来完全不是一回事」。现在只替换那一个非确定量。

## 快捷命令栏与标记图形

结构上是两个区：左区是配置菜单入口 + 若干命令组；右区是溢出下拉、设置、关闭。

- **组**：一个灰色组标签 + 若干命令按钮（彩色小图形 + 文字 + 细边框圆角矩形）。同一组颜色
  相同、形状不同；不同组用不同颜色区分。命令按钮的宽度按文字与标记计算，放不下时按可用
  宽度线性收敛，仍放不下的进右端溢出下拉——不裁切、不换行。
- **数据来自配置**（`quickbar.config`）：每条命令有显示文字、要发送的文本、颜色、标记与
  组归属。三个显示开关（多组、组标题、字母序）属于偏好设置，不随命令表落盘；组可见性是
  会话内的界面状态，同样不落盘——放进配置就会出现两个写入者写同一个变量。
- **标记图形**共七种：方、圆、十字、图钉、箭头、星、心。全部用绘图原语画，不用字体里的
  `★` / `♥`：字体一旦缺字，同一份代码在不同机器上会给出不同的图。星形拆成十个凸三角形，
  心形拆成两个圆加一个凸三角形，都是为了避免非凸多边形填充的不确定性。
- **点击不执行命令，只把文本送进输入行**（不带回车）。`reboot` 这类命令自动执行是危险的；
  没有活动会话时静默不动作。溢出、设置、关闭三颗各有真实动作，不画点了没反应的按钮。
- 这条栏与状态栏等高、整窗宽，共用同一种底色；开关只影响这条栏本身，不影响窗格工具条上的
  图标组。

## 每窗格工具条（面包屑）

工具条是**一条可整块拖走的工具栏**，不是「窗格 chrome + 一块面板」：从拖动抓手到面板右缘
是一个矩形、一次拖动，两段底色不同只表示视觉分段。

- 结构（从左到右）：拖动抓手、立体按钮组（窗口+加号、下拉、窗口+叉、窗口+圆）、面板段
  （`(i)`、面包屑）、右端三颗带真菜单的 `>` / `∨` / `⋮`。
- **面包屑是纯函数**：分组名按 `/` 拆成多级、跳过空白段，末尾补会话名；空分组只画会话名，
  不画一个空的 `›`。不拿协议当分组的父节点——那会把层级说错，也会让默认会话名与协议名撞车。
- **单窗格与分屏共用一份绘制**，靠一个作用域参数区分：单窗格 `salt = None`、允许整条拖走；
  分屏时 `salt = Some(窗格身份)`，所有 `egui` id 带上窗格身份，且**不允许拖走**——三格共用
  一份拖动位置会互相抢。
- **尚未覆盖的部分**：分屏下没有「每格各自的工具条位置」这回事，位置只有窗口级一份；矮窗格
  里三段 chrome 按比例压缩、终端至少留一行，此时工具条内容不做额外的省略处理；窗格标签条
  右端的三件（组名、＋、≡）与这里的工具条是两条独立的条，共用绘图原语但不共用状态。

## 通知条

一条前景浮层，不是固定带。位置钉在底部居中线上方 40 点（状态栏 27.5 再加一点缝），宽度由
内容决定，与窗口宽度无关。

- 两种性质：**恢复提示**（琥珀）说明「上次没走正常退出、已恢复到某个留存点」，**界面错误**
  （红）说明「某帧内部出错、已跳过该帧、会话未受影响」，并带第几次与原因。
- **必须画在最前**：界面错误会中断当帧剩下的一半，画在最后的提示条永远不会出现；前景层保证
  它先画也在最上面。
- **关掉淡入**：锚定容器默认淡入，而截图运行的时钟被钉在零，整条会永远停在淡入第一帧（几乎
  全透明）。另外它的首次显示是一次测量过程，所以出现的第一帧不可见，需要主动请求重绘。
- **提示条不因下一帧画成功而消失**：错一次、之后全好是最常见的情形，也正是最容易让人误以为
  「什么都没发生」的情形。只有用户点右侧的 × 才撤掉；再错一次则更新成「第 N 次」。
- **连续出错有退避**：连续出错达到 10 次后不再主动请求重绘。目的是留活口而不是放弃——进程、
  会话、隧道都还在，用户任何一次交互都会重新触发一帧，修好之后自然恢复。
- 原因是可能很长的格式化消息，提示条只显示前 80 个字符并加省略号，完整文本留在标准错误上。

## 居中浮层与锚定窗口

界面里有两类浮层，定位规则不同：

- **锚定窗口**（命令面板、Goto、命令中心、隧道、tmux）：居中锚定、**定宽不定高**。宽度在
  两端都钉死（只给最小宽时，一句长提示会把窗口撑宽，同一份代码两次出图就差几个像素），
  高度随内容；需要限高时内容进竖向滚动区并允许纵向收缩，否则三行内容也会留下一大片空白。
  稳定 id 与标题分离（标题随页面变，id 不变），默认不画关闭按钮——`Esc` 就能走的浮层多一个
  × 只是多维护一条关闭路径。
- **对话框**：不拖放、不缩放、不折叠，本质是不可移动的固定浮层。因此不走通用窗口容器，
  而是自绘 chrome（标题条 26 点、圆角 8 点、内边距 12 点），并且**只存尺寸**，位置由屏幕
  中心推算——窗口大小怎么变，弹窗永远在正中。

### 会话弹窗的外框分流

会话弹窗有多种用途，它们的外框不是同一种，而是按用途分成两支：

| 用途 | 外框 | 遮罩 |
|---|---|---|
| 新建会话 | 系统独立窗口（标题栏与窗口按钮由窗口管理器绘制） | 无 |
| 会话属性 / 编辑 / 默认模板 | 应用内弹层，与设置页一样没有自绘标题条 | 有 |

分流按 `kind` 在一个外壳模块里统一分派：新建分支请求后端开一扇真正的系统视口
（尺寸固定，打开时请求前台）；其余分支走无标题条的弹层。之所以不能合成一种：新建
需要系统级窗口与多视口能力，属性与默认模板则是同一窗口内的临时层，给后者画一条
自绘标题条只会多出一层不属于它的装饰。

- **两级回退**：运行在截图夹具里、或后端不支持多视口时，新建分支退回应用内弹窗，
  并保留自绘标题条供视觉基线比对。于是「真系统窗」与「回退弹窗」走同一套内容绘制，
  只有外壳不同。
- **遮罩只属于应用内那一支**：系统窗口已经与主体分离，再压暗主体没有意义；回退到
  应用内时照旧加罩。是否加罩由外壳判定，内容页不自己决定。
- **系统窗正文只画底色**：不再套一圈描边与圆角——那本是应用内弹层的边界语言。
  外框坐标按「内容区居中 + 标题栏偏移」推算，与浮窗的定位口径一致。

### 表单控件的单一实现

设置页、会话属性页、新建会话页共用**同一套**表单绘制函数，避免出现「同一件事两种
写法」：设置页用自己的字段盒与行距，会话页另画一套盒子、行距与标签截断，改一处样式
就会漏掉另一处。

- 一个盒子函数负责输入框表面（圆角、描边、底色），所有表单页共用；
- 一个行函数负责「标签 + 控件」的对齐，支持两种排布：控件在标签上方、或控件与标签
  同行——它们是同一组件的两个参数，不是两套风格；
- 标签列宽由「本页最长标签 + 固定间距」现算，每行标签格撑满该列，保证同页控件左缘
  落在同一条竖线上；窄标签的行不再只占文字宽度。

灰显规则也在这里统一：没有后端字段的控件只读并给出说明，而不是画成可编辑的样子。

## i18n 的覆盖范围

- **key 是英文原文**，词表是「英文原文 → 中文」的一张表；缺词一律退回原文。这样漏翻的表现
  是「照原样显示」，界面永远可用，不会出现空串或键名。
- 语言只有英文与简体中文两种，默认英文，落盘标签分别是 `en` 与 `zh-CN`（也接受 `zh`、
  `en-US` 这类写法）。默认值属于界面契约：既有界面截图都按英文取值，改变默认等于把一整批
  截图作废。
- **进词表的**：菜单树的全部可见文案（含可勾选行与子菜单标题）、面板标题、标签右键菜单、
  查找栏、状态栏、发送器工具行、各类浮层与关于窗口。
- **不进词表的**都是数据：会话名、分组名、终端输出、要送进 PTY 的命令行文本；预览窗里的
  字符集名、图片格式、`MiB` 单位、文件名与路径同理。理由不是省事，而是这些值由用户或设备
  产生，翻译它们等于篡改数据。
- **覆盖面靠两条扫描**：菜单树与面板标题逐条扫一遍（出现没翻译的字母文案即失败）；散落在
  各绘制文件里的固定文案另抄一份清单兜底。纯数字标签（如进制档位 `2` / `8` / `16`）按
  「不含字母」豁免，豁免边界单独钉住，避免豁免放宽成「返回原文也放行」。
- **未覆盖**：新建会话表单这类正文的双语化不在这一层，留给后续处理。

## 命令面板的两种检索模式

两种范围有真实差别，不是同一个开关的别名：

| 模式 | 列出什么 | 可执行 |
|---|---|---|
| 命令 | 已实现的命令 | 是 |
| 全部 | 全部菜单项（含未实现的占位项） | 否，行内灰显并给提示 |

- **注册表不另建清单**：条目递归取自菜单树，再并上标签右键那批「不在菜单栏里但真实存在」
  的入口（分组名单独叫 `Tab`）；是否可执行由能力注册表判定。命令 ID 不在这里存字面量，
  任何一侧新增一条命令，面板自动多一条。
- **命令模式还要排除上下文命令**：它们的 ID 路径需要目标才能成立，列进可执行列表只会让
  用户点了没反应；在全部模式里仍然可见。
- **过滤是大小写不敏感的子串匹配**，命中显示名、菜单名或命令 ID 任一即可——用户未必记得
  菜单名。结果集、当前条目都是「模式 + 查询词」的纯函数值，不缓存，因此不会过期。
- **交互**：上下键环绕移动、回车执行、`Esc` 关闭；一屏最多十行，结果更长时以选中项为中心
  开窗；点击某一行等于「先选中再确认」两条动作同帧派发。占位项确认时产生空动作，不假装成功。
- **状态只有四件事**：开没开、哪种范围、查询词、选中第几个。输入框的跨帧缓冲放在投影层，
  每帧只在外部改动查询词时回填——否则用户正在敲的字与输入法预编辑会被每帧覆盖打断。
- 面板打开时终端键盘有守卫，同一批键不会既给面板又发给 PTY；执行不经过字符串派发的旁路，
  确认后回到统一的动作派发。

## 设置页布局

设置页由左侧页列表与右侧内容区组成。内容区不画页级标题——第一个可见元素就是分组框标题，
避免同一个词出现两次、整页整体下移。

- **字段列**：标签左对齐，控件左缘统一到「本页最长标签 + 9pt」的列宽。每行标签格必须撑满
  该列宽；否则标签较窄的行只占文字宽度，控件左缘会在同一页里漂移。
- **控件宽度**：单行控件铺到分组框右内边距；下拉不设固定上限；带尾部按钮的字段（如列表
  高度）箭头贴框右内缘，右缘与同页其它控件齐平。
- **按钮**：固定尺寸（80×24）而不是只给最小尺寸，文字才会在按钮内居中。
- **分组框**：标题画在框外上方；框为闭合四边、圆角 2pt；描边由 painter 画在矩形内侧，
  避免滚动区把右缘半条线裁掉；左右内边距对称（10/10）。
- **行结构**：按页内容选择「标签 + 控件同行」或「标签在上、控件在下」：标签短的组走同行，
  长标签组走堆叠，不统一一刀切。
- **已知偏差**（按当前事实）：等宽字体已统一到 `kit/type_scale` 的语义阶梯，字段输入
  用 12.2pt 按基线定标，原先「字段宽度比基线窄约 10%」的说法已过期；分组框描边收进
  滚动区裁剪区，右框线完整可见，不再短 6pt；数值框由 `kit/form::spin_field_delta`
  画出可点击的 `▲▼`，不再是「没有增减箭头」。仍有的简化只来自数据模型：搜索页只有
  单条 URL，终端页多一行「选中即复制」开关。

## 边界

- 壳层顺序是几何契约：任何新构件要么插进这张表，要么明确「覆盖而非切分」（例如查找栏、
  传输进度行声明在中央区之后，覆盖终端底部一行而不切走它）。
- 浮层分两类，不许混用：模态对话框压住一切并带灰罩；浮层（命令面板、Goto、命令中心、预览）
  不算模态，打开时主窗口仍可点。
- 地址栏浮层画在最后，因为它承载直接输入焦点；危险操作的模态挂着时它整段不画——同时成立
  「输得进去」与「不盖住模态」，而不是靠调用顺序去赌。
- 状态栏只念事实，不自己算：连接态、隧道态、日志态、命中数都由各自模块从只读快照现算。
- 不画没有动作的控件：宁可少画一颗，也不留一颗点了没反应的按钮。
- 文案缺翻译必须退回英文，不许退回空串或占位符。
