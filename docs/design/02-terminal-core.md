# 终端核心与渲染

本文说明终端从字节到像素这条链上各层的职责划分与取舍：语义层如何做到对 UI、IO 与操作系统句柄完全不可见，网格怎样表达字符与宽度，字体如何把字符变成可排版的 cell 盒，以及绘制阶段的顺序与逐帧成本。

**负责**：VT 语义层的边界、屏幕模型（行 / 列 / 回滚缓冲）、字符宽度与 CJK 双宽、编码切换的作用范围、字体装载与 cell 度量、终端区渲染分层与绘制顺序、性能约束。

**不负责**：crate 之间的总体依赖图（见 `docs/architecture.md`）；选区、查找与滚动的交互语义（见《选区、查找与回滚》）；配色、控件尺寸与截图基线（见《主题与视觉基线》）；PTY / SSH / 串口的数据通路。

## 1. 语义层边界：无 UI、无 IO、无 OS 句柄

`crates/term-core` 的定位不是一个「放终端逻辑的目录」，而是一个可以无头编译、无头测试的值计算库。三条边界由 `scripts/verify.sh` 逐条检查，而不是靠约定：

- **无 UI**：`term-core/src` 内不得出现 `egui` / `eframe` / `epaint` / `winit`，Cargo 依赖表也按 crate 名拦同一份词表。语义层里的颜色是 `Rgb { r, g, b }`，只有在 `apps/desktop/src/theme.rs` 的 `to_color32` 才变成绘制框架的类型。
- **无 IO**：不读文件、不开 socket、不启动线程。主题文件的「找路径 + 读文件」住在 `crates/term-import/src/theme.rs`，解析本身是 `Palette::from_scheme` 的纯函数。
- **无 OS 句柄、无墙钟**：语义层不持有 PTY、串口、窗口，也不读时钟。边栏时间戳由宿主在写入前递入（`Terminal::stamp_row`），内核只把它记到那一行——时间是「被传入的数据」，不是「被调用的 API」。

这样做的直接收益有两件事：网格可以在没有窗口、没有真实终端的机器上逐 cell 比对；换渲染后端时语义层不需要改一行。

## 2. 屏幕模型与网格

网格是行主序的 `Vec<Cell>`，长度 `cols * rows`，对外的只读视图是 `GridSnapshot`：

```rust
pub struct Cell { ch: char, fg: Colour, bg: Colour, attrs: Attrs, wide: bool }
pub enum Colour { Default, Indexed(u8), Rgb(u8, u8, u8) }
```

`Attrs` 是八个手写位（粗体 / 暗 / 斜体 / 下划线 / 闪烁 / 反显 / 隐藏 / 删除线）——八个标志位不值得引一个宏依赖。`Colour::Default` 表示「跟随调色板的默认前景 / 背景」，`Indexed` 表示 xterm-256 的某一项，`Rgb` 表示 SGR 直给的 24 位色。三者并存的好处是网格不绑定任何具体配色：换主题只换解析表，不重写已画过的内容。

**回滚缓冲**是 `VecDeque<Vec<Cell>>`，按最老在前的顺序存。容量由 `max_scrollback` 决定，默认 `config::DEFAULT_SCROLLBACK = 999999`，上限钳到 `config::MAX_SCROLLBACK`。`history = scrollback.len()` 直接进入快照，因此「还能往上翻多少行」这件事 UI 不需要额外发一次请求去探——滚动上限、滑块比例都从这一个数字来。

快照同时携带**模式位**，而不是让绘制层去猜：方向键是否应用光标模式（DECCKM）、是否括号粘贴（DECSET 2004）、鼠标上报模式与编码、是否处于备用屏、OSC 133 命令块表、行时间戳表、自动换行续行表。绘制层手上没有 `Terminal` 实例，只有快照；凡是要影响像素的模式，都必须在快照里有一格。

**失效语义**分两级：`DirtyRows { rows, full }` 里 `full` 表示整屏重排（resize / 清屏 / 切换备用屏），否则按行标记。这一级目前只是网格层给出的类型与判据，绘制侧真正用的是行内容哈希（见第 8 节）——两套判据互为补充，不是替代关系。

## 3. 事实窗口：唯一的渲染入口

绘制只认一个形状——`ScreenImage`：

```rust
pub struct ScreenImage { cols, version, range, lines, cursor, history }
```

它是**值类型**：不含锁、句柄或闭包。`range` 用「视口行」编号，`0` 是贴底时的屏幕首行，负数是向上回看，与 `LineSlice.row`、选区行号、查找结果行号同一套坐标系。越界行用空白补齐，所以上层不需要知道内核历史的上限。

三个派生操作各有明确语义：

| 操作 | 语义 | 失败时 |
|---|---|---|
| `crop` / `crop_view` | 从已有窗口裁出子区间 | 覆盖不全返回 `None`，上层重发请求而不是硬画 |
| `blank` / `blank_view` | 占位空白帧 | 只用于「事实还没到」的中间态 |
| `drop_rows` | 过滤掉被折叠的行，产出新值 | 行号从此带洞，此后不得再做减法定位 |

渲染因此只有一条路径：贴底时 `GridSnapshot::to_screen_image()`（`range = 0..rows`），回看时向内核请求范围再 `crop_view`。绘制代码不分叉——回看不是另一种渲染，只是把窗口挪了几行。门禁对此是双向的：`ui/` 不得直接索引 `snapshot.cells`，也不得再调用只吃快照的查找入口。

## 4. 字符宽度与 CJK 双宽

宽度判定在**渲染之前**就完成，来源是 Unicode 的东亚宽度区间表（`crates/term-core/src/width.rs`），不是字形实测。一个字符占两格时，起始格带字形并置 `wide = true`，后一格是占位空格——这是全终端一致的做法，代价是网格里出现「有格无字」的位置。

由此产生一条容易被踩的规则：**布局单位是格，文本单位是字形**。按格逐 `ch` 取文本，`你好` 会变成 `你 好`（中间那个占位空格也是 `ch`）。所以取文本只有一处实现 `grid::cells_text_range`：跳过延续格、去掉行尾空白，`row_text` / `LineSlice::text` / 选区文本 / 查找扫描全部走它。选词与查找的边界判定同样先「把格折叠回字形」再比较，列号在命中后由字形起始格还原。

自动换行也是真的换了一行，内核把新行号记进 `wraps`（升序的绝对行号表）。这条表有三个消费者：行尾折行标记、边栏的 `~` 列、以及复制时「相邻两行之间该不该插换行」。判据下沉到 `grid::is_continued` 一处，三处共用一次二分查找，不再各自漂移。

> **软换行（按指定列）已于 2026-11-24 接线**：走「折行宽度可配」路线——用比内核列宽更窄的 wrap column（默认 40）再折一次，让一条硬折行占多段。内核 `vt.rs` / 三张绝对行号表全部不动；`wraps` 保持硬折原义，软折续段用 `VisualRow::soft_continued` 独立表达。段表每帧在投影层算一次，正文 / 查找 / 选区命中 / margin / 回看各自按段换算坐标（行号/时间戳只首段，行尾勾按行）。`--demo scroll` 与 `--demo wrap` 同字节流、截图逐字节不同是端到端判据。完整分析见 `crates/term-app/src/wrap.rs` 模块头。另一条「内核 reflow」路线（拼回被 resize 丢弃的逻辑行）仍未做，但当前方案不需要它。

## 5. 编码切换：只影响之后的输出

字符集是**会话属性**（`SessionConfig.charset`，默认 `config::CHARSET = "UTF-8"`），不是网格属性，也不是每格一份记录。

语义层吃到的是字符流：字节先由 `vte::Processor` 解成字符（跨 chunk 被切开的半个 UTF-8 由解析器自己拼完整），网格里只存 `char`。这一层信息损失是刻意的——网格记录的是**渲染结果**，不是字节录像。因此：

- 改编码只可能影响**之后**到达的字节，已入网格的字形不会被重新解释；
- 「切回旧编码看历史」在模型上不可能成立，需要原文只能走会话日志；
- 会话日志的清洗（`crates/term-core/src/ansi.rs` 的 `TextCleaner`）复用同一个解析器，避免「屏幕一套解释、日志另一套解释」。

这也是为什么模式位必须进快照：绘制层要在不知道 `Terminal` 的情况下决定粘贴该不该加括号、方向键该发哪种形状。

## 6. 字体装载与 cell 盒

字体层（`apps/desktop/src/fonts/`）做三件事：按用户选择装字面、量出 cell 盒、在字体不可用时回落。

**四槽字族**对应设置页的四行：槽 0 是主字面，槽 1 通常是 CJK，槽 2–3 是补充回退。空槽表示「自动」，走内置候选（各平台一份等宽候选表 + 一份 CJK 候选表）；候选按顺序试读，读不出就试下一个，全部失败时退回绘制框架自带字形——终端不会因为缺字体拒绝启动。**字重只作用于槽 0**：回退字族按各自常规面装，否则中英混排会忽粗忽细。

网格使用**独立的字族名**（`windterm-terminal`），不直接占用 `Monospace`。UI 的菜单、标签也挂在 `Monospace` 上，若把终端字重直接装进去，用户把终端设成粗体就会把整个界面一起加粗。

**cell 盒从字体量出来，不从字号推**：cell 宽取 `glyph_width('M')`，行高取 `row_height`。两个值一变，网格列数与 PTY 尺寸随之重算，所以「换字体」是一次真正的重排，而不是换个字形继续排。字号默认 `config::DEFAULT_FONT_SIZE = 13.0`，可调区间 6.0–48.0（设置页滑块与渲染层共用同一组上下限），缩放按 ±1 逻辑点步进。

替换字形有一帧延迟：`set_fonts` 交给框架后**下一帧**才生效。于是「刚交出新定义的那一帧」量到的是旧字体——这一帧照量（首帧排版需要它，否则会按占位值把 PTY 按错误行列 resize 一次），但把「已量」标记撤回，下一帧用真正生效的定义重量。字族名在真正生效前不可用于取字形（未绑定字族在绘制库里会 panic），此时 `font_id()` 退回 `Monospace`，代价只是头两帧用 UI 的字体量。

回落是**可见**的：`slot_info().fell_back` 让设置页能说出「选的名字没装，实际用了谁」。默认四槽全空时启动路径不扫字体目录，只有用户真的选过字族才建清单（扫描约一秒，不在启动路径上）。

## 7. 渲染分层与绘制顺序

终端渲染按职责分成五段，与总体分层一致，但每段内部的边界值得写清楚：

| 段 | 承载 | 约束 |
|---|---|---|
| core | 事实值、调色板、坐标类型（`ViewRow` / `HistoryRow` / `ViewRange`） | 零 UI、零 IO、零时钟 |
| app | 投影状态与纯几何：`Viewport`、`Selections`、`FindState`、`Folds`、`scrollbar.rs` 的 `Track` / `Thumb`、`wrap.rs` 的行切段、`margin.rs` 的列开关 | 零 `egui`，可单测 |
| view | `apps/desktop/src/ui/terminal/`：`pane_body`（正文与光标）、`pane_overlays`（五段叠层）、`pane_scrollbar` / `pane_preview`（第 7、8 段）、`view.rs` 的合批与行缓存、`margin.rs` 的列宽与绘制 | 只读事实窗口，不改语义状态 |
| render | `apps/desktop/src/theme.rs`（色值与令牌转译、视觉样式安装）、`ui/kit/type_scale`（字号层级） | 颜色与字号不许在 `ui/*.rs` 硬编码 |
| platform | `fonts/`（字体文件）、`clipboard.rs`（系统剪贴板）、`shot.rs`（离屏截图）等窗口 / 外设触点 | 触点按路径精确白名单列出，名单之外出现绘制框架类型即判红 |

**顺序决定像素，一条都不许换**：正文 → 叠加层（查找高亮 → 常驻词高亮 → 空白 / 符号标记 → 调试覆盖层 → 光标）→ 滚动条 → 预览框。调试层插在标记之后、光标之前，理由都是几何上的：既不能被半透明高亮糊住，也不能把实心光标画脏。

**合批**是这一层的主要优化：一行内连续、同样式、非空白的 cell 合成一个 `Span` 一次画出，连续同背景的合成一个 `BgRun` 一次填充。典型行的绘制调用从「每格一次」降到 1–3 次；宽字符单独成段，因为它的字距由字体决定，与 ASCII 混排会破坏逐格对齐。

## 8. 性能约束

- **每帧不扫描**：绘制只读当前事实窗口，不遍历回滚缓冲、不索引 `GridSnapshot.cells`、不重新解一遍模式位。
- **缓存行**：行内容哈希作为脏判据，未变的行直接复用缓存的 spans / bg_runs，连字符串构造都省掉。缓存实例按绘制目标分开——预览框用栈上独立实例，与主视图交替写会让两边每帧互相失效。
- **就近判脏而不是整屏重画**：绘制侧以行哈希判定单行是否重建；整屏重排只在 resize / 清屏 / 切备用屏这类事件上发生，不会因为一行变化而重画一屏。
- **空闲 0 CPU**：没有新快照就不重绘。反过来，任何「指针停在边缘要持续滚动」的交互都必须显式请求重绘，且只在状态真的变化时请求——否则「已经滚到顶」会变成永远重绘的空转。
- **值传递有成本上限**：多一份事实窗口（悬停预览）就是多传一份 `ScreenImage`，成本与窗口大小成正比（24×80 量级为几十微秒），因此不引入共享镜像或锁。
- **计数不进状态**：查找的匹配集合是「查询 + 窗口」的纯函数值，每帧算一次（见《选区、查找与回滚》）。用一屏扫描换「不存在过期计数」。

## 9. 设计约束

- 语义层不新增任何对 UI / IO / OS 的依赖；新能力若必须碰外设，入口放在 runtime 或 import 一侧。
- 颜色、尺寸、字号只能来自令牌或实测度量，`ui/*.rs` 不写字面量。
- 网格只记录渲染所需的最小事实，不承担回放职责；要原文请走会话日志。
- 不接受「贴底与回看两条绘制路径」；只允许一条 `ScreenImage` 路径。
- 字体层测出的「CJK 字形是否真的占两格」目前只是度量记录，网格的列宽判定仍来自 Unicode 宽度表。两者若在某套字体上不一致，应以显式规则统一，而不是在绘制时补偏移。
