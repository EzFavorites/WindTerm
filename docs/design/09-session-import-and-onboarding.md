# 会话导入与首次启动

本文说明「把机器上已有的会话搬进来」和「第一次启动时预填会话树」的实现方式。
它写给需要改动导入器或引导页的贡献者；导入后的日常操作见
[user-guide.md](../user-guide.md)。

## 这一层负责什么、不负责什么

| 这一层负责 | 这一层不负责 |
|---|---|
| 把外部文本解析成会话领域类型 | 决定扫哪些目录、什么时候问用户 |
| 宽松兼容多种序列化形态 | 解密或迁移第三方密码 |
| 分组、命名与落库前的合并 | 会话连接与认证（见 [01](01-sessions-and-connection.md)） |
| 首次启动的两页引导与预填 | 后续的持续同步 |

## 三步流水线

导入被拆成三步，边界落在 crate 上：

```
① 发现            ② 解析                     ③ 落库
外部配置在哪        文本 → 领域类型             领域类型 → 会话库
（投影层读文件）    （term-import，纯函数）      （调用方合并后保存）
```

`term-import` 的依赖表里没有会话运行时、没有配置写入、没有 UI，也没有写权限。
它只回答「这段文本里有哪些会话」，因此每条解析都能用固定字符串写单测，跑多少
次结果都一样。唯一的宿主依赖是展开 `~` 时的家目录查询——`IdentityFile
~/.ssh/id_ed25519` 必须变成绝对路径。

## 输入格式

| 来源 | 形态 | 产出 |
|---|---|---|
| OpenSSH 客户端配置 | 按 `Host` 分段的文本 | SSH 会话（主机、用户、端口、密钥路径、跳板链） |
| 第三方终端会话导出 | JSON 或节段式文本 | SSH 会话（含分组、跳板链、密钥路径） |
| PuTTY 会话文件 | 节段式文本 | SSH 会话（含密钥路径） |
| 本机 Shell 列表 | `/etc/shells` + `$SHELL` | 本地 Shell 会话（无主机） |

## 宽松解析

第三方会话文件的格式并不公开，导入器按「宽松解析」处理：

- 先试 JSON，解析不出会话再按节段式文本读。判断不能只看首字符：`[section]`
  也以 `[` 开头，直接当 JSON 数组会把整份文件读成空。
- 认不出的**行**忽略，认不出的**整份**才返回空——不因为一行怪格式就把整份
  配置判死。
- 键名大小写不敏感，`Key value` 与 `Key=value` 都认。
- 只取能连上的字段：主机、端口、用户、分组、跳板链、密钥路径。密码类键在
  进入字段表之前就被跳过，连读都不读。
- 空值不覆盖已有默认值；端口解析失败回落到 22，而不是把会话丢掉。

## OpenSSH 配置的解析口径

- `Host` 一行多个别名展开成多条会话；含 `*` / `?` 的块当默认值，不生成会话。
- `HostName` 是目标地址，没写就回落成别名本身（`ssh web` 的 `web` 本身可解析）。
- `User` 可空。导入时留空而不是编一个登录名——ssh 会回落到本机登录名，导入器
  没有资格替用户决定。
- `Port` 缺省 22；`IdentityFile` 展开 `~`；`ProxyJump` 整条链原样保留。
- `Match` 段跳过，不生成主机，也不把段内指令套到前后块上。
- 行尾注释只在 `#` 前有空白时裁掉：`Port 2222  # bastion` 要能读成 2222，而
  `IdentityFile /keys/id#2` 里的 `#` 是路径的一部分，裁了就找不到私钥。
- `Password` / `PasswordEncrypted` / `Passphrase` 等键一律不读。

## 树结构还原

导入结果不是一张平表，它带分组：

- 每条导入结果有 `group` 字段。解析器给的默认分组区分来源（OpenSSH、第三方
  终端、PuTTY、本机 Shell），用户配置里写了分组就用用户的。
- 分组只在实际新增了会话时才创建：空导入不该在树上留一个空文件夹。
- 合并后按「分组名、会话名」做大小写不敏感的排序，再整表保存。树是「分组 +
  会话」的两层结构，没有嵌套分组，也没有从第三方文件里推断层级。
- 首次启动引导另有自己的落点：所有预填会话放进一个统一的导入分组，与用户
  自己建的会话分开，第一次打开不会看到一团混在一起的树。

## 去重与命名

去重的实际判据是**会话名**：

| 入口 | 遇到同名时 |
|---|---|
| 侧栏导入 | 跳过该条，不覆盖已有会话 |
| 首次启动引导 | 改名后追加，后缀沿用「复制会话」那套（`web (copy)`） |
| 会话库 | `name` 是主键，落库前名字必须唯一 |

启动恢复另有一套名单规则：指定会话档会跳过空行、按书写顺序去重；恢复上次
布局档保留重复与顺序——用户真的开过两条同名会话时，恢复出来就该是两条。
`resolve` 一类的运行时寻址也只认精确名字，不做模糊匹配。

**没有**「主机 + 端口相同就视为同一条」的判据。同一个主机在树里出现两次是
合法状态（不同分组、不同认证方式、不同跳板链都可能），导入器不替用户合并。

## 密码永不迁移

这是产品底线，也是类型层面的保证：

- `ImportedSession` 里**没有密码字段**。解析器不是「读了再丢」，而是根本没有
  地方放。
- 第三方配置里的密码是加密的，各家方案不公开；解密既不合规也不可靠，所以
  不尝试。
- 首次连接时由用户重新输入。之后可以按需存入保险库，也可以只在本次连接使用。
- 密钥只迁路径，不迁内容：私钥文件仍在本机原位置，导入器只记住路径。

## 探测与预填

首次启动的探测在投影层完成，解析复用同一份解析器，不写第二个：

- 读 `~/.ssh/config`，以及本机常见的第三方终端 profile 目录（按扩展名筛选
  会话导出文件）。这两类来源的知识只在「找文件」处存在，解析不关心文件从哪来。
- 读不到就当作没探到：不报错、不伪造、也不阻断启动。第一台机器上什么都读
  不到是正常情况。
- 每条探测结果带五个字段：会话名、主机、用户、端口、来源文件。来源必须跟着
  每条走，两个来源混在一个列表里时才不会串。
- 会话名取别名；没有别名就取主机名。用户为空就保持空，不猜一个。
- 清单默认全部勾选：用户走进「探测到的会话」这一页，意图本来就是导入；要排除
  的那几条自己取消，比全选一遍省事。
- 导入按清单顺序进行，同名才改名；分组只在真的加进来东西时才建。

## 首次启动的两页引导

引导是一个三态机，不是两个窗口：

| 页 | 内容 | 出口 |
|---|---|---|
| Welcome | 一两句说明 | Next / Skip |
| Detect | 探测到的主机、勾选框、来源 | Back / Import N / Skip |
| Done | 不是页，是「走完或跳过」 | 由投影层收尾 |

- 打开总是回到第一页：这是一次性引导，记住上次停在哪只会让下次从中间开始。
- 「跳过」直接到 `Done`，与「导入」共用同一条收尾路径：写 `prefs.onboarded`
  并关闭窗口。右上角的关闭按钮等同跳过。
- 一台都没探到时，清单位置画一句说明加 `Finish`，不弹 toast——引导是一屏的
  事，用户不该去别处找解释。
- 收尾必须落盘：只改内存的话下次启动会再弹一遍，那比不做引导更烦人。
- 偏好里 `onboarded` 的出厂值是 `false`；旧配置文件缺这个键时也回落到
  `false`，不会让升级上来的用户永远看不到引导。

## 失败与降级

- 文件不可读、格式不认识、清单为空：都归为「没有可导入项」，给一句话说明，
  不抛错、不阻塞。
- 解析器对未知行是忽略而不是整份判死；只有整份都认不出会话时才返回空。
- 一条都没有导入成功时不建分组，也不在会话树里留下痕迹。
- 落库前先合并出完整列表再整表保存，中途失败不会留下「导入了一半」的会话树。
- Windows 注册表形态的会话导出在本机读不到时返回空，不伪造。
- 导入不触发连接：预填只是把会话放进树里，点哪条才连哪条，之后照常走主机
  密钥校验与认证。

## 设计约束与边界

- 不解密第三方密码，也不猜测其加密方案；密码不迁移是类型层面的设计，
  不是运行时约定。
- 不写回第三方格式：导入是单向的，外部文件只读。
- 不自动发现「所有可能的终端」：探测范围是明确的几个位置，不做全盘扫描。
- 不在后台持续同步外部配置：导入是一次动作，不是一条持续通道。
- 不替用户猜测登录名、密钥口令或分组层级；拿不到就留空。
- 引导不做成多步向导，也不承担教学：它只解决「第一次打开时树是空的」这一个
  问题。
