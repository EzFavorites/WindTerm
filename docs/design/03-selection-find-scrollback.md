# 选区、查找与回滚

本文说明「用户往回看」这条功能带的三件事怎么在纯数据层落地：选区从哪两个点表达、回滚窗口如何被请求与钳制、查找为什么不算状态，以及终端滚动条与悬停预览这块 chrome 为什么必须开第二条事实窗口。

**负责**：坐标系与只读投影关系、回滚缓冲的视口语义与贴底判据、线性 / 矩形选区模型、多选手势、复制与粘贴的编码路径、查找的匹配与导航语义、滚动条几何与悬停预览槽。

**不负责**：字符宽度与网格存储（见《终端核心与渲染》）；滚动条与预览框的颜色与尺寸令牌（见《主题与视觉基线》）；PTY 写入与传输。

## 1. 坐标系与只读投影

回看功能里同时存在三种「行号」，混用一次就会错行：

| 类型 | 含义 | 取值范围 |
|---|---|---|
| `HistoryRow` | 从历史第一条算起的绝对行号 | ≥ 0 |
| `ViewRow` | 视口行：`0` 是贴底时的屏首 | 任意整数，负数 = 回看 |
| `ByteOffset` | 原始字节流里的绝对偏移 | 无符号 |

`crates/term-core/src/coords.rs` 把三者的换算收成 `history_to_view` / `view_to_history` 两个函数，并用私有字段加 sealed trait 挡住跨类型误用。`ViewRange` 是视口行区间的类型化版本，唯一「擦除」出口是 `to_i64()`——每调用一次都在放弃一层保护，所以调用点必须一眼可见。

**投影是只读的**。`Tab` 每帧从 `ensure_view()` 得到一个 `ScreenImage`，渲染、查找、reducer 都读同一份；它不是权威状态，每帧被重写，因此不存在「谁改了它」。回看请求的去重键是 `(range, version)`：范围变了或内容版本变了才重发，否则复用上一份。

## 2. 回滚缓冲与「贴底」

`Viewport` 只有一个字段：向上滚动的行数 `scroll`。

- `scroll == 0` 即**贴底**：跟随输出、显示光标、直接读快照（`range = 0..rows`，不发范围请求）。
- `scroll > 0`：向上回看 N 行，窗口是 `-scroll .. -scroll + rows`。
- 上限不自己猜：内核在 `ScreenImage.history` 里报告可回看行数，滚动与滑块都从它钳制。
- 历史变短（清屏 / resize / 切回主屏）时 `clamp()` 把视口收回来，用户不会停在一片空白里。

贴底是「跟随」的唯一判据，而 `scroll` 是**相对贴底的位移**。新输出会把贴底位置抬高，同一个 `scroll` 下一帧就指向了别的内容——所以「把视口钉在某一行」需要绝对行锚：`top(history)` 记下「屏顶是哪一行」，每帧 `hold_top(top, history)` 钉回去。这是只读查看模式的实现基础，也让「查看历史时被新输出推走」成为可修的问题而不是玄学。

`scroll_top`（0 = 历史最顶端，`history` = 贴底）与 `scroll` 的换算只有一对纯函数，持久化、滚动条与预览共用同一套，避免出现第二套行号口径。

## 3. 选区模型

```rust
pub struct Selection { anchor: Pos, head: Pos, shape: Shape }
pub struct Pos { row: i64, col: usize }
```

`row` 是**内容行号**（负数即历史行），不是屏幕行，也不是像素——所以滚动不会让选区漂。`anchor` 是按下时定的锚点，`head` 是活动端，`shape` 只有 `Linear` 与 `Block` 两种。

**形状属于选区，不是手势参数**。写成「拖动时传一个 `rect: bool`」会让扩选丢形状：矩形扩出来会突然变线性。把 `shape` 放进去之后规则只剩一句——手势决定形状，之后所有操作（拖动、扩选、切形状）都沿用当前形状。

取列有两种读法，不能互相替代：

- `normalized()` 按 `(行, 列)` 排序给出读取顺序的起止，线性选区用它。
- `block_bounds()` 对行、列**各自**取 min / max。矩形不能复用 `normalized()`：跨行反向拖时它会给出「读取顺序的第一个点」而非「左上 / 右下」，直接拿来做区间会得到空集。

零宽矩形视为塌缩：只上下拖、没有横向位移时「有行没有列」，照常取文本会吐出几个空行；`is_collapsed()` 因此多看一个条件，投影层本来就以「非塌缩才准备复制内容」，这条规则不需要额外分支。

提取文本的规则有四条，缺一条就会产生「复制出程序没打印过的字符」：

1. 只取当前事实窗口覆盖到的行——用户看到什么就复制什么；
2. 每行去掉行尾空白；
3. 跨行时，只有**上一行不是自动换行续行**才插换行；
4. 跳过宽字符的延续格（唯一取文本口径在 core）。

选区可以有多份：`Selections { items, active, locked }` 保存集合、活动下标与锁定位。锁定只挡鼠标与键盘改选区，集合类命令照旧生效。

## 4. 手势

- **按下**定锚点、定形状（Alt = 矩形），拖动只移动 `head`。形状在拖动中途不再变，否则已画出的高亮会来回跳。
- **双击**选词：先把一行折叠成字形序列，再按「同类连写」扩张。字母 / 数字 / 下划线算词（CJK 汉字属字母），其余可见字符按同类成组（`-->`、`::` 整段可选），空白不产生选区。点在延续格上仍归前一个字形。
- **三击**选行：从行首到最后一个非空白字形；空行返回空。
- **Shift+点击**扩选：保留锚点与形状，只把头部挪过去；没有现成选区时退化成重新起锚。
- **点击分派顺序**必须从具体到宽泛（三击 → 双击 → 单击），否则选词会立刻被「单击清空」吃掉。
- **拖到边缘自动滚**：按越界距离给 1–5 行 / 帧，并且只在视口真的变化时请求重绘——指针不动时进程不会自发重绘，不请求就卡在第一行，无条件请求则等于永远空转。

选区的几何入口只有一处（`pointer_selection`），Bin 视图在同一处直接分叉——不抽出来就要在八个分支上各贴一次判断，漏一处就是「切到 Bin 还能拖出一片网格坐标」。

## 5. 复制与粘贴

三个动作都只声明意图，不携带内容：`Effect::CopySelection` / `Effect::Paste` / `Effect::PasteSelection`。reducer 是纯函数，拿不到剪贴板，也不该拿到。

**选中即复制**由三条同时成立才触发：开关打开、选区非空、指针没有按着；再加一条去重——同一段选区只写一次。指针按着时不写，于是拖动中间态不会一路覆盖剪贴板；选区被清空时把「上次写过什么」一并清掉，否则「重新选同一段」不会再生效。

**粘贴编码属于语义平面**，不在投影层：

| 情况 | 处理 | 不处理的后果 |
|---|---|---|
| `\n` 与 `\r\n` | 归一成单个 `\r`（`\r` 后紧跟 `\n` 时只保留 `\r`） | 全屏程序在 raw 模式下把裸 `\n` 当 `^J`，多行粘贴挤成一行 |
| 控制字符（含 `ESC`） | 一律丢弃，只留 TAB | 剪贴板不可信：`ESC[201~` 能提前闭合括号粘贴，`ESC]0;…BEL` 能改窗口标题 |
| DECSET 2004 | 整段包进 `ESC[200~ … ESC[201~` | shell 把粘贴当逐字符键入，触发补全与自动缩进 |

`paste_bytes_for(text, bracketed)` 与方向键编码同一形状：**只要一个模式位，不要 `Terminal` 实例**。投影层从快照里取模式位，一行调用完事。

粘贴确认由两个**独立开关**决定（主屏 / 备用屏）：全屏程序里粘贴与提示符下粘贴的风险不同，一个开关替另一个做决定是不诚实的粒度。判据函数的入参里没有文本，也就是说**没有「超过 N 行才问」的阈值**——要不要打断由用户按场景决定，多行的风险交给预览里的总行数如实呈现。确认弹窗的预览有上限（20 行 / 800 字），但**只影响显示**——写进 PTY 的永远是全文，把「看到多少」与「贴多少」分开。

所有入口（快捷键、菜单、右键、中键、确认弹窗的「是」）最后都汇到一个落地方法：编码 → 写 PTY → 喂输入行 → 记命令行历史。两条路各写一遍编码是这类改动最容易埋的雷，症状要到远端粘贴出怪东西时才显形。

## 6. 查找

查找状态只有四件事：开没开、搜什么、是否区分大小写、是否全词，外加一个「第几个」的选择。**匹配集合不是状态**：

```rust
pub fn matches(state: &FindState, window: &ScreenImage) -> Vec<Match>
pub fn current_index(state: &FindState, total: usize) -> Option<usize>
```

`matches` 是 `(查询, 大小写, 全词, 窗口)` 的纯函数值。把计数缓存进状态必然过期：滚动不是 `Action`，换窗口不会触发 `reduce`，于是「3 / 7」会停在旧数字上。补法不是「滚动时也写一次计数」（那就是第二个写入者），而是把计数删出状态——换窗口，计数自动就是新窗口的。`current_index` 对总数取模，窗口一变也不会指到集合外。

扫描单位是**字形**，不是格：先折叠成（列号, 字符）序列，匹配在字符序列上做，命中后用列号还原成「屏上从第几格到第几格」——高亮框与文本因此同源。行尾填充不参与匹配。全词要求命中两端都贴词边界，词字符按「字母 / 数字 / 下划线」判定。

导航语义是**在窗口内的匹配集合上环回**，不跳到窗口外：当前匹配永远在屏幕上，「N / M」永远指「你正在看的这一段里第 N 处」，不需要「跳转后视口怎么摆」这套额外规则。代价是窗口外还有匹配时用户得自己滚过去——这是有意的设计选择，不是待修的缺陷。

两处明确的边界：大小写折叠统一由 `regex::RegexBuilder::case_insensitive` 决定——字面查询先 `regex::escape` 再走同一引擎，因此与正则模式逐项一致，并非「只折叠 ASCII、非 ASCII 精确比较」；默认查找是子串匹配，打开 `.*` 后改走 `term-core::find` 的 regex 引擎。两种模式共用同一套字形→列坐标映射，所以高亮框与文本同源；整词按钮在正则模式下语义不变（仍按「字母/数字/下划线」判定命中两端）。正则语法错时查找栏边框与 `.*` 图标转红并给出编译错误，不会把「0 / N」静默当成搜不到。

## 7. 终端滚动条

几何全部下沉到 `crates/term-app/src/scrollbar.rs`，只做数值换算，一个像素常量都没有：

```rust
pub fn thumb_of(track, rows, history, scroll_top) -> Thumb
pub fn scroll_top_of(track, rows, history, thumb_top) -> u64
pub fn preview_range(history, ratio, preview_rows) -> ViewRange
pub fn preview_box_top(content_top, content_h, box_h, hover_y) -> f64
```

- 滑块高 ∝ `rows / (history + rows)`，并有下限（与绘制库的滑块最小长度对齐，取 12 逻辑点），否则长会话时滑块会缩成看不见的一条；
- 反解用「有效轨道高 = 轨道高 − 滑块高」，避免上下端因滑块被钳制而跳变；两函数互为逆，允许 ±1 行取整误差；
- `history == 0`：滑块占满轨道、不可拖，整条滚动条不画不交互；
- 轨道宽固定 15 逻辑点，贴内容区右缘，**不画轨道底色**，只画滑块；常态中灰，悬停提亮（提亮是指向指示色，只在真实悬停时出现）；
- 拖拽必须先抓住滑块（按下时记录指针与滑块上缘的偏移），点在滑块之外按「跳到该位置」处理——滚动条只加这两种手势，翻页仍由滚轮与既有视口路径承担；
- 滚轮每格滚多少行来自会话配置（默认 1 行）；程序开启鼠标上报时滚轮交给程序，Shift 是「本地回看」的豁免键，两者二选一，避免一次滚轮既滚程序又滚回看；
- 指针落在轨道上时，上层控件的悬停归属已被抢走，滚轮必须在滚动条模块里显式接住，否则会出现「滚不动」的死角；
- 滚动条**浮动叠加**，不改内容区宽度、不改列数、不触发 PTY resize——用右缘 15 点换一次全窗重排不值得。代价是必须补一条右边界守卫：鼠标越过网格右缘时列号退到哨兵，否则点击滚动条会顺手产生「最后一列」的选区。

## 8. 悬停预览：第二条事实窗口

预览不是提示框，而是一整块取景框：占满内容区宽度、高为内容区高度的 0.564（由 `pane_preview::PREVIEW_FRACTION = 576.0 / 1022.0` 这个浮点常量表达，不是整数除法 `576/1022`）、框内是历史快照、框外仍是真实视口。框的中心跟随指针 y，整体钳进内容区。

难点不在画，而在**数据**。既有通道是「一条请求 + 一个槽 + 一份去重键」：

```
RequestRange → 监管者 → Event::Screen → handle.screen（最后一个获胜）
             → Tab.screen → crop_view(desired) → 失败即 blank
```

内核本来就支持一轮吐多份窗口（`requested` 是列表，切窗口是纯函数，范围请求不递增版本）。瓶颈在句柄只有一个槽。把预览请求塞进同一条通道，同一 tick 内两份窗口只剩最后一份，真实视口裁不到自己那一份就退化成空白帧——用户看到闪白屏。这是结构性冲突，不是偶发竞态。

另一个诱人方案是「从已抓到的 `tab.screen` 里裁一段」，零接口改动。但最常见状态是贴底，而贴底根本不发范围请求，`tab.screen` 是旧窗口或空——这个方案恰好在最常用的场景里失效。

因此选择**第二槽**：新增 `Command::RequestPreview` / `Event::PreviewScreen` 两个变体，句柄多一个 `preview_screen` 槽，`Tab` 多一对并列字段（`preview_screen` / `preview_last_request`），旧变体签名一字不改。预览图用第 8 段 chrome 绘制，直接调已经收 `&ScreenImage` 的 `paint_rows`，不参数化正文与叠层函数，也不碰 `tab.view`。

**不变式**（也是这块功能最重要的验收判据）：预览期间，视口位置、`tab.view`、真实窗口的去重键、滑块矩形**四者都不变**；只有预览槽与预览去重键在变。

代价明确认领：`Session` 接口变宽两个方法（给了默认空实现）；句柄与循环各多一个槽 / 列表；每帧最多两份窗口值传递。可逆性很高——删掉两个变体与两个槽即回到单窗口时代，无数据格式、无持久化、无协议版本影响。

不选「通用多窗口表」的理由是需求量：当前只有「真实视口」与「预览」两个消费者，通用化要改既有通道签名、所有会话实现、脚本与桥接替身——那是拿全局契约换一个还没出现的需求。真出现第三个消费者（例如跨会话结果窗、缩略图）时再收敛成表，是一次局部重构。

绘制上还有两处细节值得记住：预览框底色必须**不透明**（底下的实时视口会透出来，形成重影），且框底要取主题背景而不是固定色；框内左侧边栏复用真实终端同一套边栏绘制，行号右边界、时间戳、符号列逐列同源，配置一变两边一起变，不会各自漂移。

已知不做：预览内选区 / 查找 / 超链接 / 滚轮。一旦可交互，`reduce`、查找、选区都得认识第二份窗口，改动面从「画一层」膨胀成「双视口全功能」。Bin 视图的滚动条同样不做——它的坐标来自字节环而不是视口，半套映射的风险高于收益。

## 9. 与 UI 的只读关系

- 选区、查找、视口都是纯值；绘制只读它们，不改。
- 本功能带内唯一由手势写入的是 `Viewport`（滚轮 / 拖滑块 / 点击轨道）与选区集合；预览只写 `preview_*` 两个字段。
- 查找栏与状态栏的「N of M」读同一个 `matches()`，不各自重算、不缓存。
- 滚动条不改内容区几何，因此不影响网格列数与 PTY 尺寸；没有历史时整条不画不交互，贴底画面一个像素都不变。

## 10. 边界

- 跨窗口跳转（搜到屏外匹配并滚过去）未实现，且被明确定义为「不属于当前语义」。
- `Find All` 与结果列表面板**已实现**：Find 栏的 `Find All` 按钮展开一个 `egui::Area`，数据由 `app::find::result_rows` 从同一份 `matches()` 产出，按标签身份发布，分屏时不会互相覆盖；替换面板仍未实现。正则查找已实现（`.*` 按钮 + `validate_regex` 实时校验 + 着色反馈）。
- 矩形选区不补空格对齐：每行仍按去尾部空白处理，避免把不可见字符塞进剪贴板。
- 双击后继续拖动不按词扩展；Alt+双击仍是选词，没有「按列选词」。
- 水平滚动条未实现：内核不做 reflow，变窄时数据已经丢失，加一条水平条只会暴露这个事实。
- 预览框内的内容不可交互，也不支持滚轮。
