# 标签、分屏与布局持久化

## 负责什么 / 不负责什么

本文描述**窗口里「会话如何被看见」**这一层的模型与边界：会话与标签的关系、每个窗格一组
标签的数据结构、窗格身份与二分切分布局树、六条分屏 / 移动命令的语义、布局文件的形状与
恢复边界，以及锁屏时布局处于什么状态。

不负责：会话的建立、IO 与生命周期（控制面与 IO 层）；终端的网格渲染、选区与查找（终端区）；
标签条、工具栏、状态栏怎么画（见窗口壳一篇）；崩溃时的留存策略（见崩溃防护一篇）。

## 会话为单元，标签为投影

- **会话是唯一真相**。控制面持有一份会话登记表，按名字与运行实例身份（`SessionId`）寻址；
  窗口只持有「有序的会话身份列表 + 当前活动身份 + 一棵引用身份的布局树」，不持有会话本身。
- **标签是投影**。`Tab.identity: SessionId`，其余字段是每帧从会话池取回的只读快照；活动身份、
  顺序、布局引用都已身份化到窗口态，`Tab` 不再重复持有这些权威字段。
- **一处必要的例外**：断连或尚未连接的标签保留打开时的配置快照。它不在会话池里，名字没有
  第二个来源；存活态一律以池子为准，并由每帧轮询校正。
- **视图态按 `(窗口, SessionId)` 键控**，留在投影层：滚动位置、选区、输入行都不下沉到控制面，
  也不写进持久字段。
- **直接后果**：同一会话不会同时出现在两个窗格里，因此「各自独立滚动」是默认事实，不需要
  共享视口的机制。**代价**：布局按名字恢复，改名即断引用——旧布局里的旧名字会在恢复时
  被跳过。

## 每窗格一组标签的数据模型

| 结构 | 职责 |
|---|---|
| `tabs: Vec<Tab>` | 会话真身与生命周期（新建即 push，彻底结束即移除并收口） |
| `pane_groups: HashMap<PaneId, PaneGroup>` | 空间分区：哪个窗格挂着哪些会话、当前显示哪一条 |
| `layout: Layout` | 几何：谁在左 / 右、上下、比例多少 |
| `open_order: Vec<SessionId>` | 由 `tabs` 派生的只读顺序，不做第二套算法 |
| `active: Option<SessionId>` | 窗口唯一焦点 |

- `PaneGroup { order: Vec<SessionId>, active: SessionId }`：`order` 是该窗格的标签序列，
  `active` 是它当下显示的那一条。**窗格内切标签只改 `active`，不动布局树。**
- **不变量**：一个 `SessionId` 至多属于一个 group（同组内不重复，跨组也不重复）；
  `pane_groups` 的并集与 `tabs` 的集合一致；`active` 必属某个 group。
- **活动窗格不单独存字段**：由 `pane_of_session(active)` 反查。因为每条会话只在一处，
  反查结果唯一，少一个可以与 `active` 不一致的缓存。
- **单窗格的对齐约定**：`set_active_slot` 在树只有一片叶子时，把该窗格的分组压成「只有当前
  会话」。否则从单窗格分屏时会锚到错误的会话——分屏锚点是「当前会话所在的窗格」。
- **组名**：`pane_group_name(PaneId) -> String` 是纯函数，按窗格恒在身份派生，`1 → A`、
  `26 → Z`、`27 → AA`（进位式列名）。名字跟着身份走，不随屏幕位置重排，也不回收；因为
  身份不落盘，重启后按树重建顺序重新领名。
- **关会话**：`remove_from_group` 是组关闭语义的唯一真源。组里还有别的会话 → 只换该窗格
  显示的会话（落到被关那条的左邻居，左边没有则取第一条）；组已空 → 剪掉这片叶子并摘掉
  分组；最后一格 → 不剪，唯一窗格的分组改指窗口里的第一条活会话（窗口始终留一块终端）。
- **窗格内增删**：`＋` 起一条新会话、追加进本组并设为该组活动，树一个字节不动；`×` 只做
  归属校验，真正的清理仍走统一的关标签路径（确认弹窗、Reopen Closed、焦点历史都只一份）。
- **`≡` 的范围**：只列当前窗格所属分组的会话，不列全窗。

## 窗格身份与二分切分布局树

- `PaneId(u64)` 是独立 newtype，与 `SessionId` 刻意不混用：把窗格身份当会话身份传进绘制
  入口，会在编译期被挡下。它由模块级原子计数器铸造，进程内单调递增、不回收、不落盘。
- 树只有两种节点：

  ```text
  Leaf(PaneId)
  Split { horizontal: bool, ratio: u16, first: Box<Layout>, second: Box<Layout> }
  ```

- `ratio` 是千分比：默认 `500`，夹在 `100..=900` 之间，任何一格都不会被拖到消失。用整数
  而非浮点，是因为布局要参与相等比较与落盘比对。
- 纯数据操作：`single` / `is_single` / `leaf_count` / `leaf_panes` / `tabs(groups)` /
  `split` / `close_leaf` / `merge_into_next` / `repoint_single_if_dead` / `ratio_at` /
  `set_ratio_at`；拖拽交换在单独的 `swap_leaves`。
- `split` 的目标窗格不在树里时（例如刚被关过）退化为「整棵树 + 新叶子」并排，不丢已有窗格。
- **渲染路径分叉**：`layout.is_single()` 为真时走原来的单终端绘制，全窗的标签条 / 工具行 /
  Sysmon 细带照旧由窗口壳声明；只有真的分了屏才递归切分：每层用路径与 `salt` 派生稳定的
  `egui` id，向两个子 `Ui` 递归，中间留 2 点间隙；分隔条命中区 8 点宽，拖动只改比例，比例
  确实变化时才置「待落盘」标志。
- 分屏时每片叶子自己画一套 chrome（标签条 + 工具行 + 终端 + Sysmon），全窗那三条不再画，
  否则会出现「全窗一条 + 每格一条」的重复。矮窗格按比例压缩三段 chrome，终端至少留一行。

## 六条分屏 / 移动命令

| 命令 | 效果 | 边界 |
|---|---|---|
| `Window.SplitViewHorizontally` / `Vertically` | 新起一条本地 shell 会话，进新窗格 | 新 `PaneId` + 只含新会话的分组；原窗格不变；结构变化即落盘 |
| `Window.SplitGroupHorizontally` / `Vertically` | 复制当前会话的**配置**再开一条，名字追加「 · 2」后缀 | 新 `SessionId`、新 PTY、新快照、空回滚；不是共享同一条会话 |
| `Window.CloseActiveGroup` | 收起当前窗格，兄弟顶上来 | 单叶子时无动作；被收起的会话集合仍留在窗口的会话清单里 |
| `Window.MoveGroupToGroup` | 把当前窗格并进遍历序里的下一格，自己收起 | 移动的是「窗格连同整组会话」，不是把一条会话塞进对方的组 |

- **两种动作不要混**：分屏与 `＋` 都是「开新会话」；把已有会话换个位置是拖拽，不是分屏。
- **复制配置的例外路径**：内置 SSH 会话的窗格要等握手完成才存在，所以「锚点窗格 + 方向」
  随连接请求一起带去落地，避免先出现一个内容为「(disconnected)」的窗格。
- **拖拽的语义**：拖一条标签落到另一格 = 两片窗格交换位置（整组随之移动），树形与身份集合
  都不变；拖回自己那格是空操作；松手没落在任何格，拖拽态在本帧末作废。
- **窗格只能调比例，不能拖动重排**：位置由树决定，比例由 sash 决定，两件事分开。
- **被收起窗格的可见性**：分屏态没有全窗标签条，因此刚被收起的分组在分屏期间不显示在任何
  格内；回到单窗格后，标签条按窗口的会话清单逐条列出，切到该会话时唯一窗格改用它。

## 布局持久化

布局文件 `layout.json` 与配置文件同目录，原子写：写到一半断电，丢的是这一次改动，而不是
整份布局。

| 字段 | 含义 |
|---|---|
| `schema_version` | 文件格式版本，只写在文件里 |
| `tabs[]` | 每条会话的引用：`name`，以及可选的 `cwd` / `scroll_top` / `history_len` |
| `active` | 活动会话在 `tabs` 里的下标 |
| `tree` | 二分树：`Leaf(下标)` 或 `Split{ horizontal, ratio, first, second }` |
| `dock[]` | 面板停靠 / 浮动位置：`panel` / `zone` / `order` / `rect` |
| `last_saved_at` | 最近一次运行期写盘的 Unix 秒（元信息） |
| `last_exit_kind` | 上次退出形态：`clean` / `crash`（元信息，缺省表示没走正常收口） |

- **存引用，不存状态**：会话名 + 切分树。PTY 句柄、屏幕快照、选区、回滚内容一个字节都不落盘；
  `scroll_top` 只是一个偏移数字，用来把视口放回原处。
- **叶子存下标而不是身份**：`PaneId` 每次运行重铸，跨运行没有意义；树按「第几条会话」落盘，
  恢复时按同一顺序重铸窗格身份，第一片叶子复用构造期的窗格，组名因此从 `A` 起。
- **触发**：结构变化（分屏 / 关窗格 / 合并 / 拖动比例 / 组内增删）只置「待落盘」标志，帧末
  统一派发一次，避免渲染期重入；另有 30 秒周期留存兜住「安静运行、只有输出」的时间段。
- **退出路径只改元信息**：那时标签已全部收口，拿当前内存布局去写盘等于把要恢复的内容抹掉。
- **启动策略决定写什么**：只有「上次的会话」这一档把 `tabs` / `tree` / `active` 写回；另两档
  只更新 `dock`，否则临时切到「不恢复会话」再切回来，上一次的清单会被写成一条默认 shell。
- **读入即收敛**：越界的活动下标归零；越界的叶下标归零；比例夹回区间；停靠项按面板去重，
  小于 80×60 的浮动窗直接丢弃（屏幕上抓不到的点等于找不回）；`tabs` 为空时退回一条本地 shell。

## 恢复边界与版本字段

- **版本只写在文件里**，不进布局结构体：它是文件的属性。缺这个键读作 `0`（最早那一版的形状）。
- **比自己新的格式不读**：按旧规则解释新字段，会把标签顺序与分屏形状静默改成别的东西——
  用户以为记住了、其实记错了，这比「没恢复」更难发现。宁可退回一条本地 shell。
- 旧文件缺 `ratio` 时读作默认 500（分屏对半）；缺 `dock` 时视为空，保持默认布局。
- **恢复是按名字的查表**：在会话库里找同名配置，找不到就跳过、不凭空造一条；保持顺序、
  不去重（同名开过两条，恢复出来就该是两条）。
- **按「指定会话」启动时丢弃旧树**：旧树的下标指向上一批标签，套到今天的列表会把窗格挂到
  错的主机上；活动下标也从第一条开始。
- **断开会话挂起**：恢复出来仍是断开态的会话登记进待激活集合，被激活时在原位连一次。先摘牌
  再连——连接失败不重试，否则来回切标签会无限弹连接框。
- **恢复范围到此为止**：叶子只记一条会话下标，因此窗格内多标签的集合与组内活动态不跨重启；
  重启后每格只摆回一片会话。运行中的进程、回滚内容、选区同样不恢复。

## 锁屏与布局

- 锁屏是视图状态里的两个布尔（`locked` / `error`），**不落盘**：重新启动即处于解锁态。
- `locked` 为真时，绘制入口只画遮罩并整帧早退：布局树、标签条、状态栏都不画；挂在帧内的
  每帧钩子（恢复连接轮询、周期留存、结构落盘）当帧也不执行。
- 布局在内存里原样保留，解锁后回到同一棵树、同一组会话，不重建、不重排；锁屏期间不写盘，
  也不改动布局文件。
- 遮罩的解锁凭据复用保险库主密码，没有第二套口令；从未创建过保险库时允许取消——否则会把
  用户锁在一个永远解不开的遮罩后面。
- 桥接侧另有一道独立的门：操作系统会话处于锁屏状态时，每个调用都返回「已锁定」，包括新建
  会话。这道门管的是外部调用，与窗口内的遮罩互相独立。

## 设计约束

1. **会话只在一处**：分组、拖拽、分屏都不得制造跨组重复；`pane_groups` 的并集必须等于
   `tabs` 的集合。
2. **叶子身份唯一**：剪叶只剪一片；重复身份会让后续 split / close 只认第一个匹配，深嵌套后
   第二片窗格就失灵。
3. **窗格身份不落盘**：任何持久字段都不得出现 `PaneId`，恢复一律由树形重建。
4. **布局不是领域状态**：动作层只声明意图（分屏 / 关闭 / 合并 / 交换），树由投影层落地。
5. **视口不下沉**：滚动位置、选区、输入行按会话键控，留在投影层。
6. **结构变化必须落盘**：置标志而不是在绘制中直接写盘；写盘失败不崩，也不装作成功。
7. **恢复要可解释**：读不懂的文件退回单条本地 shell，而不是猜着读一半。
8. **单窗格路径不许变形**：分屏是加一层，不是改写单终端路径。
9. **比例有下限**：任何一格都不得被拖到消失，比例夹在千分比的固定区间内。
