# 文件传输

本文说明 WindTerm 里「文件怎么从一端到另一端」这条链：文件面板怎样绑定到一条会话、传输请求怎样排进队列与后台线程、中途停下时目标文件该留还是该删、断点续传凭什么判定起点，以及当对端没有 SFTP 时 X/Y/ZMODEM 这条纯协议通路怎样被驱动。

**负责**：SFTP 会话的生命周期与请求/事件形状、文件面板的数据源与路径状态、传输队列的状态机与重试策略、取消三态与目标文件处置、续传偏移的判定、落盘权限位与时间戳的保留、远端文件「下载—外部打开」的链路、X/Y/ZMODEM 协议层与驱动编排、传输速率与基准脚本的测量口径。

**不负责**：目录双向同步的判定表与审阅流程（见 `crates/term-xfer/src/sync.rs` 与 `filer_sync`）；SSH 认证与主机密钥策略本身（见 `docs/architecture.md` 与《凭据与安全设计》）；脚本侧 `sftp_*` 动词的授权信封（见《脚本与自动化》）；文件面板的像素布局与截图基线（见《主题与视觉基线》）。

## 1. 一条会话，两种数据源

文件面板不持有自己的连接配置，它跟着**活动标签的会话**走。三种情形归成两条源：

| 活动会话 | 面板源 | 路径根 |
|---|---|---|
| 本地 shell、系统 `ssh`（标签上没有内建凭据） | 本地目录 | `local_dir::home()` |
| 内建 SSH（标签带 `tab.auth`） | SFTP | `Event::Ready` 报回的 `home` |

SFTP 这一侧**新建一条 SSH 连接**再开 `sftp` 子系统，而不是复用终端那条 TCP 连接。它复用同一份 `SessionConfig` 与同一份凭据，所以用户不会遇到二次认证；但传输与终端是两条独立的会话，任一侧断开互不牵连。

主机密钥沿用 `HostKeyPolicy::Tofu`：终端那条连接已经裁决过一次（能连上说明账本里有它），文件面板再问一遍指纹只会让用户困惑「为什么又问一次」。连接参数拼不出来时（例如手写的 `ProxyJump` 链有误），面板不 panic、也不静默，而是把原因写进面板自己的 `error` 槽。面板关闭、切换会话、关闭标签三处都会显式收掉句柄：理由不是省内存，而是服务端要看到一次挂断——反复开关面板若只靠丢句柄，服务端会累积半死会话，直到它自己的超时或 `MaxSessions` 顶满。

## 2. 顶部目标与浏览位置

面板顶部只有一条路径栏：一个可编辑输入框，加清除、上级、刷新、排序四颗按键。**这条栏就是「当前目标」的唯一控件**——本地源下它解释成本地目录，远端源下解释成远端路径，两种源不各设一套导航。

源本身不是用户手挑的开关，而由活动会话决定。这条取舍避免了「面板显示 SFTP，标签却是本地 shell」这种自相矛盾的状态。

浏览位置分两层：

- **跨帧**：`local_path`、`path`、`path_input` 都是面板字段，切换目录、翻页、排序都不丢；隐藏文件开关从 `prefs` 重新取（`Filer::from_prefs`），否则面板重开时勾选会静默弹回出厂值。
- **不跨面板/不跨会话/不跨重启**：面板重建时回到 `Ready.home` 或本地家目录。远端路径是「那条连接上的事实」，不是用户偏好；把上次的 `/var/log/xxx` 存下来，下次连到另一台机器只会得到一个不存在的目录。

排序（名称 / 日期 / 大小）是面板态，不进偏好文件。表格只认排序后的整张表下标，行序每帧由同一份数据确定性算出，所以「双击第 N 行」在同一帧内稳定。

## 3. 后台会话线程与事件

一条 `SftpHandle` 背后是一条专用线程加一个单线程异步运行时，对外只剩「发请求 / 收事件」。请求与事件都是枚举，UI 每帧非阻塞地取。

为什么不给每个请求起一条线程：SFTP 是**一条会话上的多路请求**，`SftpSession` 自带请求 id 与并发上限；每次列目录重连一遍要付认证与 subsystem 的钱，而浏览目录的本质就是连着点几下。

传输请求在同一个循环里**串行**执行：一次传输期间，后面排着的请求等它传完。这是有意的，同时传多个文件会把一条通道的带宽与并发窗口互相挤占，进度也就失去意义。真要并行，该开第二条会话，而不是往同一条里塞队列。

事件形状：

| 事件 | 含义 | 关键字段 |
|---|---|---|
| `Ready` | 握手完成 | `home`：服务端认定的家目录 |
| `Listed` | 一层目录的完整内容 | `path` / `entries` |
| `Progress` | 传输进度，已节流 | `path`（远端）/ `transferred` / `total` |
| `Done` | 一次操作收尾 | `path` / `bytes`（续传时是完整大小） |
| `Cancelled` | 用户取消 | `path` / `kept`（分片是否留在原地） |
| `Failed` | 真失败 | `path` / `message`（服务端原话优先） |
| `Scanned` | 一棵目录树的清单 | `entries`（带 `mtime`） |
| `Closed` | 会话结束，之后不会再有事件 | `message` |

`Done` 同时被写操作复用（建目录 / 改名 / 删除 / 改权限），此时 `bytes` 恒为 `0`——做了什么由发起方自己知道，它发的请求。传输进度的节流口径是「涨了 1 MB 或过了 200 ms，先到先报」，所以拿到就能直接重绘，不必在绘制层再做一次合并。

`close()` 是幂等的三步：先取消在跑的传输（否则后台要等整个文件传完才读得到通道已断）、丢掉请求通道、最多等 2 秒让线程收敛。超时后线程被**放弃**而不是被杀——Rust 没有安全的线程终止；它会在 socket 报错时自己结束。正常路径下线程还会发一次 `SSH_MSG_DISCONNECT`，这是「会话不泄漏」的关键一步。

## 4. 传输队列

队列是纯模型层（`term_xfer::Queue`）：零 IO、零线程、零时钟，`now` 由调用方注入。它回答五个问题——先跑哪个、一次跑几个、失败重试几次、等多久、总进度算到哪。

状态迁移如下（终态不再回 `Pending`）：

```
Pending ──start_next──► Running{transferred} ──finish(Ok)──► Done
   │                        │
   │                        ├── finish(Err)，还有额度 ──► Failed{retry_at: Some(t)}
   │                        └── finish(Err)，额度用完 ──► Failed{retry_at: None}
   ├── cancel ─────────────────────────────────────────► Cancelled
   └── finish(Err(Cancelled)) ─────────────────────────► Cancelled
```

策略常量的取值与理由：

- **并行上限 1**。后台是一条线程串行消费请求，填 2 只会让第二项显示「传输中」而实际堵在通道里——那是假进度。
- **自动重试 3 次，退避 2 / 4 / 8 秒**。SFTP 的失败多数是权限、磁盘满、路径不存在，重试不会变好；但瞬时断流与服务端忙属于真会自愈的一类。8 秒后仍无结果，把「重试」交给用户按，比界面自己一直转更诚实。等待退避的项不占并行位：它没有在传，占着名额只会让并行度凭空跌掉；但它在重复判定里仍算「未结束」，因为同一文件早晚要再传。
- **重复判定 = 同名 + 同方向 + 尚未结束**（`Done` / `Cancelled` / 终态 `Failed` 不参与）；总进度分母只计未取消项的大小之和，取消项既不在分子也不在分母。

界面壳只做两件事：把用户选中的条目丢进队列，以及按固定节拍把一批事件报进来。它与模型之间需要一张「远端路径 → 任务 id」的表——事件里的 `path` 一律是**远端**路径（下载时是源，上传时是目标），用本地路径做键会让上传的进度永远对不上。这张表还必须记住发起时的两端路径：排队期间用户可以在面板里换目录，等轮到它跑时再按「当前目录」拼路径就会传到别处去。

目录树在队列里只占**一行**：树根另存一份映射，文件事件按前缀归到这一行，文件级 `Done` 只记账不结算，只有树根那条收尾事件才 `finish`。树的总字节要等树根 `Done` 才知道，之前用一个哨兵值放行累计进度，真实分母绝不把哨兵透给界面。

## 5. 取消三态：停下的方式决定目标文件的命运

取消不是一个布尔参数。处置只需要两个判据：**怎么停的**，以及**传前目标是否存在**——差别不在「停不停」，而在「停完要不要删文件」：

| 触发 | 目标文件 | 用户意图 |
|---|---|---|
| 传完 | 留着 | 这就是结果 |
| 网络中断 / IO 错误 | 保留分片，可续传 | 「没传完」 |
| 用户主动取消，目标原先不存在 | 删掉分片 | 「不要了」 |
| 用户主动取消，目标原先就存在 | 一个字节都不动 | 那是用户既有数据 |

判据是**传输开始前目标是否已存在**，不是传了多少。最后一行最容易写错：把「用户传了一半的文件」当成「我们造的垃圾」删掉，等于替用户做了删除决定。空文件也算「原有的」——长度为 0 的既有文件同样是用户的数据。

这张表是纯函数 `disposition(stop, target_preexisted)`，单测不需要连服务端。旗子是 `CancelToken`，克隆共享同一个原子布尔：句柄持一份响应按钮，传输循环持一份每 64 KiB 问一次。内存序统一 `SeqCst`——这里没有性能敏感的热路径，换来的是「读到的值一定是某次写入的值」这种可以直说的性质。

`reset()` 只由后台线程在**每次传输开始前**调用。放在「收请求之前」会吞掉用户在「点了取消、下一条还没开始」之间点的那一下；放在「传输开始之后」则会让上一条的取消顺延到下一条。

**取消不是失败**，这条要在三处同时成立：事件用 `Cancelled { kept }` 而不是 `Failed`（`kept` 说清目标位置现在是什么）；队列收到 `FailReason::Cancelled` 直接落 `Cancelled`，不进退避重试——否则「取消」会在几秒后自己复活；状态行用中性色，不抽错误条，不计入错误率。取消是用户按的按钮，不是设备坏了。

取消的删除动作失败**不上报**：此刻真正的结论是「用户取消了」，再叠一条「删除失败」只会盖掉原因，让界面同时弹两个错。留下的半成品下次照样能被续传接上。

## 6. 续传与断点

续传的判据只有一条：**已有前缀必须不长于完整文件**。

```
!resume                    → 0（覆盖）
existing > total           → 明确失败
其余                        → existing
```

两边对不上时明确失败，而不是二选一：静默覆盖会把别人辛苦传了一半的大文件抹掉，静默从头开始会让「续传」变成一句假话。默认（不带续传）才是覆盖。下载的覆盖路径带 `TRUNCATE`，续传路径只开 `WRITE` 以保住已有前缀；上传侧同理，续传时本地文件按偏移 `seek` 到起点。分块固定 64 KiB：再大要被 `max_write_packet_len` 切开，再小则往返次数白涨。这个块长同时是取消的最坏延迟——每块之前问一次旗子。

目录同步刻意**一律不续传**。续传是「接着半截往下写」，那半截若不是同一份内容，续出来的文件既不是旧的也不是新的。同步要的是「让两侧一致」，宁可重传一个整文件。

进度上报只在两个条件之一满足时发生（涨 1 MB 或过 200 ms）。`Progress` 的对端没报总大小时 `total == 0`，此时界面不画比例、也不画剩余时间——除不出东西，写一个满值反倒像「已经传完」。

## 7. 落盘、权限位与原子性

上传的权限处理按「新建」与「覆盖」分岔：

- **新建**：`open` 时带 `DEFAULT_FILE_MODE | S_IFREG`，收尾再用一次 `setstat` 把权限与 mtime 一起写死。多这一步是因为 `open` 的 mode 会被服务端 umask 再削一遍（umask 022 时 0644 保得住，077 时会变成 0600），只有 `setstat` 才真的「换台服务端也不变」。
- **覆盖**：`mode` 传 `None`，表示**不碰权限**而不是设成 0。`setstat` 只更新带标志的字段，所以对端原本的 0600 会保住。把别人的私钥文件放宽成 0644 是数据事故，不是保真度。

`chmod` 是另一条路：`SSH_FXP_SETSTAT` 收到的是**整个 mode**，里面既有类型位（`S_IFREG` / `S_IFDIR` / 符号链接）也有权限位。只写 `0o755` 会把类型位清零，有的服务端就此把文件当成未知类型。所以 `merge_permissions` 保留已知类型位、只替换权限位；请求值必须落在 `0o0000`–`0o7777`，十进制 755 会被明确拒绝，而不是猜。路径为空串也先拒绝：空路径在多数服务端会被解释成当前目录，`rmdir("")` 于是变成一次对家目录的删除请求。

时间戳只写 mtime，不碰 atime。服务端没报 mtime 时什么都不做——写 0 等于把文件设成 1970，比不设更糟。`setstat` 被拒（只读挂载、权限不足）静默返回：文件已经传好，时间戳是锦上添花，不该把一次成功的传输判成失败。

**原子写的适用范围要说清**。配置、布局、偏好这类小文件走「同目录唯一临时名 + `rename`」，临时名带 pid、纳秒与进程内序号，因为多个窗口进程可能共享同一份 profile 目录；`rename` 失败会把临时文件删掉，目录里不留半截账本。SFTP 传输**不走**这条路：它需要落盘后的真实路径与续传前缀，因此直接写目标，完成的界是「`flush` 与 `close` 都成功之后才发 `Done`」。由此产生一条可观察的性质——传输进行中，读端可能看到不完整的内容；把「传完了」当成原子可见是错误的用法。

## 8. 远端文件的「下载—外部打开」

双击或右键「预览」一个远端文件，链路是三步，**没有内建编辑器**：

1. **造落点**：`temp_preview_path(name)` 在临时目录下建一个本次运行独有的子目录，再放远端 basename。每个文件一个子目录，是因为不同远端目录下同名 basename 很常见，共用一个平铺目录会让第二次下载覆盖第一次的副本——而预览窗可能还开着前一个。远端文件名里的 `/`、`\`、`..` 在本地会被解释成别的路径，所以只取最后一段，`.` 与 `..` 换成兜底名。
2. **下载**：复用同一条 SFTP 请求通道，`resume = false`（预览要的是「现在这一份」），`preserve = false`（临时副本不需要源时间戳）。
3. **交给系统**：`open_path` 先做存在性校验，不存在就**不 spawn** 任何进程——否则桌面会弹一个「找不到文件」的系统对话框，而我们这边拿到了 `Ok`。拉起用 `Command::new(程序名).arg(路径)`，全程不拼 shell 字符串；路径里的空格、引号、`$`、`;` 都只是 argv 字节。因此也不提供「自定义打开命令」，那等于把 `sh -c` 请回来。

临时目录**不清理**是刻意的：系统会按自己的策略回收，而在我们这边删掉用户可能正在编辑器里打开的文件，比留一份副本更糟。

写回这一段**不做自动回传**。没有文件监视、没有「保存后自动上传」：外部程序的保存可能是多次、可能是「另存为」、可能写非原子临时文件，从进程外无法判定「这一次编辑结束了」。写回是一条显式动作——用户在文件面板里把改好的文件上传回远端，走的是同一套队列与取消语义。这条边界必须写在文档里，而不是让用户以为预览副本与远端是同步的。

预览期间只给一句一次性提示，**不做第二条进度条**。进度是 Transfer 面板与传输状态行的事；预览行再长一条进度，用户就得猜哪个是真的。

## 9. X/Y/ZMODEM 协议层

两条协议的共同前提：**纯逻辑、零 IO、零依赖、定时器归调用方**。输入是远端字节流与本地文件内容，输出是「该发给对端的字节」与「文件 / 进度事件」，中间不读文件、不开 socket、不 sleep、不起线程、不看时钟。

XMODEM 家族（`term-xfer`）覆盖 128 字节块、1K 块（尾块自动降到 128）、CRC-16 与 8 位校验和两种帧尾、`SUB` 填充、`CAN CAN` 中止、重试超次放弃；YMODEM 在它前面加文件头块、允许连续多文件、批结束发空头块。三条纪律中最容易写错的是**任意切分**：一条协议帧可能分三次到达，一次到达可能跨两帧半，两个状态机内部都维护未消费缓冲，帧长由帧头字节唯一决定，所以喂进去的切分方式不影响结果。

ZMODEM（`term-zmodem`）单独一个 crate。它不是「带窗口的 XMODEM」：滑动窗口、可变长帧、帧内十六进制转义、会话内子协议协商，错误恢复语义是「从偏移重传」而不是「重发当前块」。硬塞进同一个 crate 会让两边的 `feed` 都长出一堆协议分支。它只复用 `term-xfer` 的事件形状 `Action` / `Error` 与 `packet::crc16`，状态机独立实现，阶段按帧名命名（`AwaitingZrinit` / `AwaitingZfile` / `AwaitingZrpos` / `Receiving` / `AwaitingZack` / `AwaitingZfin` 等），因为 X/Y 那组线性时序的名字套到 ZMODEM 上会出现「阶段名在等另一种帧」的错位。

续传在协议里的表达：接收方的 `ZRPOS(N)` 表示「前 N 字节已有，从 N 续传」，发送方据此从偏移续发；早期的 `ZSKIP(N)` 约定仍被容忍，但不再作为本端发起的语义。这是 ZMODEM 与 X/Y 最本质的差别，也是它必须独立成 crate 的理由之一。

## 10. 驱动与编排

两个协议内核的公开面照着同一个形状做（`start` / `feed` / `on_timeout` / `cancel` / `phase` / 字节计数，事件类型共用），所以驱动层只需要一个 `Engine` 抽象加四个薄壳（X/Y 收发、ZMODEM 收发）。协议差异收在壳里，线程、落盘、进度、取消、旁路交还只有一份实现——换协议不该换驱动。

驱动跑在后台线程上，第一件事是把这条会话的输出 `attach_raw` 到本线程的 sink。原因：传输期间协议字节是纯二进制，绝不能进 VT——会把屏幕刷乱、把日志写满、把脚本的读取游标污染掉。收尾时**一定** `detach_raw`，靠 `Drop` 而不是靠「记得调」：正常结束、取消、出错、panic 四条路都盖住。漏一次，那条会话就永久收不到字节。

轮询粒度 200 ms。对端静默不自己重发——`on_timeout` 是钩子，什么时候催由驱动决定；X/Y 默认 10 次重试，ZMODEM 抬到 40 次，因为它的握手往返更长。取消除了置旗子，还要直接调状态机的 `cancel()`，让它产出中止序列（X/Y 是 `CAN CAN`，ZMODEM 是一串 `CAN`），否则对端会继续发。

落盘路径先过一道不可信输入处理：对端给的文件名可能是 `../../etc/passwd`、`/etc/passwd` 或带盘符的 Windows 路径。`resolve_name` 统一分隔符后拒绝绝对路径、盘符、NUL、空串与取不出名字的路径，只取 basename 再拼目标目录。XMODEM 线上不带文件名，这不是「对端给了坏名字」，本端起一个不会撞名的默认名。

收尾时写回 mtime，**权限位有意不落盘**：发送端恒发 `100644`，这个值是线格式惯例而不是可信的对端意图；接收端 chmod 还涉及 Unix/Windows 差异，以及「对端能不能让本端落一个可执行文件」的安全面。代码里显式消费那个字段，让「读到了但决定不用」可见，而不是悄悄丢掉。

ZMODEM 的多文件批处理与 `ZCRCG` 连发是 opt-in：打开后一次 `start` 可以把「目录或分号分隔的多路径」展开成同一台发送机上的多次 `add_file`，每个文件之间有独立的 `FileDone` 边界。续传能力内核自带，驱动层不重复实现——驱动每次新建落盘文件（`truncate`），没有「本地已有前 N 字节」的语义，也就没有可声明的起点。

## 11. 速率、剩余时间与基准

速率估计是纯函数层（`RateMeter`），界面只显示最后一次结果：

- 用毫秒而不是秒。几十 MB 的文件在千兆链路上几秒就完事，按秒算出来的速率是「0 或满值」，没有意义。
- 采样窗口下限 100 ms。更密的重复采样被**折叠进下一个窗口**而不是丢弃——丢字节等于让速率偏低，而偏低会被读成「速度慢」。
- 指数平滑新样本占 30%，历史占 70%，初值取第一次有效瞬时速率、不从 0 往上爬（否则刚开头几秒会显示一个很小的速度，看起来像卡住）。只估计单向速率：同时收发的会话各持一个 `RateMeter`，开始新文件、重试、续传重新计时都要 `reset`。
- 剩余时间只在对端给了总长时给，向上取整，极慢链路钳一天，传完给 0；没有速率时后缀为空而不是「估算中」。

基准脚本 `scripts/transfer-bench.sh` 的默认口径是 **8 MiB × 3 轮**，可加 `--size-mb` / `--rounds` 放大。被测实现是本仓的 `term_sftp::blocking::Client`（与脚本端口 `sftp_get` / `sftp_put`、界面传输共用传输层），不是系统 `sftp`——后者测的是 OpenSSH 客户端。对端是容器里的真 sshd 加 `sftp-server`，监听 `127.0.0.1:22022`，密钥在运行时生成、不入库。

三条测量纪律：

1. **必须 `--release`**。debug 下分块加密与拷贝没优化，测出来的是「编译器没做内联」而不是「传输层快不快」，实测会低一个数量级。
2. **校验与字节数都要对**。每轮用 FNV-1a 指纹与源文件比对，且收发字节数相等；只比大小会漏掉「传了同样长度但内容错了」。
3. **判回归看中位数，不看均值**。单轮的系统抖动可以让极差达到数倍，均值会被某一轮拖偏。改进前后的两份报告必须同机、同载荷，且差异超过极差才算真差异。比值大于 1 是可能的（页缓存命中差异），小于 1 是正常开销；跨机器或跨文件系统的比较没有意义。

## 12. 设计约束

- **传输依附于连接**：连接没了，队列与「传输中」的行一起消失；不允许在断开后继续显示进度。
- **取消的处置只有一个判据**：传输前目标是否存在，不许用「传了多少」「是否为零字节」代替；取消也不进入错误统计、不自动重试，重试只属于退避窗口内的行，终态失败的重试入口回到文件面板。
- **续传必须显式请求**，且前缀不得长于完整文件；目录同步一律不续传。
- **覆盖路径不改权限位**；新建路径的权限要能被 `setstat` 钉住，而不是赌服务端 umask。
- **协议层不碰 IO、不读时钟、不起线程**，重发时机是调用方的策略；**协议字节不进 VT**，原始旁路必须由 `Drop` 兜底交还。
- **对端文件名一律不可信**：绝对路径、盘符、`..`、NUL 一律拒绝，不拼接后再交给文件系统去解释。
- **不内建编辑器，也不自动回传**：预览副本与远端之间没有隐式同步，写回是显式上传；预览也不再造一条进度显示，进度只属于 Transfer 面板与传输状态行。
- **性能数字只在本机同载荷下有意义**；对外引用必须带环境、载荷与轮次，并说明看中位数。
