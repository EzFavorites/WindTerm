# 会话与连接

本文说明一条会话从配置、建立、认证到断开的实现方式，写给需要改动连接层或
排查连接问题的贡献者。用户操作见 [user-guide.md](../user-guide.md)，分层总览见
[architecture.md](../architecture.md)。

## 这一层负责什么、不负责什么

| 这一层负责 | 这一层不负责 |
|---|---|
| 会话配置、身份与生命周期 | 终端网格、选区、回滚（`term-core` 语义层） |
| 建立字节通道：PTY、SSH、Telnet、串口 | 标签页、分屏、菜单（`term-app` / `apps/desktop`） |
| 认证、主机密钥、跳板链、隧道 | 保险库的加密格式（见 [06](06-security-credentials.md)） |
| 把失败分成可行动的类别 | 重试与自动重连的产品策略 |

## 会话模型

### SessionConfig

`SessionConfig` 是纯数据，字段按用途分组：

| 组 | 代表字段 | 说明 |
|---|---|---|
| 身份 | `name`、`group`、`description` | `name` 同时是会话库主键与脚本寻址键 |
| 目标 | `protocol`、`host`、`port`、`username` | 串口协议把设备路径放在 `host` |
| 认证 | `auth`、`auth_chain`、`identity_file`、`agent_forward` | 只存方式，不存凭据 |
| 连接 | `builtin_ssh`、`proxy_type`、`proxy_jump`、`forwards` | 代理四档互斥；转发存用户写的那一行 |
| 终端 | `term`、`charset`、`system`、`cols`、`rows`、`scrollback` | 影响会话侧的终端行为 |
| 串口 | `baud_rate`、`data_bits`、`stop_bits`、`parity` | 只对 `Serial` 有意义 |

**这个类型里没有密码字段**。密码、私钥口令、代理口令都在保险库或连接时临时
收集；会话库只保存认证方式与凭据引用。`Debug` 实现按字段脱敏。

### 协议与通道

`Protocol` 有五档，默认端口分别是无、22、23、无、80。「能开」不等于「同一条
路径」：

| 协议 | 实际通道 |
|---|---|
| `Shell` | 本机 `$SHELL`，分配一个 PTY |
| `Ssh` | 新建会话默认走进程内 SSH；历史配置可继续走系统 `ssh` |
| `Telnet` | 进程内 TCP 直连，协商字节在语义层剥离 |
| `Serial` | 进程内按 termios 直接打开设备 |
| `Tcp` | 系统 `nc`，跑在 PTY 里 |

多数新增字段用 `#[serde(default)]`，读旧会话库时回落到「升级前的行为」，
而不是回落成「新特性的默认值」：`builtin_ssh` 缺省 `false`（老会话继续走系统
`ssh`），`proxy_type` 缺省空串表示「没设置过」，此时按 `proxy_jump` 是否非空
推断，一旦有显式档位（包括显式 `none`）就以显式值为准。`SessionConfig::new`
不读环境变量：本地 Shell 的登录名由宿主经 `new_local_shell(login)` 注入。

### 会话 ID 与寻址

会话由 `SessionId`（`u64`）标识，登记在 `SessionPool` 的映射表里。池维护一个
**唯一寻址名**：重名时按 `name`、`name-2`、`name-3` 排下去，不顶掉已有名字。
`resolve(name)` 只做精确匹配，不模糊、不忽略大小写——寻址打空必须报错。

界面标签只持有一个 `SessionId`，不持有通道句柄。句柄归控制面，窗口、脚本、
RPC 桥、自动化都只能经控制面触达会话；「某个客户端自己握着一条远端会话」
在类型层面不成立。

### 生命周期

```
open() ──▶ 选通道 ──▶ 监管线程 ──▶ Alive ──▶ Finished(退出文本) ──▶ close()
             │                          │
             └─ 配置错误 / 开通道失败 ──▶ 带类别的 OpenError，不建会话
```

- **创建**：`open()` 是唯一入口。PTY 会话直接起监管线程；内置 SSH 先经应用层
  注册的通道工厂建 `TermChannel`，再走同一条监管路径。工厂只允许注册一次。
- **运行**：`send`、`poll`、`snapshot`、`status`、`resize`。`poll` 把本帧事件
  并进会话并回答「有没有新事实」；`snapshot` 读已收下的那一帧，不产生跨线程
  往返。`state` 只有 `Alive` 与 `Finished(Option<String>)` 两档。
- **能力**：`facets` 让会话声明自己有哪些附加能力，调用方不得按协议硬编码
  假设；当前监管会话实现返回空表，表示没有可发现的附加 facet。
- **关闭**：`close` 从登记表移除并关闭会话；标签侧随之关闭挂在这条会话上的
  隧道与文件面板——终端断了，转发没有理由还留着。

## SSH 认证

内置客户端支持四种方式：

| 方式 | 凭据来源 | 说明 |
|---|---|---|
| 密码 | 对话框或保险库 | 空密码不去试，避免白送一次失败握手 |
| 公钥 | 本机文件 + 可选口令 | 只认配置的 `identity_file`；文件不在就报错，不偷偷换钥匙 |
| agent | `$SSH_AUTH_SOCK` | 遍历 agent 身份逐个尝试；非 Unix 平台明确报不支持 |
| keyboard-interactive | 对话框收集的答案 | 按服务端提问顺序回答，答案不够补空串 |

公钥认证的 RSA 哈希算法不写死：先问服务端支持哪一种，再选 `rsa-sha2-256`
或 `-512`。选错的症状是「钥匙明明对却认证失败」。

`auth_chain` 是有序回退链：首选 `auth` 在前，其余方法依次在后并去重。被拒
（`Auth`）或该方法本地用不了（`Key`）时继续下一种；通道、本地环境、配置错误
立即返回——换一种方式也不会好，继续试只会掩盖病因。交互式认证是一个循环：
发起 → 收到提问 → 按序回答 → 成功或失败，服务端可以问任意多轮。

## 主机密钥校验

校验是同步的纯判定：输入是策略、主机、端口、账本路径和服务端公钥，输出是
「可信 / 新记录 / 跳过」三档之一。策略三档：

| 账本里的情况 | `Strict` | `Tofu` | `Insecure` |
|---|---|---|---|
| 记着同一把钥匙 | 接受 | 接受 | 接受（不读账本） |
| 没有这台主机 | 拒绝 | 记下再接受 | 接受（不读账本） |
| 记着另一把钥匙 | 拒绝 | 拒绝 | 接受（不读账本） |

- **TOFU 只在第一次宽松**。记下之后按 `Strict` 对待；指纹变化一律阻断，并给出
  账本行号与这次的新指纹，公钥本体一并带出，供显式替换时写回。
- **只比较公钥本体，不比较注释**。把 `user@laptop` 这类注释算进去，会把同一把
  钥匙报成「钥匙变了」，那是把人往中间人恐慌里推的假警报。
- **拒绝时不写文件**。替换旧记录必须由用户显式确认，且只改命中的那一行；
  账本里不认识的行原样保留（注释、空行、`@cert-authority`、哈希行都不改写），
  因为这个文件用户和 OpenSSH 共用。
- **非默认端口写成 `[host]:port`**，否则同一主机的两个端口会互相覆盖。
- **图形界面首连先问再信**：第一次用 `Strict` 校验并弹出指纹，确认后才写入
  账本并用 `Tofu` 重连；库的默认策略是 `Tofu`，因为无窗口调用方没有对话框。

## 跳板链

`ProxyJump` 解析成有序跳列表：逗号分隔，每跳是 `[user@]host[:port]`，空串或
`none` 表示直连。跳上没写用户名就沿用目标会话的用户名；端口缺省 22；IPv6
必须写成 `[::1]:22`，裸地址在冒号上无法消歧，直接报错而不是猜。

```
TCP ──▶ 第 1 跳（完整 SSH） ──direct-tcpip──▶ 第 2 跳（完整 SSH） ──▶ 目标
```

- 每跳都是一次完整的握手与认证，只有第一段是 TCP；之后每段都是上一条连接里的
  一条 `direct-tcpip` 通道。通道是双向字节流，同一份握手代码可以原样跑在上面。
- 中间连接的句柄不能掉：每跳的 `Handle` 挂在最终会话的 handler 上，生命周期
  正好等于「最终会话还活着」。
- 每跳用自己的主机、端口、用户名记 `known_hosts`，账本路径不变；否则记账会
  记到目标机头上，用户名也会串味。agent 转发只作用于最终目标。

出网代理与跳板是两件事，四档互斥：`None`、`Jump`、`Http`、`Socks5`。HTTP 与
SOCKS5 只作用于整条链的第一段 TCP，之后每跳已经在 SSH 连接里开通道，不需要
再穿过一次代理；有出网代理时目标主机名不在本地解析，交给代理。未知档位一律
回落 `None`，手改配置不能凭空造出一条代理。

## 隧道

| 规则 | 谁在监听 | 连接往哪去 |
|---|---|---|
| `Local`（`-L`） | 本机 | 服务器再去连目标 |
| `Remote`（`-R`） | 服务器 | 回到本机连目标 |
| `Socks5`（`-D`） | 本机 | 由客户端临时指定（只支持 `CONNECT`） |

解析与校验都是纯函数，在碰网络之前完成：绑定地址必须写成 `host:port`；本地
监听端口不能是 0（系统随便挑一个，用户不知道连哪）；远程监听端口可以是 0
（让服务器挑，再把真实端口告诉我们）；目标端口不能是 0；绑定地址与目标主机
都不能为空。

`start()` 阻塞到**所有**监听都建好或明确失败为止。一条规则建不起来就整条隧道
失败——半个隧道比没有隧道更难查。实际端口按规则顺序返回，`-R ...:0` 的真实
端口由服务端分配后回填。服务端推来的转发连接按 `connected_port` 匹配规则；
只有一条规则且服务端把端口报成 0 时才兜底，否则宁可拒绝，也不把流量送到错的
目标。

隧道复用 `term-ssh` 的握手、认证与主机密钥校验，只负责开通道和搬字节。关闭
会话时隧道一并关闭。

## 失败与降级

SSH 失败分成七类，因为用户能做的事完全不同：

| 类别 | 用户要做什么 | 例子 |
|---|---|---|
| `Config` / `Resolve` | 改表单 | 没填主机名、端口非法、解析失败 |
| `Connect` | 查网络、改端口 | 连不上、超时、被防火墙丢包 |
| `HostKey` | 判断是不是中间人 | 未知主机、钥匙变了 |
| `Key` | 换私钥或补口令 | 私钥有口令、格式不认识 |
| `Auth` | 换账号或换方式 | 密码错、服务器不认这把钥匙 |
| `Channel` / `Local` | 重连或修本机环境 | 通道开不出来、线程起不来 |

隧道另有五类：规则不成立、SSH 失败透传、本地端口占不上、服务端不同意转发、
后台线程意外结束。

- SSH 握手受会话的连接超时约束（出厂 20 秒）；隧道另设 15 秒的启动上限。
  心跳间隔由会话配置决定，0 表示关闭；库的默认是 30 秒，只负责发现「已经
  断了」，不会因为空闲主动断开——交互式终端会开着窗口离开很久。
- 连接在后台线程里跑，界面每帧取一次结果；结果就绪时回调唤醒界面，避免
  「Connecting…」停在屏幕上。
- 用户取消只放弃这次连接的结果，不中断已经发出的握手，也**不建标签页**。
  连接失败同样不建空标签。
- 不静默降级：串口打不开就报错，不退回去拉 `cu`；Telnet 连不上就报错，不退
  回去拉系统客户端；内置 SSH 建不出通道就报错，不退回去拉系统 `ssh`；选了
  GSSAPI 但内置客户端不支持时明确说明并给出「改用系统 ssh」的出口；非 Unix
  平台的 agent 认证明确报不支持，不假装成功。

## 设计约束

- `tokio` 只允许出现在 `term-ssh`、`term-tunnel`、`term-sftp` 三个 crate；
  桌面 UI 源码零 `.await`。连接层对外一律同步接口，异步只活在内部线程里。
- 控制面 `term-session` 不出现 SSH / SFTP / 隧道等协议概念；会话配置与错误类型
  都不拍平成字符串，跨 crate 边界必须能按类别反应。
- 外部客户端（系统 `ssh` / `nc` / `cu`）只保留给 CLI 与无窗口兼容路径，不是图形界面的隐式回退。
- 本文只描述实现结构；凭据格式、锁屏与 `term-desk serve` 的准入见 [06-security-credentials.md](06-security-credentials.md)。
