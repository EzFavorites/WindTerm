# 功能范围与需求基线

本文回答「做什么、不做什么、按什么顺序做」，是其余设计文档的范围依据。具体实现设计见同目录的其他篇目。

## 1. 分级定义

| 级别 | 定义 | 判定口径 |
|---|---|---|
| P0 | 没有它就不是一个可用终端 | 只算内置、用户可见的工作流；「可以敲命令实现」不算 |
| P1 | 达到可日常迁移的门槛 | 缺了它，重度用户没有理由换过来 |
| P2 | 差异化能力 | 同类工具普遍缺失或做得不完整 |
| P3 | 长期或按需 | 不影响主线，按需求再议 |

## 2. P0 · 首发必备

| 模块 | 能力 | 验收要点 |
|---|---|---|
| 本地终端 | 本地 Shell（zsh / bash / pwsh） | 启停、resize、退出码、Ctrl-C / Ctrl-D 正确 |
| SSH | 密码 / 公钥 / keyboard-interactive 认证 | 三种全通；主机密钥提示明确 |
| SSH | agent 转发、单跳 ProxyJump | 跳板链路可用 |
| 会话 | 会话树（文件夹 + 会话） | 重命名、排序、复制、搜索 |
| 会话 | 布局恢复 | 恢复标签与分屏**结构**，不恢复进程内状态 |
| 凭据 | 保险库 | 主密码可改；条目零明文落盘 |
| 导入 | `~/.ssh/config` 与常见会话导出 | 首次启动即可用；密码不迁移 |
| 终端 | 真彩色、Unicode 双宽、emoji | 中文与图标不错位 |
| 终端 | 选区复制、右键粘贴、中键粘贴 | 双宽字符选区边界正确 |
| 终端 | 缓冲区内查找 | 高亮全部命中，可前后跳转 |
| 界面 | 标签 + 分屏 | 分屏内可再分屏，关闭行为可预期 |
| 界面 | 命令面板 | 所有动作可检索、可绑定快捷键 |
| 界面 | IME 中文输入 | 候选框跟随光标 |

## 3. P1 · 迁移门槛

| 模块 | 能力 | 价值 |
|---|---|---|
| tmux | 控制模式（`-CC`）集成 | 双向同步窗口/窗格，安全降级 |
| 文件 | SFTP 面板（同源会话） | 终端与文件共用一条连接，免二次认证 |
| 文件 | 传输队列、进度、取消语义 | 取消三态见 `05-files-and-transfer.md` |
| 文件 | 断点续传 | 大文件场景 |
| 文件 | 拖拽上传（取真实路径） | 原生路径，不经过浏览器层 |
| 终端 | 大回看（热区 + 冷区日志） | 长输出会话 |
| 终端 | 多会话同步输入 | 批量巡检 |
| 网络 | 端口转发（本地 / 远程 / 动态） | 运维日常 |
| 网络 | HTTP / SOCKS5 代理 | 内网穿透 |
| 会话 | 会话日志（手动 + 自动） | 审计与复盘 |
| 终端 | 键位模式（本地 / 远程双模式） | 重度用户肌肉记忆 |

## 4. P2 · 差异化

| 模块 | 能力 | 差异化点 |
|---|---|---|
| 插件 | 沙箱插件系统 + 能力清单 + 签名 | 能力可扩展而不牺牲边界 |
| 协议 | ZMODEM / XMODEM / YMODEM | 串口与跳板场景必需 |
| 协议 | Serial / Telnet / Raw TCP | 老设备与网络设备 |
| 终端 | 命令块折叠 / 大纲 | 重型输出可读性 |
| 终端 | 时间戳 + 行号侧栏 | 排障场景 |
| 终端 | 跨标签搜索 | 多会话定位 |
| 脚本 | 命令片段 + 命令发送器 | 批量操作 |
| CLI | 无头子命令（doctor / capability / serve / script） | 自动化与排障 |
| 导入 | 更多会话导出格式 | 降低迁移成本 |

## 5. P3 · 长期

SSH GSSAPI、X11 转发、SCP、远程桌面（RDP / VNC）、运维面板（容器 / 进程 / 磁盘）、云同步、团队共享、AI 命令解释。

涉及终端输出的智能能力一律放在 P3，并且必须可选、默认关闭、明确告知、不静默外发——终端输出可能包含密钥与生产数据，这是产品底线而不是功能取舍。

## 6. 明确不做

| 不做 | 理由 |
|---|---|
| 云同步 / 账号体系 | 引入服务端即引入运营与数据责任；本地优先是设计前提 |
| 团队协作 / 共享会话 | 同上，且与「单人可维护」冲突 |
| 内置容器 / 进程 / 磁盘运维面板（远程多平台） | 与终端核心重叠度低，投入产出比差 |
| 远程桌面（RDP / VNC） | 独立编解码工程，用户重叠度低 |
| 通用文本编辑器 | 远端文件走「下载—外部打开」链路，不内建编辑器 |
| Tektronix 4014 等极冷门终端类型 | 维护成本高于收益 |
| 复用第三方的图标 / 主题 / 截图资产 | 只做行为与结构层面的兼容，不复用表达 |
| WindEdit 超大文件（10GB / 400MB 单行 / 5000 万行） | 通用编辑器不在范围内，文件大小承诺没有对应实现 |
| 计算器 / 拖放文本 / 地址栏文字双击选择 | P3，长期按需，当前无实现 |

参考产品宣称有、本产品明确不提供以上能力；审计清单里应单列此块，避免与缺陷混排。

X11 转发的边界：本产品实现 `x11-req` 并桥接到本机已有 `$DISPLAY`，但不附带
「内置 XMing X server」，也不把它计入已交付的运维/桌面能力；范围文档把它列在
P3 与实现现状一致，差异只应在文档中说明，不应按缺陷处理。

`Window.GotoSymbol` 保留为置灰第三态（菜单可见、`Action::parse=None`）：设计上
刻意不做该能力，官方功能文档与置灰清单的口径差异在此固定。

## 7. 需要固定语义的细节

以下三处必须在实现前写死语义，否则会在实现期反复改：

- **传输取消三态**：用户主动取消删未完成文件；网络中断保留分片可续传；目标文件原本已存在则不删。详见 `05-files-and-transfer.md`。
- **布局恢复边界**：恢复的是结构（窗口 / 标签 / 分屏 / 会话引用），不是进程内状态（回滚内容、运行中的进程）。恢复出的标签是断开态，激活时才建立连接。详见 `04-tabs-split-layout.md`。
- **密码不迁移**：导入只带主机 / 端口 / 用户 / 分组 / 密钥路径，密码首次连接重输。各家加密方案不公开，解密既不可靠也不合规。详见 `09-session-import-and-onboarding.md`。

## 8. 需求条目格式

需求按「触发条件 → 系统响应」写，便于验收：

```
当 <触发> 时，系统应 <可观测响应>。
若 <异常条件>，系统应 <降级行为>，而不是 <错误行为>。
```

示例：

```
当用户在一次传输中点「取消」且目标文件在传输前不存在时，
系统应删除未完成的分片，并在队列中标记为「已取消」而不是「失败」。

当连接建立时主机密钥与已知记录不一致时，
系统应阻断连接并同时显示新旧指纹，而不是把它当作未知主机重新信任。
```

## 9. 兼容与导入范围

- **输入**：OpenSSH `config`（`Host` 块、`ProxyJump` 链）、常见终端的会话导出文件（宽松解析，未知行忽略）。
- **输出**：只写本项目的会话库与配置，不写回第三方格式。
- **不迁移**：密码、私钥内容、终端回滚内容。
- **命名与去重**：导入按会话名归并，重名在同一次导入内做区分，不覆盖既有会话。

## 11. 首发人群

面向对性能敏感、多机运维、有 tmux 刚需的重度用户。不做「新手友好」首发：那需要大量引导设计与监控面板投入，与当前差异化方向不一致。

## 11.1 Sysmon 细带与「运维面板」的边界

终端区下沿那条 `T/C/M` 细带（`apps/desktop/src/ui/shell/sysmon_bar.rs` +
`apps/desktop/src/sysmon_sample.rs`）**不是**第 6 节「明确不做」的运维面板：
它只读**本机**时间 / CPU / 内存读数，没有远端采集、容器 / 进程管理或任何写操作；
存在理由是与参考 UI 的 25pt 下沿视觉基线对齐，属于只读装饰。二者能力面不同，
不可用后者为前者交差，也不因前者被误判为范围越界。

## 12. 设计约束

- 范围条目只增不悄悄减：砍功能必须同时改本文与对应设计文档。
- 「不做」清单是守门条款：新增需求与它冲突时，先改这里再谈实现。
- 每个 P0 / P1 能力必须在对应设计文档里有可验收的语义，不接受「先做出来再说」。
